# 远程调试：logicmatrixsemi.com:5174 · FPGA LAB

> **优先用脚本化桥接**：`D:\0000\111\001\Pango\tool\fpga_lab\` 的桥接服务器已把下面的核心流程
> （预约/烧写/串口）封装成 REST+CLI（见 `bridge_server.md`），已实机验证。本文件保留为**人工兜底**
> 与 ILA/摄像头等未自动化能力的操作说明。

远端是紫光同创的网页远程实验平台 **FPGA LAB**（SPA 应用）。**下载位流、网页串口、
ILA 波形捕获都是浏览器内的手动操作，没有脚本化 API**，本机无法直接用 curl/脚本驱动。
下面是从本地 `generate_bitstream/<top>.sbit` 走到实板验证的完整路径。

> 平台地址：`http://www.logicmatrixsemi.com:5174/developer/dashboard?module=devices`
> 账号密码：`D:\0000\111\001\Pango\tool\account.txt`
> **不要把账号密码写进任何脚本、SKILL 或提交。** 需要登录时由用户手动在浏览器完成。

## 1. 登录与预约实验箱

1. 浏览器打开上面的 dashboard 地址（建议 Chrome；需要 JavaScript）。
2. 用 `account.txt` 的邮箱 + 密码登录开发者账号。
3. 进入 `devices`（设备/实验箱）模块，确认目标箱显示器件为 **PG2L200H**。
4. 预约（占用）一个空闲实验箱；记录箱号（例如“实验箱5”）。**结束调试后必须释放设备**，
   否则会一直占用、且远端板卡持续上电。

## 2. 下载位流

1. 在实验箱面板选择“下载/烧录”，上传本地生成的 `<top>.sbit`。
2. 平台提示“固件下载完成且设备已唤醒”即表示位流已落到远端 PG2L200H。
3. 若设计带 UART，先在约束里确认用的是 **RemoteLab 引脚 AC26/AB26**（见
   `pin_constraints.md`），不是板载 B24/C24。
4. 摄像头观察类设计（如 LED 流水）可直接看实时画面验证。

## 3. 网页串口（UART）调试

1. 打开实验箱的“串口/终端”面板。网站会明确标出 RX/TX 引脚与波特率。
2. 设 **115200 8N1**（部分低速固件 9600），电平 LVCMOS33。
3. 发指令/收回包与本地 RTL 逻辑配合。例如自检固件常回 `ZSOC PASS` 之类握手串；
   用 UART RX 外部中断触发继续的设计，向串口发 `A5` 等字节即可推进，无需现场按键。
4. 出现“假死”先确认：是否缺少输入事件（没发字节 / 没按键）、串口参数是否匹配、
   引脚是否 RemoteLab 而非板载。

## 4. ILA / 逻辑分析仪（Fabric Core Inserter）

用于抓取片上信号波形：

1. 本地 PDS 里用 Inserter（`cdt_ins.exe` / Fabric Core Inserter）向网表插入 DebugCore，
   生成 `.fic` 调试工程文件。**FIC 首行必须是 `#Fabric Core Inserter Project File`**，
   删掉会被 Inserter 报 `Inserter-0003`。
2. 烧录**插入 ILA 的同一版位流**到实验箱，并上传严格匹配的 `.fic`。
3. 网页点“启动/捕获（触发）”，再“导出”原始 CSV。
4. 离线用脚本（参考工程 `cpu/scripts/ila_analyze.py`）把 CSV 渲染成波形 SVG 再分析。

> 注意：位流与 `.fic` 必须同源同次实现；换一版位流就要重新导出匹配的 FIC，
> 否则触发/采样连接会对不上。

## 5. 收尾

- 关闭串口、停止捕获。
- **释放实验箱设备**（面板“释放/结束”），确认设备状态回到空闲。
- 本地保留位流 SHA-256、串口日志、CSV 等证据，便于复现与对照。

## 本机无法自动化的部分（如实反馈）

- 登录、预约、上传、串口收发、ILA 捕获均依赖人工在网页操作。
- 若后续平台暴露 REST API，可在本文件补充脚本化步骤；当前以手动流程为准。
