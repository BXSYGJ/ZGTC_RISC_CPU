# 保留ALU高段预计算：同步I-cache版的时序收敛

日期：2026-09-07。当前非插核候选为Cache 680F03DF、ALU 47E2A544；其132/135 MHz性能与验证两组位流均已本地合格，尚未实板复测。此结论不是正式CoreMark成绩，也不是全项目验收。

## 先核实实际电路

D681同步读I-cache将数据移入块RAM后，仍有三组时序失败。仅把Cache request_address的syn_maxfan从64收紧到32，得到680F03DF：132 MHz/种子7为7981 LUT、4992 FF、WNS -0.166 ns；135 MHz/种子1为7969 LUT、5008 FF、WNS -0.001 ns。两者严格拒绝，未把负裕量四舍五入为零。与各自同频同种子D681相比只改变Cache，固件及规范化顶层完全相同。

原生网表检查发现，ALU B6版本虽在RTL中写出高段进位为0/1的预计算，ADS实际仍把低段sum_low[16]或difference_low[16]接入连续17个高段进位单元。旧实板构建051442-9813d121和同步Cache构建091551-a2e4d560均可复现，因此不能只凭RTL写法认定已经得到并行电路。

当前ALU对四个16位高段中间网分别添加syn_keep=1，声明与赋值分开。低16位运算、高段选择和其余操作不变，没有添加寄存器或流水停顿。依据为本地PDS ADS_Synthesis_User_Guide.pdf第5.11节；该属性保留网，并非自动时序保证。分开声明避免Icarus对声明赋值上属性丢弃的警告，不放宽lint。

新132/135 MHz原生网表都保留四个高段名字，低段进位/借位不再直接作为任何GTP_LUT6CARRY的输入；旧扇出32版本解析到136个进位单元，新135为145个、新132为144个。检查明确验证模块、单元数和九个管脚，避免空匹配误报。这是局部连接证据，不是全网表形式等价证明。
