# MMIO 影子请求候选

## 范围与结论

候选位于 experiments/mmio_shadow_accept/rv32_memory_system.sv，SHA256 为 16F7124CD1FDE2D1825827D0A0CB186A7925002B0A135AB83253355AD70119D7。隔离工程为 build/mmio-shadow-accept-stage。相对 cache-error-retime-stage 的20份物理输入，仅 memory_system 改变；核心、缓存、PLL、固定固件与实现参数保持一致。父方案自身没有通过时序，不能继承物理资格。

本候选功能回归通过，但实际146.25 MHz实现失败：8876 LUT、5177 FF、WNS -0.292 ns、133个setup失败端点。因此不替换合格基线、不执行完整计分、不产生新CoreMark分数，也没有上传GitHub或上板。

## 机制与安全边界

仅在 ENABLE_CACHE、DATA_OVERLAP 均开启且 MEMORY_ADDRESS_BITS 不超过26时启用 SHADOW_MMIO。D-cache入口不再通过当前请求的MMIO地址分类来屏蔽valid；MMIO地址也可以作为影子请求被缓存接受。地址始终保留全部32位，不能将高四位清零，否则会把外设地址别名映射到RAM。

在这一地址宽度限制下，所有高四位非零的MMIO地址对缓存都是越界地址。父缓存的寄存错误检查使其在接受后的第一周期返回错误、数据为零，不更新缓存元数据或发出后端内存操作。路由器仍只向CPU交付真实外设响应，并在保留的 data_mmio 为真时静默接收影子错误响应，即使 data_active 已清除。未启用缓存、关闭交接或超出地址宽度限制时，回退为原来的入口/响应逻辑。

CPU d_req_ready、外设请求缓冲、pending状态及真实响应所有权保持原样。零延迟外设响应可能完成于旧请求缓冲仍pending的周期，缓存此时能接受尚未由CPU路由器接受的后继MMIO影子请求；这种无CPU归属的影子也必须排空。定向实例观察到120次CPU MMIO请求、167次影子接受、47次无归属影子、167次排空。测试和审计要求 shadow = mmio + orphan，而不是假设二者始终一对一。它们不会重复真实外设副作用。

上述适用范围和协议模型不是对任意外设时序的形式化证明；宽地址回退条件由源码精确比较约束，不能据此声称已模拟超大RAM。

## 功能与执行效率验证

- scripts/test_mmio_shadow_accept.py 的4项方法最终18.769秒通过。60组原/新协议配对，每组每侧240个CPU请求：每侧合计14400个CPU请求、7200个MMIO请求、3600次成功外设写。覆盖两种存储/缓存几何、缓存与交接开关、外设响应延迟0/1/3、请求等待0/3及快读写配置。
- 协议逐周期比较CPU与维护握手、响应有效数据、外设全32位负载、缓存统计以及后端命令和写入；独立队列核对响应归属、外设恰好一次与顺序，最终维护后比较完整RAM及外设副作用。包含非法RAM地址、未对齐、外设错误、全部15种MMIO高四位、字节使能、背压及并行取指。
- 24组原有交接配对共48次运行通过，保留请求交接、等待期间MMIO负载、pending外设请求复位丢弃、维护写回和恰好一次断言。5个实际运行错误变体均被具体断言拒绝，不把编译错误或超时算作有效拒绝。
- 8种严格板级lint通过。两次缓存CPU运行仍为6469/6360周期，851/963条退休，完整轨迹及最终内存与父方案相同。
- 双10轮短测 20260908-112120-933e8fc7 与 20260908-112133-fd251ddd 分别3151519/3156276周期、2748941/2749614条退休；CRC、缓存事件、参数与固件均保持一致。短测不是完整CoreMark成绩。
- 常规ISA RV32UI构建 20260908-112639-c95d346f、RV32UM构建 20260908-112902-99418127：196次成功运行、8个实际拒绝控制。额外I9/D6目标配置98组原/新配对、196次运行、8个拒绝控制；完整周期、退休、轨迹与内存相同，独立审计通过，不称ISA认证。目标审计7类篡改拒绝测试2项方法34.129秒通过。

## 物理结果

实际PDS构建 20260908-112432-d91d12e3，PG2L200H-6FBB676、146.25 MHz、6.837 ns约束、种子1、RemoteLab UART 115200、同一6000轮性能固件。构建生成位流，但时序门禁拒绝通过manifest；不能把“生成位流”理解为“时序通过”。20份源、完整Tcl、种子、固件、原生PLL和缓存结构、报告与摘要绑定审计通过；强制时序资格模式实际拒绝该结果。

资源8876 LUT、5177 FF，WNS -0.292 ns、TNS -13.844 ns、133个setup失败端点。相对父方案8989 LUT、5170 FF、WNS -0.194 ns，少113 LUT、多7 FF、裕量下降0.098 ns；执行效率短测未变，不能因资源减少就认定综合优化成功。

最差路径从 core/mem_instruction[7] 经 early_operand_b[10]、SLT进位链与控制逻辑到I-cache stored_state_reg[1]的CE，11级逻辑，时钟偏斜-0.108 ns；不能继续把旧父方案的D-cache地址高位路径写作本次最差路径。源快照与位流哈希由 build/mmio-shadow-accept-physical-qualification.json 保存。物理审计4类拒绝控制2项方法23.276秒通过。

## 保留的工具失败与修正

初版 SHADOW_MMIO 使用 integer 声明，严格lint因布尔表达式位宽不匹配而失败；改成单bit localparam并重新完成单元与严格lint，最终源码哈希以本页为准。原单元/失败lint日志保留，最终合格日志为 mmio-shadow-accept-unit-qualified.log 和 mmio-shadow-accept-lint-qualified.log。

缓存聚合日志曾带入旧失败lint开头，首次筛选审计据此拒绝；未改写原始聚合日志，改为独立验证并绑定最终8项lint日志，再独立验证缓存输出。SoC回放脚本仍引用初版源码哈希，首次运行在来源门禁拒绝；修正到最终哈希并使用 soc-paired-replay-qualified 新目录，旧失败目录不覆盖。

加强影子接受守恒审计后，原缺失orphan变体先触发新守恒门禁，导致测试预期消息不符；改为分别测试“保持守恒但缺失零延迟覆盖”和“独立破坏守恒”，不削弱审计条件，不修改实际仿真日志。最终筛选拒绝控制覆盖12类。

## 后续边界

本次没有新的完整分数或远程板卡证据；生产RTL与已上传120 MHz版本不替换。最新源码上板、应用/稳定性、ILA及电气约束仍需独立闭环。以后只在用户明确要求时上传GitHub，不进行例行同步。继续优化需在执行效率、时钟频率与资源效率之间用实际测量比较，不能把有限失败实验称为达到物理极限。
