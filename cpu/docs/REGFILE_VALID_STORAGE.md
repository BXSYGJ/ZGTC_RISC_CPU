# 寄存器堆有效位复位与无复位数据存储

## 新目标和真实瓶颈

本实验从已冻结501.065730222分版本出发，目标是提高资源效率与时序裕量，而不是改变预测算法或增加执行周期。保持732509AD父CPU除寄存器堆外的逻辑、BBB08D9A预测器、缓存、157.5 MHz时钟和固件不变；不叠加已失败的连续历史/循环表候选。

冻结PDS 20260909-041604-e83d4473的最慢路径从id_instruction[22]经寄存器堆读选择到raw_pair_relation，WNS仅+0.026 ns。该次真实综合网表中有992个Q连接到registers数据的GTP_DFF_CE，即x1至x31的31×32位；并非仅依据Verilog数组名称猜测存储映射。

## 最小结构改动

规范CPU experiments/regfile_valid_storage/rv32_core.sv，SHA256 ABD2D7A8C5B7C81239F14A90E5BB802308F53E74387097D88A8A20F3531EB59D。保留32×32数据数组，但数据仅在trace_write时同步写，不对数据阵列整体复位；新增32位register_valid，异步复位清零，写入相同WB地址时置位。ID两读端口在有效位为0时返回零，原WB同拍前递优先级不变；x0从不满足实际trace_write，始终保持不可写的零读语义。

只有有效位复位，不新增流水级、不做串行清零、不延后首次读。实际原生网表已证明数据进入RAM；普通PDS面积降低但时序失败，不能晋升基线。

## 首次严格lint失败与修订

EAEC8247原型把数据写条件写成rst_n && trace_write，源片段对照3项0.435秒、25113周期/75421检查/41复位与7个运行错误变体通过，但严格Verilator拒绝SYNCASYNCNET：同一复位信号同时用于同步数据写门控和异步状态复位。原型、独立工程和失败日志保留，没有关闭警告、没有进行短测或PDS。

ABD2D7A8修订去掉数据过程中的rst_n依赖。实际trace_write由异步清零的wb_valid门控；即使探针故意在复位期间强制写入，数据也必须被清零的有效位屏蔽，并在首次合法写入时覆盖。针对这一边界新增31个地址的复位期间写入/释放/重写场景，不以“内部通常不会发生”跳过验证。
