# 加载前递的数据与执行资格解耦

## 当前范围

本轮针对达标源快照的真实时序路径：D-cache valid选择经过响应资格、前递、地址计算到MMIO寄存器使能。此前同拍乘法试验的最差路径也经过前递与ALU。先不修改ALU或Cache算法，只从前递数据多路选择中去掉重复的mem_fire和d_rsp_error资格；执行、内存请求、异常和退休门槛保持原逻辑。

不是“响应未到也允许执行”。当上一条load没有返回时，mem_ready为0，ex_can_fire/ex_fire为0；错误响应到达时mem_flush为1，年轻指令同样不能执行或发起提前请求。LOAD_USE_BUBBLE=1的旧行为保持，不使用这种load前递。待用的数据总线可以在无效周期变化，但不能把这些值提交成架构状态。EX保持寄存器即使暂存无效数据，随后必须由有效响应或WB前递覆盖；整条流水线的独立参考比对检查最终寄存器和内存效果。

修改不增加流水级、配置位、指令或CoreMark源码；区分版本依赖准确源码快照，不能只看相同配置字0e8e86f9。新源码哈希不能绕过旧Target120 ILA输入锁；旧波形不自动成为新版本证据。

## 定向验证

core_tb新增默认关闭POISON_INVALID_DATA开关，启用后延长所有读响应等待24拍，并在响应无效时持续改变数据和error输入。检查未收到响应时不能执行年轻指令或发出其请求、错误响应时必须抑制年轻指令、依赖操作数的数据选择不再等待响应资格；同时仍由独立参考模型逐退休/陷阱记录比对，并比较16KiB内存。

test_forward_data_controls.py覆盖预测开关与load bubble开关的四种组合，并注入三个反例：恢复原数据资格、允许提前执行、允许在加载错误时执行。初版错误反例删掉所有mem_flush条件，只触发稍后的固件签名失败，不能证明指定加载错误覆盖；修订后只放开load错误，延长等待并强制统计待执行年轻指令下的错误响应，获得明确拒绝。没有把初版不充分反例计为定向验收完成。

## 135 MHz探索：拒绝上板

同源码的6000轮性能候选build/pds/20260907-002616-d6a0314b完成实现，但135 MHz WNS=-0.454 ns，10223 LUT、4812 FF、4 APM，约束不通过。PDS估计127.2103 MHz仅是此布局报告值，不是已验证可运行频率。该位流未上板，不给出135 MHz正式CoreMark/资源效率成绩，也不因为存在.sbit就采用它。

下一步仍需缩短Cache响应到前递/地址/MMIO使能的长路径，或验证更细的合法PLL频点；新ILA映射、独立GPIO输入正例、电气约束/SCBV和长期稳定性仍缺，不能宣布全项目或三项物理极限已完成。
