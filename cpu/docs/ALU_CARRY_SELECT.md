# 分段进位选择ALU实验

## 输入与动机

上一阶段折叠BTB与除零载荷候选的132 MHz默认布局仅差0.008 ns，但种子1/7分别为-0.095/-0.111 ns，均拒绝上板。默认最差路径从D-cache地址副本经标签/数据选择、load格式化与前递进入ALU进位逻辑，终到mem_result[22]。路径报告体现的是组合逻辑与布线共同作用，不能只用RTL加法器位宽预言时序结果。

保持BTB旋转4/F467693E、M载荷1079EF43、Cache AC24EDFB及其他生产输入不变，仅改rv32_alu.sv。旧ALU SHA-256 B2BEE3DB4819FD6EFD2975EFA56422A9844D36436D25DB51B52EA4BF5B960815；候选B6A0954A08A708B090FA3CFA770535346EACDC99DE005BA6D830EADDDED24C72。

## 电路变化

加法低16位先计算17位和；高16位分别预计算无进位/有进位两种结果，按低段进位选择。减法同理：17位低段差的bit16表示借位，高段分别计算A-B与A-B-1再选择。整体结果仍按模2^32截断，最高溢出不作为额外架构状态。

只替换ALU操作0/1；移位、比较、异或、或、与和默认结果均保持。没有新增寄存器、流水级、握手或ISA指令，也不统一加减法的输入控制以额外引入晚到选择信号。RTL意图是以并行计算换取较短进位依赖；原生综合是否保留该结构、实际LUT代价和时序仍须以新报告判定。

## 定向与短测

新增alu_carry_select_tb覆盖16种边界值的两两加减、每一位的进位/借位传播与32位溢出，共640检查。既有decode_alu_tb的13124项检查继续通过，其中10000项随机ALU结果涵盖全部10类操作。test_alu_carry_select.py的丢进位、丢借位、错误借位位号、错误借位符号四个反例均被实际运行拒绝；严格Verilator --Wall通过。日志build/test-alu-carry-select.log。

10轮性能/验证两组均CRC通过、周期与上一阶段相同：3307565/3308242，退休2748941/2749614。目录build/compiled/20260907-051417-065cf6aa、20260907-051424-c7ebb14f。这次改动不降低执行拍数，也不是实板新成绩。

## 实现与实板终态

132 MHz构建build/pds/20260907-051442-9813d121正式时序通过：10353 LUT、5023 FF、4 APM、WNS +0.103 ns。匹配验证种子构建20260907-052636-ad526862同源、同资源和裕量。135 MHz构建20260907-051508-e2775865为10379 LUT、5050 FF、WNS -0.103 ns，失败且未上板。完整validate-alu-carry-select.log以PASS结束，外部RV32UI 164次和RV32UM 32次运行及共8个拒绝控制通过，源哈希已绑定；不等于完整ISA认证。

实验箱2完成两次性能6000轮及一次验证6000轮，CRC均通过、每次计分超过15秒，两份性能UART逐字节一致。实际3.02972052980729 CoreMark/MHz、399.9231099345622 CoreMark、0.038628717273694796 CoreMark/LUT，严格门槛通过。与上一已测132 MHz相比，执行效率+0.5559642%，资源效率-0.0170873%，LUT增加59；旧版保留作折衷，不能称全面改善。详见HARDWARE_132MHZ_CARRY_SELECT.md及build/hardware/alu-carry-select-f132-provenance.json。
