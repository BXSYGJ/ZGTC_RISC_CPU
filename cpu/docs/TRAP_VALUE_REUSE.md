## 结构与行为边界

上一轮64项BTB写命中快路径的120 MHz最差路径经过DCache响应、加载前递、有效地址加法及异常值选择，落在mem_tval寄存器。此次不放宽时序约束、不降低主频、不删除异常，而是删除EX→MEM重复保存的32位异常值寄存器及EX端宽选择器，在MEM级使用已保存的元数据重建异常值。

- cause=0：若当前指令PC未对齐，返回mem_pc；否则返回跳转目标mem_target。优先级不能反过来。
- cause=1/3：取指访问异常、断点返回mem_pc。
- cause=2：非法指令或非法CSR访问返回mem_instruction。
- cause=4/6：加载、存储未对齐返回mem_address。
- 中断和ECALL返回0；解码使用完整32位cause，不能丢弃中断最高位。
- MEM级总线访问异常仍由原接口返回mem_address；异常PC、指令、数据地址均不能借用当前EX级值。

异常发生条件、优先级、请求发出条件、流水线握手及CSR提交时刻不变。mem_tval保留为组合信号名，不能把它继续解释为独立32位寄存器。是否真正减少FF/LUT、是否改善120 MHz时序，以布局布线报告为准。

## 定向验证

sim/trap_value_tb.sv直接注入EX级已解码事务并使用实际EX→MEM寄存和machine CSR提交；它不是取指端到端测试，端到端行为另由CPU/SoC差分和外部ISA回归覆盖。遍历32个位模式，检查PC/跳转目标优先级、取指错误优先于非法指令、非法指令原字、断点、JAL/JALR目标、加载/存储未对齐、延迟数据总线错误、ECALL、非法CSR及三种中断。MEM停顿时持续改变年轻EX元数据，验证陷阱不被污染，并核对mtval/mcause/mepc提交。

scripts/test_trap_value_controls.py包含正常实际RTL与八个临时RTL变异：错误选择PC/跳转目标、引用年轻EX的PC/有效地址、非法指令返回PC、非零中断异常值、丢弃cause最高位、总线错误使用年轻地址。变异必须由对应值断言拒绝，编译错误或超时不算检出。生产RTL不被变异修改。

最终定向测试通过3249项检查（build/tval-unit-final.log），包括半字/字未对齐、低位PC、地址回绕以及待决异常/访存复位取消；最终八个变异全部被预期断言拒绝（build/tval-controls-final.log）。完整validate.ps1运行通过（build/validate-tval-reuse.log），涵盖原有单元、CPU/SoC、差分参考与内存比对、严格lint和检查器反例。全回归起跑后的定向测试增强已单独重跑，不冒充全部增强均在同一次全回归内执行。 另外将同一最终定向测试对上一轮20260906-192055-5533ee5b快照中的旧核心运行，亦通过3249项检查（build/tval-unit-baseline.log）；新旧测试预期相同，未借此次结构改动改变异常值规范。
