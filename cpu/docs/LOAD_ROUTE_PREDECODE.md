# 加载响应字节路由预译码

本轮独立基于已完整配对的全偏移加载地址旁路版本，不叠加失败的WB匹配预译码或I-cache碰撞隔离。生产RTL与GitHub不变。

## 改动依据和电路结构

上一轮实际最差路径从D-cache同步读输出，经加载格式/偏移提取、有效地址长进位链，进入下一次D-cache请求状态控制；并非只由最低两位对齐判断造成。本实验将原先在数据返回时执行的字节移位和格式选择，改为进入MEM时寄存17位字节路由与符号扩展控制，再用按位掩码组合返回数据。

核心为experiments/load_route_predecode/rv32_core.sv，SHA-256 F02A7F259598E85E5F2B8344ACC21FB1F347E714310B9F3DDADA6C4D70D7183C。低字节支持四个输入字节；第二字节支持三个数据来源及LB符号扩展；第三字节支持两个数据来源及LB/LH符号扩展；最高字节支持一个数据来源及LB/LH符号扩展。控制在原ex_fire处与mem_funct3、mem_address同拍捕获，停顿时保持；没有增加流水级。

仍保留LB/LBU/LH/LHU/LW、全部4个偏移和保留格式的原始组合语义。即使非法/未对齐请求最终不会提交，也不借此删掉原数据提取行为；例如偏移3的LH仍等于零填充右移后进行半字符号扩展。非load仍返回mem_result。普通前递、加载地址旁路、执行资格、请求有效、MMIO路由、错误响应和精确异常逻辑不变。逻辑控制位数量不是物理总FF增量；当前原生综合网表可见16个命名路由触发器，最终资源与时序以完整PDS报告为准。
