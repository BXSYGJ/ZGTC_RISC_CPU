# 局部分支历史：执行效率与资源联合优化

日期：2026-09-07。候选保留在 `experiments/btb_local_history/rv32_btb.sv`，独立实现位于 `build/btb-local-history-stage`。未替换生产 BTB，未上板，未上传 GitHub。

## 为什么改预测器

当前生产组合为同步只读 I-cache、地址扇出 32、保留 ALU 高段预计算以及折叠索引的 256 项双模态 BTB。它的合格本地实现是 132 MHz/种子7（8090 LUT、5021 FF、WNS +0.102 ns）与 135 MHz/种子1（8222 LUT、4989 FF、WNS +0.003 ns），详见 `ALU_KEPT_PRECOMPUTE.md`。本次保持其他 19 份 PDS 输入及固件不变，只替换预测器，优先减少实际执行周期。

双模态预测器每项只有一个两位饱和计数器，混合了同一分支的不同历史。新候选每项保存上次是否跳转，并准备两组两位计数器：上次不跳转时查一组，上次跳转时查另一组。更新时先训练旧历史对应的计数器，再记录本次结果。没有新增流水级，也没有修改 CoreMark 算法、种子或编译选项。

## 先观察，再筛选

`experiments/btb_history_profile/coremark_compiled.cpp` 是原编译式仿真驱动的只读采样副本。仅在下降沿求值之后，采集真实 `mem_fire && mem_branch && !mem_fault` 事件；字段包括 PC、指令、目标、实际下一 PC、预测 PC、方向及条件分支标志。它没有修改任何 RTL。

窗口从退休的 `iterate` 入口开始，到 `stop_time` 入口之前结束。当前十轮性能 ELF 的两个地址为 `0x1398`、`0x5a88`；审计不仅检查符号，还从该 ELF 重新提取二进制、补齐并编码成 hex，与仿真固件逐字节比较。窗口前后分支均保留，用于预测器预热。遇到动态 FENCE.I 失效立即拒绝分析；不能声称该固定驱动适用于任意固件或所有控制流。

权威采样构建：`build/btb-history-profile-stage/build/compiled/20260907-110125-0c4d9d9a`。18 份编译输入只有 C++ 驱动不同，UART 与普通驱动的同固件基线逐字节相同，结果 JSON 相同；基线构建为 `build/compiled/20260907-094529-ba4a636d`。

- CSV SHA-256：`6B07535ACA82D689D6D6B46405A782FE14F136DBD8D28A609BBC9BF40A269095`；662956 条事件，含窗口外预热。

132 MHz 同种子对照为8090 LUT/5021 FF/+0.102 ns：新候选少27 LUT、多20 FF，时序裕量减少31 ps，而短仿真执行效率提高。135 MHz种子7与旧双模态种子1是不同布局种子的比较，不能把全部面积/时序差异归因于算法；新候选同种子1仍失败。正裕量也不证明长期稳定性。

已完成的五份实现均18 DRM、4 APM。资源效率必须用同一位流对应的完整实板分数和布局后 CLMA+CLMS LUT 分母，不能把历史实板399.9231 CoreMark直接除以8063或8181。当前正式 CoreMark/LUT 不更新，0.031门槛仍需对应硬件长测闭环。

135 MHz种子7验证 PDS（`20260907-113733-79a3e1f7`）也已通过，8181 LUT、5009 FF、WNS +0.026 ns，位流 SHA-256 为 `675537120AC17D1F7BF171C19BC74AC01A969C7FB0CF4F323745ED41DF753435`。两组频点均完成性能/验证源输入和原始时序/资源成对审计；135 MHz种子1失败保留，不混入合格集合。
