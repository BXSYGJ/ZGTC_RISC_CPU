## 目的与证据边界

新增独立诊断固件，不修改120 MHz CoreMark达标版RTL或基准算法。诊断将UART收发与KEY外部中断分开：板级真实连接为GPIO bit0 = ~key（C23），bit1 = uart_rx（远程UART RX为AC26）。UART跳变不是独立按键事件，不能仅凭串口引起GPIO变化便宣称按键验证通过。

此固件只允许GPIO bit0触发外部中断，UART中断关闭；所有通信都先检查RX状态，再读UART_DATA，不用阻塞读阻碍后台中断响应。中断服务程序检查mcause及实际GPIO已使能挂起位；异常来源进入dead0010故障状态，不伪造成功。

## 命令

通过115200、8N1发送单个大写ASCII字符，收到完整响应后再发下一条。CR/LF被忽略，兼容网页文本发送自动追加LF；其他字节返回GPIO UNKNOWN，没有控制副作用。状态行固定61字节（含CRLF），保留五个完整32位十六进制字段，避免首版长行在远程传输中出现的截断。不能由此推断后端缓冲区的确切深度。

| 命令 | 行为 |
| --- | --- |
| S | 输出原始同步I、累计中断N、bit0挂起P、最近服务L和完整使能掩码E |
| A | 仅当KEY释放（bit0=0）时允许：清除旧挂起位、计数及LED，开启bit0；返回GPIO ARMED |
| D | 关闭GPIO中断使能，但保留计数和挂起记录；返回GPIO DISARMED |

KEY已按下时A返回GPIO RELEASE KEY FIRST，原有使能与计数不变。首次启动及复位默认不使能GPIO中断，启动输出GPIO READY。每个服务的bit0上升沿计数加1并写入GPIO_OUTPUT；持续按住不应重复触发，下降沿不计数。没有按键去抖，因此实体开关抖动可能产生多个真实上升沿，不能把计数直接等同于人的按压次数。

S在短暂屏蔽CPU全局中断期间读取字段，以避免中断服务更新计数与L造成撕裂；硬件输入和挂起位仍可能在各次MMIO读取之间改变。它不是同一时钟沿原子硬件快照，也不测量输入到中断延迟。

## 构建与测试

PowerShell 7：

~~~powershell
& ([System.IO.Path]::Combine('D:/AAAFPGA', 'ZGTC_RISC_CPU', 'cpu', 'scripts', 'run_gpio_tests.ps1'))
& wsl.exe --distribution Ubuntu-22.04 --exec /usr/bin/python3 /mnt/d/AAAFPGA/ZGTC_RISC_CPU/cpu/scripts/test_gpio_diagnostic.py
~~~

build_gpio.ps1采用既有RV32 GCC 10.2.0、RV32I/ILP32/O2、启动和链接脚本，生成独立时间戳目录，不覆盖CoreMark固件。清单记录输入源码、工具链、固件哈希；默认ClockHz=120000000，可选27000000。代码不依赖计时常数，该时钟字段用来与PDS配置绑定，不是频率实测。

run_gpio_tests.ps1运行实际rv32_board_top、CPU、存储系统和MMIO；不在测试里复制GPIO板级映射。测试通过串行引脚发送命令，逐字节检查固件返回和UART起止位，并观察真实核心trap事件。覆盖默认配置与达标配置（M、I8/D2 KiB、BTB256、全部已选快路径）。测试时钟/波特率缩比为3200/100，只证明RTL功能，不产生实板或频率证据。

序列覆盖：启动屏蔽、UART单独跳变、第一次上升沿、持续按住、下降沿、第二次上升沿、屏蔽期间挂起、按住时拒绝重置、释放后重新使能清旧挂起、第三次上升沿、按住时复位。状态行、LED和累计陷入次数交叉检查，不仅检查PASS字样。

test_gpio_diagnostic.py将UART误接KEY、KEY极性反转、GPIO使能错误扩到bit1、漏清中断挂起、错误增量分别注入临时副本；要求在具体UART/固件/中断风暴检查失败，编译失败或超时不算抓到缺陷。不会改写工作树RTL或正确固件。

构建日志在build/gpio、测试日志在build/gpio-tests；result.json明确标为RTL_SIMULATION_ONLY并绑定运行输入哈希。总回归validate.ps1已接入这两项。

## 实板流程与限制

用build/gpio-latest.json中的Hex传给run_pds.ps1，必须显式指定120000000、RemoteLab、115200及达标候选全部参数。固件与PDS位流均有独立哈希，不将新诊断位流当作旧CoreMark位流。

上板先S确认释放电平，再A；仅发送串口命令和55/AA时计数应为0。随后需要独立外部KEY电平输入，依次记录释放、按下、保持、释放、屏蔽、重新使能的返回和板卡来源。对真实机械开关应结合波形判断抖动，不强求一按一次。

远程网站数字孪生的虚拟按键采用边界扫描驱动；在未确认扫描指令、数据通路及是否影响正常用户逻辑运行之前，不能将它当作实体按键接触证据，也不凭前端视觉变化判定已驱动C23。诊断固件、仿真和PDS通过都不能填补独立输入实板缺口。
