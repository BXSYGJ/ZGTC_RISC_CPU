# 并行前递选择与字加载旁路

2026-09-07。本轮独立以MMIO_READY_PAYLOAD的合格16 KiB I-cache、2 KiB D-cache、H3预测器版本为基线，不混入CACHE_COLLISION_FORWARD的失败缓存。生产RTL与GitHub已发布版本均不改变。

## 两个候选与不变量

- mask源0BC6382F11826855F587D977C75AD67F37E0EA03C21471AAC76445B3A4127291：先生成互斥EX/WB/MEM选择条件，再按位掩码并联选择操作数，尝试减少级联选择深度。
- raw_word源08A722CF39D507E2A25B9B8CCFBF1FCCEA0DF8BDB6AA6165A47C6F8F4B9C303C：在mask上为无bubble、字加载且地址低两位为0的情况增加原始响应数据旁路，其他情况保持原mem_value提取。

选择优先级仍是MEM覆盖WB、WB覆盖EX；零寄存器和未使用的源操作数始终为0，异常MEM不参与前递。LOAD_USE_BUBBLE=1时不前递load。数据选择仍独立于响应有效/错误资格，执行、提前请求和异常提交继续由原mem_ready、mem_flush等控制，不能据此允许年轻指令提前执行。

raw_word只绕过真正等价的已对齐字加载；未对齐字、字节/半字及保留funct3的原组合行为也全部保留，未借助“通常不会发生”删减语义。未增加流水级、配置位或改写CoreMark算法。

## 实际验证

sim/forward_parallel_tb.sv直接实例化真实核心，采用项目已支持的整译码结构体/寄存器强制方式，只隔离数据选择。每个源和bubble组合65792组：256种资格/使用位、8种寄存器别名关系、8种加载格式、4种低地址组合，另有256组边界数据。原基线与两候选各两种bubble，共394752组比较，其中候选263168组、参考131584组；这是组合定向检查，不是形式认证或流水级完整证明。

12个优先级、零寄存器、使用位、异常、bubble及raw-word边界的编译变异均被运行时拒绝。两候选另外继承已存在的无效响应扰动检查：各4种预测/bubble组合通过独立退休参考与内存比较，各3个执行/错误资格反例被拒绝。完整6项unittest终态通过。

两候选CPU/SoC、独立参考、严格板级lint、合计392次外部ISA及16个拒绝控制均已完成并审计。每套十轮性能/验证短跑的全部UART字节和结果与对应MMIO I9基线相同：3199743/3206720周期，退休指令2748941/2749614，CRC正确。18项编译输入、20项PDS输入都只改变核心文件，固件、约束、缓存和参数保持原值。新增测试的可覆盖路径接口未改变旧测试默认源。

## 下一步依据

已开始对已有LOAD_USE_BUBBLE=1参数做执行代价探测，而不是直接加入流水停顿后只报告频率。十轮探测显示性能周期增加6.08993%，对应短跑代理值约2.94585，尚不支持直接采用全局停顿。详见LOAD_USE_COST.md；后续应先统计真实加载依赖的类型，再判断能否选择性保留廉价操作的旁路、只对长路径操作停顿，同时满足至少3.0 CoreMark/MHz与0.031 CoreMark/LUT。这里是后续方向，尚未实现选择性策略或证明频率提升。
