# 缓存地址边界与加载前递时序修订

2026-09-06。本轮从MUL_REQUEST_CAPTURE.md的64项BTB、I/D各2 KiB、120 MHz候选继续优化。硬目标仍为120 MHz达到3.0 CoreMark/MHz；本文的短仿真不能作为正式成绩。

## 有界标签，不产生地址别名

rv32_cache新增ADDRESS_BITS参数，单位为字节地址位数，独立模块默认32位；memory_system按实际后端RAM的字地址位数加2传入。当前SoC字地址14位，因此字节地址16位；两路Cache的SET_BITS=6、WORD_BITS=2时，标签由22位缩至6位。通用约束为WORD_BITS+SET_BITS+2 < ADDRESS_BITS <= 32；本工程已开放的几何组合均满足。

- 在接受请求时检查完整32位地址的高位，超出范围直接返回错误，不查缓存、不发后端命令；不能只截断地址再查标签。
- 只在上述完整检查后使用低地址部分；正常替换和维护写回都显式补零重建完整32位行地址。每行16字节，物理边界为2的幂，最后一个合法字的整行填充仍在边界内。
- I-cache非法高地址产生取指访问错误；D-cache的MMIO译码仍先于缓存选择，MMIO地址不受RAM范围检查替代。CPU保留原始完整故障地址，缓存内部压缩不修改异常tval。
- 新的越界请求与既有未对齐/只读写入错误一样，在LOOKUP之前拒绝，不增加hit/miss计数，也不逐出已有脏行。历史版本可能先计一次miss再等待后端错误，不能混用两版失败访问计数。
- 配置字不新增位；内部修订靠源码快照区分，不能由历史配置字追认旧版本已经缩短标签。

### 按指令类别缩短控制路径

核心仍用原来的execute_exception/cause/tval生成MEM阶段异常。新增的短资格只用于对应类别的握手：M指令使用中断、PC未对齐、取指错误及非法译码；加载/存储在此基础上加数据未对齐。乘法器等待、取消及提前访存不再经过与该指令类别无关的分支条件比较。

cached_core_tb、isa_tb和muldiv_core_tb逐拍断言：在对应EX指令有效时，短资格与原完整异常判断相等。删除M中断资格、删除数据未对齐资格的两个独立变异均命中指定断言，日志为build/class-exception-negative-no_irq.log及class-exception-negative-no_alignment.log。没有改写完整异常优先级来迎合测试。

### MMIO请求寄存

memory_system在CPU接受MMIO请求时锁存地址、数据、写标记及字节选通；外设请求仅由这些寄存器驱动，直到外设真正接受。仍只允许一笔未完成的数据事务，不允许年轻请求越过旧响应；DATA_OVERLAP开启时的完成沿交接规则保留。MMIO多一级请求延迟，RAM/Cache路径不增加这一级。维护操作等待已接受事务完成；复位丢弃尚未交给外设的请求。

快照计数器在外设端valid/ready握手沿统一锁存。CPU入口接受现在可能早一拍或更多拍，不能再把两者当作同一沿；正式CoreMark周期依旧来自CSR计时，计数快照区间仍包含额外边界开销。

### 保持响应数据，而非每请求清零

取消新请求对内部response_data的无条件清零，避免后续请求的长控制路径回到旧响应寄存器使能。错误响应通过输出选择仍返回零；正常有效响应、背压保持、复位及刷新规则不变。缓存测试额外断言所有错误响应的数据为零，不依赖“错误时数据无所谓”来修改接口表现。

## 验证证据

- 有界Cache复用完整随机/替换/写回测试，另覆盖10位、14位、16位地址范围；逐个测试所有被裁掉的高位、首末合法字、脏行保护、完整地址写回、错误响应背压及有效/无效请求交接。
- memory_system测试检查I/D两侧实际继承后端地址宽度。test_cache_address_bounds.py包括正确RTL、删除高位检查、截断写回标签的正负对照，变异不修改正式源码。
- MMIO单元覆盖立即接受、寄存读响应和外设额外阻塞5拍；8笔正常事务完整响应，另有1笔被复位取消的未发出请求。CPU输入改写不影响已锁存请求，副作用不重复，复位后不泄漏请求。
- 将MMIO数据改回CPU引脚直通的变异命中“MMIO payload is latched independently of CPU pins”断言，证据build/mmio-register-payload-negative.log。
- 最终完整回归build/validate-response-hold-final.log通过，包含单元、CPU、参考模型、内存比较、lint和变异检查。外部RV32UM为32条测试加4个故障对照（20260906-173847-d3b11c57），RV32UI为164条测试加4个故障对照（20260906-173929-e3659b22），均通过；不等同于穷尽全部指令序列。
