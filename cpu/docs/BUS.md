# CPU 存储总线契约

指令和数据使用独立的请求/响应通道，每通道最多一个未完成事务。CPU、Cache 和片上存储控制器复用这一接口，不能通过取消已经接受的访问来实现冲刷。

- 请求仅在 `req_valid && req_ready` 的时钟沿接受。valid 已置位而未接受时，地址、数据与字节使能必须稳定。
- 请求接受后，控制器至少下一周期才给出响应。响应在 `rsp_valid && rsp_ready` 的时钟沿完成，等待 ready 期间数据与 error 保持稳定。
- 数据请求地址为 4 字节对齐，`wstrb[3:0]` 指定有效字节；读返回完整 32 位字，由 CPU 完成偏移与符号扩展。
- 错误响应对应访问故障；错误写不得产生存储器或外设副作用。未对齐半字/字在 CPU 内捕获，不发总线事务。
- MEM 阶段按序发出数据访问，投机指令不得访问 MMIO。前端跳转时排空已接受的旧取指响应，丢弃其内容。
- 缓存维护必须先完成脏数据写回，再使指令 Cache 失效；维护完成前 FENCE.I 不退休。

上述为本项目内部接口，不声称是 AXI。

## 已实现的突发后端

- `rv32_cache` 输出独立命令 `cmd_*`、写数据 `w_*`、写应答 `b_*`、读数据 `r_*` 四组握手信号。
- 命令包含 32 位字节地址、读写方向和 8 位 `cmd_length`，实际拍数为 `cmd_length + 1`。Cache 行为 `2^WORD_BITS` 个 32 位字，默认 4 拍、16 字节。
- 命令、各数据拍和应答在 valid=1、ready=0 时保持稳定；命令接受后的下一周期起才能发送数据。r_last/w_last 标记最后一拍。
- 两主机仲裁器以完整突发为单位锁定归属，读末拍或写应答完成后切换；同时请求时轮转，不能在命令等待 ready 时更换目标。
- 写回 RAM 先缓冲全部写拍并检查地址、长度与 last，再逐字提交。非法命令或不匹配的写 last 返回错误，不修改 RAM。
- 读错误随每拍返回；Cache 只在全部拍无误且 last 正确时设置新行有效位。过早 last 使该行失效，缺失末拍标志时保持排空状态直到收到 last。
- 写回失败保留原脏行，不能提前丢弃；维护错误经 `maintenance_error` 返回，不得当作维护成功。SoC 将其锁存为 `maintenance_fault`，不给 CPU 维护成功响应，也不重发维护；CPU 停在 FENCE.I，复位恢复。板级 LED 显示 E1，故障注入回归验证停机后无退休和年轻副作用。
- RAM 当前默认 16 KiB，默认单次突发上限 16 字；存储系统按 Cache 行长配置该上限。它是片上存储后端，不声称已经实现 DDR 控制器。

## I/D Cache 与维护顺序

`rv32_memory_system` 集成独立两路组相联 I/D Cache、轮转仲裁器与可综合 RAM。I-Cache 只读；D-Cache 写回、写分配、支持四个字节写使能。每组使用一位 LRU，优先使用无效路。

默认每个 Cache 为 16 组 × 2 路 × 16 字节 = 512 字节。容量参数化；当前集成回归额外测试 2 组配置以强制冲突替换。

数据地址小于 `0x10000000` 进入缓存存储路径，超出物理 RAM 范围由后端返回访问错误；其余地址走独立 MMIO 端口，不分配 Cache 行。实际 SoC 配置 RAM 为 64 KiB；具体地址见 `PERIPHERALS.md`。

维护先排空数据事务、写回并失效 D-Cache，再失效 I-Cache。CPU 在 FENCE.I 等待期间停止新取指、排空旧取指响应并清除年轻流水级，解除“缓存等待响应被接收、CPU 等待缓存失效”的循环依赖。维护完成后从 FENCE.I 的下一条指令重新取指。
