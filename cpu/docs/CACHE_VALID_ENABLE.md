## 电路变化

规范源experiments/cache_valid_enable/rv32_cache.sv，SHA-256 16A56BAF0E06E2F7D1477DFC7E289C10B5CCAF09E43213A453F07E6D058A8FBD。CPU保持F02A7F259598E85E5F2B8344ACC21FB1F347E714310B9F3DDADA6C4D70D7183C；相对8707 LUT父工程20项物理输入、18项短测编译输入均只有缓存不同。

本版仍只为D-cache增加两个有效位寄存器，不预读标签、不增加流水拍。与连续预读版的区别是：

- req_ready时按实时请求组号读取两路有效位，包含req_valid为0的ready窗口，与原请求地址采样约定一致。
- 否则，仅在无累计或本拍错误的成功回填末拍，将victim对应的一路有效位置1，另一位保持。
- 其余忙态保持两位，不再通过实时/保存索引二选一来持续读取有效位数组。
- 回填期间victim必须属于当前请求组；有错误的回填不能视为成功提交，刷新后的新请求须重新采样真实数组。

有效位与底层数组的一致性要求位于LOOKUP消费阶段；其他阶段遵守采样、保持和回填更新约定，不宣称全状态都与数组同步。标签、数据RAM、字节合并、写回、LRU及I-cache分支均保留原语义。

原生网表实际仍是两个GTP_DFF_C，保持行为经D端逻辑实现，而非带独立CE端的触发器。本版没有关断时钟，不能仅凭条件更新语句宣称降低时钟功耗。最终FF变化以布局报告为准，不等于RTL新增位数。
