## 来自实际路径的修改

下一状态IRQ父版20260909-011430-8304d6bb最终157.5 MHz、9200 LUT、5183 FF、WNS -0.291 ns失败。其最差路径从MMIO请求地址[22]经写译码进入64位递增进位链，再到下一状态比较和IRQ寄存器；问题不再是原来的IRQ组合输出直接贯穿CPU。父版功能及原生/来源审计通过，但没有时序资格。

本候选在experiments/timer_increment_boundary/rv32_peripherals.sv保留完整timer_value+1运算为timer_incremented，再由原下一状态逻辑选择写入结果。只新增带syn_keep的64位线网边界，并将默认下一状态改为该线网；不改计数器值、不加流水级、不增加中断周期、不拆成可能改变X传播的分段加法。是否真正改善时序必须由本次实现证明。

规范外设SHA-256：B61ED1BC98CA4B6375AA27337FB6C68091FBFEBA156495424D71431A6F4630E6。直接父版为555426210B1380AB8D20EAEF3FB8EE893CA6031356420DAB261C678CC57ADEF6；CPU2807、ALU3BF、PLL2C1C保持，另外19份物理输入逐项相同。生产RTL及已发布版本未修改。

## 最终结果与后续方向

Windows PDS 20260909-014133-12495d99（会话28764）已退出1：157.5 MHz、种子2、9295 LUT、5179 FF、WNS -0.110 ns，时序不合格。最差路径转为EX立即数[1]经PC相对目标加法、预测目标比较到IF指令寄存器CE，12级逻辑，逻辑延迟2.027 ns、布线3.800 ns，末端路由扇出94。递增边界未带来合格时序，不能启动完整计分或称为500分版。

实际原生网表审计已完成：64位递增4032组真值、下一状态比较3080组、D/CE捕获3072组以及写使能正反译码32组均通过；使用当前实际常量输入先做逻辑化简，不展开LUT6D未选中的平面。首位共享原语只证明递增输出函数隔离，不声称所有原语引脚均来自计数器。原始PDS模型实际运行比较40256次和递增4288次。专用测试7项14.525秒、77个变异拒绝通过。

原始ISA/SoC证据反例测试4项586.782秒、18个拒绝通过。完整来源审计会话95239退出0，确认来源与实际原生结构，但performance timing=False、full pair=False；无长测、新成绩或实板结论。
