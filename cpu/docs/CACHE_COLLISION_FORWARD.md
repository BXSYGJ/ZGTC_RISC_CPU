# 写读碰撞前递的状态分解

2026-09-07。本地隔离候选，缓存SHA-256为D34848005B91D1CAD1DC30B2362B0E9386837091E1A7502FC36693773D39768E，基于CACHE_LRU_STORAGE中的直接数组版BB337C68。生产核心/缓存没有替换，不上传GitHub。

## 修改依据

直接数组版135 MHz种子7的最差路径从D-cache同步读数据经加载前递、有效地址进入read_index，再通过store_index==read_index比较进入forward_way1。旧写读碰撞逻辑先选择写地址和读地址，再比较完整索引。

新逻辑将写命中与填充分开：写命中仅发生在LOOKUP，既不是写回状态，读索引就是已保存请求或req_ready选择的新请求；填充只发生在FILL_DATA，此时req_ready和writeback_read均为0。因此写命中的比较可写为!req_ready或新旧请求索引相等，填充则比较victim/beat与已保存请求索引。两种状态互斥，最后分别按hit_line与victim选择前递路。

不更改请求资格、载荷捕获、字节合并、存储数组、写回节拍、执行周期或LRU策略；不是省略碰撞处理。只有D-cache的前递标志组合表达式改变，I-cache保持原实现。

## 验证

scripts/test_cache_collision_forward.py复用LRU差分夹具，并逐拍额外断言新碰撞条件等于旧索引比较、两路已寄存前递标志等于独立DB55缓存参考，以及所依赖的状态条件成立。七项测试终态通过：96种模式/任意初值并训练后复位，32种物理几何加32个参考，6个完整容量场景加6个参考，12种地址/别名加12个参考；另有32种同步可写覆盖，检查两路前递、部分字节合并、store碰撞、写回首拍/后续拍及回压。

10个LRU变异和10个碰撞/前递数据变异都已编译，并由运行时检查拒绝。CPU/SoC、独立参考、严格lint以及196次ISA正例、8个拒绝控制均已完成。两种132 MHz十轮短仿真的UART和结果与MMIO I9基线逐字节相同，性能3199743周期、验证3206720周期；不是计分长测。

父夹具仅新增可覆盖的候选路径和miter变换方法，默认源及默认覆盖参数不变；test_forward_data_controls的后续可覆盖路径改动同样不改变原测试的默认目标。

## 实现结论

135 MHz/种子1构建20260907-175355-d3f8a548：8618 LUT、5135 FF、21 DRM、4 APM、WNS -0.192 ns，明确失败。相对直接LRU同种子的8578 LUT、5123 FF、WNS -0.088 ns，没有观察到收益。最差路径改为D-cache读数据到core/mem_result，不能把终点转移当成整体时序提升。

原生网表仍为两个LRU RAM256X1SP和一个RAM64X1SP，没有恢复576个LRU触发器；这不证明布局时延改善，也不等于原生网表全功能等价。20项PDS输入和18项短仿真输入均独立核验，相对MMIO I9仅缓存文件不同；相对直接LRU源，候选只增加两条碰撞条件并替换两路前递更新式。完整报告、位流、固件和源哈希在build/cache-collision-forward-audit.json；ISA逐条日志审计在build/cache-collision-forward-isa-audit.json。

本候选未取得135 MHz联合合格结果，不运行无合格PDS绑定的计分长测、不上板，不借用旧长测周期组合新LUT。下一轮改为检查核心前递选择深度，两个新的前递实验以已合格MMIO I9为独立基线，不混入本失败缓存。
