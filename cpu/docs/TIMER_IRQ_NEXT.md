# 下一状态定时器中断预计算

## 目标与边界

2026年9月9日更新后的目标仍先要求CoreMark至少500、执行效率至少3.18 CoreMark/MHz、资源效率至少0.052 CoreMark/LUT，优先160 MHz以上、困难时争取157.165 MHz以上。接受500分基线后改为提高执行效率，频率及资源效率不得下降。当前无新500分合格结果。

前递匹配寄存父版20260909-004247-5480b202的157.5 MHz实际WNS -0.416 ns，前三条setup路径均从timer_value[36]到next-PC使能。该父版时序失败，不直接采用；本次在隔离工程继续修改真正出现在关键路径上的定时器中断来源，而不是继续同源换种子。

## 无额外中断周期的变化

- 新增timer_value_next与timer_compare_next组合下一状态，默认计数器加1、比较寄存器保持。
- 只有被接受的写请求才能覆盖相应半字；四个寄存器地址均自然对齐，保持原字节掩码。TIME_LOW/HIGH写入覆盖整份计数器，因此即使零strobe也保持该拍计数器、不进行默认加1；这与原非阻塞赋值优先级一致。
- 对两份下一状态继续采用原32位分段相等/大小关系组合，在同一时钟沿捕获irq_timer，同时更新timer_value/timer_compare。不是将旧irq简单延迟一拍，也不改软件可见定时器值。
- 保留分段比较的四态语义，不擅自换成单一64位关系式。其余外设、响应状态、UART/GPIO、计数器读取与CSR计分机制不变。

规范外设源：experiments/timer_irq_next/rv32_peripherals.sv，SHA-256 555426210B1380AB8D20EAEF3FB8EE893CA6031356420DAB261C678CC57ADEF6。CPU为2807、ALU为3BF、PLL为2C1C，与父版其余19份物理输入完全相同。生产RTL未替换。
