# 分支专用加载前递候选

2026-09-07。隔离实验：不修改生产输入、不更新GitHub、不宣称新硬件成绩。

## 设计与因果依据

退休跟踪（LOAD_USE_PROFILE.md）显示，原MMIO I9版本切换全局LOAD_USE_BUBBLE后，约68%的额外周期位于加载后的条件分支。候选在LOAD_USE_BUBBLE=1时保留通用ALU、地址计算、存储数据等消费者的加载停顿，只让条件分支比较器通过独立branch_operand_a/b使用MEM加载值。响应无效或故障时仍由既有mem_ready/mem_flush资格控制阻止年轻指令提交，不将数据选择重新耦合到响应有效信号。

原版的forwarded_a/b通用路径不再承载该模式的加载结果，分支比较单独使用MEM/WB/EX优先级。LOAD_USE_BUBBLE=0时保留原来无停顿语义。JALR不是条件分支，仍使用通用地址路径和加载停顿；不硬编码CoreMark指令地址。

源：experiments/load_use_branch_bypass/rv32_core.sv，SHA-256 9FDB11F57915975C491490588447E36284452BB95A5BFDE3E06E8AFC8884612B。阶段目录：build/load-use-branch-bypass-stage。18项编译输入、20项PDS输入相对MMIO I9只有核心文件变化；LOAD_USE_BUBBLE由0改为1。运行配置字仍显示该参数位为1，不能单凭配置字区分全停顿核心和本候选，必须同时绑定核心哈希。

## 正确性与拒绝控制

- scripts/test_load_use_branch_bypass.py：5个方法全部通过。两种bubble模式各1052672个分支条件/数据路径断言，共2105344次；覆盖全部比较类型、源寄存器别名/x0、WB/MEM优先级、加载宽度/偏移、非法响应、异常、通用操作数不受分支路径污染。
- 10个编译变异全部被功能断言拒绝；另有4种预测器/加载模式的毒化响应CPU正例、3个错误控制拒绝。
- 加入1组实际cached CPU正例与“恢复全停顿”负例，确保专用覆盖断言确实要求分支前递和非分支停顿同时被执行。
- 初次扩展fixture的最终计数仍是65792，导致两项正例失败；已改为65792×16=1052672，并要求变异不能靠“计数不完整”获得拒绝。最终完整测试日志为build/test-load-use-branch-bypass-complete.log。
- 原cached_core_tb要求所有加载依赖前递次数为0，按新设计会在成功程序结束时失败。保留原测试不改；新增experiments/load_use_branch_bypass/cached_core_tb.sv，逐次禁止非条件分支绕过MEM加载，同时要求通用停顿、WB加载前递及分支直通均有正覆盖。它不是删除原断言后只看通过标志。
- 本候选缓存CPU两预测器配置通过参考模型的逐退休/最终内存检查，各处理13次陷阱；UART SoC为74项检查、8238周期、23字节输出、三类中断计数1/1/1；故障SoC为41项检查。日志：build/load-use-branch-bypass-cpu-soc-final.log。
- 外部RV32UI 41项×4配置=164次，RV32UM 8项×4配置=32次，合计196次，另有8个拒绝控制。ISA构建20260907-191226-ddb5beea、20260907-191458-bef74cb3，源、适配器、固件、日志和案例清单均已审计；不是完整ISA认证。

## 后续决策

本轮同时取得“全停顿性能损失可显著收回”与“135 MHz关键路径已转移”的证据，但没有在三指标上取得全面改善。下一步优先检查实际乘法结果关键路径，并考虑与已验证功能的LRU压缩组合；每个组合仍需独立仿真和PDS验证，不能把不同候选的周期、LUT和频率拼成一个成绩。正式约束保持至少120 MHz、3.0 CoreMark/MHz和0.031 CoreMark/LUT，不降低目标、不声称有限实验已到物理极限。
