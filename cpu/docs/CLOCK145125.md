# 145.125 MHz加载路由预译码实验

## 结论

隔离工程build/load-route-145125-stage完成真实固件构建、双短测和PDS实现，但时序失败：PG2L200H-6FBB676、布局种子1，构建20260908-010359-05d180df，8749 LUT、5147 FF、WNS -0.319 ns，Some Constraints Violated。没有合格实现manifest，不采用该频点，不继续安排此失败实现的验证固件PDS或6000轮配对长测，也不把PLL模型通过当作CPU或板测通过。生产RTL与GitHub不变。

完整本地基线仍为全偏移加载地址旁路144 MHz：8626 LUT、5123 FF、WNS +0.005 ns；原有配对长测的3.128078805047 CoreMark/MHz、450.4433479268 CoreMark和0.0522192612945 CoreMark/LUT仅为来源绑定的RTL投影，不是新实板成绩。该基线裕量很窄，不能称已经达到物理极限。

## 隔离与真实频率

父工程为144 MHz加载路由预译码，PDS 20260908-003055-c2bb6c28。20项物理输入中19项逐字节不变，唯一RTL差异为PLL；CPU仍为F02A7F259598E85E5F2B8344ACC21FB1F347E714310B9F3DDADA6C4D70D7183C。新PLL SHA-256为6FB1B0CBA84DD4E84C5593F79602C4966F8B385D0208FD5AC209978724248A73。原生综合网表核验27 MHz输入、I=1、M=1、F=43、O=8及占空参数，标称输出145.125 MHz、VCO 1161 MHz。

仅在新stage扩展build_coremark.ps1、run_pds.ps1、check_coremark.py的精确频点白名单，以及run_pll_tests.ps1的模型测试频点；不修改旧工程白名单。四份固件均从固定EEMBC上游重新编译，实际使用-DCPU_CLOCK_HZ=145125000u：性能/验证数据集各有10轮和6000轮镜像。审计检查编译选项、工具链清单、端口与上游源哈希，并从每个ELF重新objcopy，确认二进制及补齐后的HEX一致；不是对旧固件换标签。

## 已完成验证

- 显式频率检查23项通过；PowerShell三份脚本语法/BOM/精确改动检查及8个邻近非法频率参数绑定拒绝通过。
- 原厂PLL模型的132、135、141.75、144、145.125 MHz五个跨度与复位重新锁定检查全部通过，新频点200周期跨度1378.158132 ns；不由此推断CPU时序。
- 性能短测20260908-010622-71a1ed2c为3205068周期、2748941条退休；验证短测20260908-010637-0d395a87为3211054周期、2749614条退休。均标记145125000 Hz，与父工程同数据集的周期、退休、CRC和完整profile一致。
- 这两次10轮短测不满足至少10秒的计分条件，没有本频点6000轮执行结果，不提供新的CoreMark/MHz或CoreMark/LUT分数。已构建6000轮固件不等于已经跑完长测。
- CPU、缓存及其他非PLL硬件输入不变，继承父工程的ISA、随机停顿、加载路由状态与SoC差分覆盖；这些不是本频点新执行的ISA或板级测试。

## 时序失败与报告量化

相对144 MHz路由预译码父工程8801 LUT、5162 FF、WNS +0.050 ns，新布局少52 LUT、少15 FF，但WNS恶化至-0.319 ns；不能因面积下降而接受时序失败。实际前三条最差路径从D-cache的storage_way0_bwe_2同步读输出，进入forward_way0、forward_way1和core/mem_next_pc[31]。当前布局的瓶颈排序不同于父工程的I-cache请求控制路径；不能仅凭前三条路径断言其他路径已消失。

原始报告声明参考周期37.0370 ns，生成时钟周期6.8900 ns、波形{0.0000 3.4450}。这与参考周期乘8/43、半周期按1 ps量化后乘2的观测一致；标称145.125 MHz周期为6.890611541774333 ns，两者约差0.612 ps，远小于319 ps违例。这里只解释已观测的报告值，不作为所有厂商报告的通用规格。

首次来源审计因原先0.51 ps的周期容差而拒绝，原日志保留为build/clock145125-audit.log。修正后的审计显式检查声明时钟、生成时钟波形、半周期量化及小于1 ps的标称周期偏差；未修改约束、原始报告、源快照或位流，也未将失败标记改为通过。build/clock145125-audit-corrected.log确认来源一致、performance timing=False、full pair=False；详细证据为build/clock145125-qualification.json。

失败构建位流SHA-256为1C0A7A5A9E65C6B154FBCCB07A7826A7C8335A6537945F053418922BF77C16D9，仅留作追溯，不作为通过时序的交付物。仍有SCBV未设警告；实际电气条件、实板、ILA、应用与稳定性验收不能由本次本地实验关闭。

## 复现与过程边界

build/audit_clock145125.py执行默认来源审计；--require-timing必须拒绝本次真实时序失败，--require-full必须拒绝缺少合格双实现与配对长测。build/test_clock145125_audit.py仅在内存中变异来源、资源、时序、周期、布局、固件和原始波形，不覆盖实验文件。

审计负控制完整运行3项、70.742秒通过：8个元数据反例、1个原始波形反例，以及真实失败时序和缺少完整配对的2个门槛全部按预期拒绝。日志为build/clock145125-audit-controls-corrected.log。当前所有构建、短测及审计会话均已结束，状态见build/clock145125-local-state.json。

准备脚本最初全部复制/验证成功，但包装器错误检查没有外部命令设置的LASTEXITCODE而报告失败；已为准备脚本添加显式exit 0，随后独立复核stage输入。没有重建或覆盖已有stage。负控制测试初次还出现测试夹具缺少根scripts搜索路径的导入错误，原始日志保留，修正只涉及测试入口。

后续优化应依据实际路径和三项指标进行，不盲目重跑此失败频点，不关闭性能计数器凑时序，不混用旧板测分数与新布局面积。没有进行Git提交、推送或远程板卡操作。
