# 独立指令缓存容量

日期：2026-09-06。目标是保留大指令缓存的执行收益，缩小数据读出选择及请求接收关键路径；本记录不把短仿真当作正式CoreMark成绩。

后续实板更新：链接松弛后的同一8/2 KiB候选已在实验箱2完成120 MHz两次性能长测及一次验证长测，达到3.0129645923 CoreMark/MHz；见HARDWARE_120MHZ_TARGET.md。下文未达标判断仅针对当时关闭松弛或未上板的各项实验，不外推覆盖后续实板结果。

## 参数与兼容性

新增ICACHE_SET_BITS，默认0表示沿用CACHE_SET_BITS；非零时仅改变指令缓存索引位数。CACHE_SET_BITS仍控制数据缓存。各侧均为两路、每行4个32位字，容量为32×2^索引位数字节。没有修改Cache命中/缺失、替换、回填错误、写回、维护、MMIO与复位协议。

PowerShell入口run_pds.ps1、run_coremark_test.ps1、run_cached_tests.ps1、run_soc_tests.ps1和run_isa_tests.ps1新增-ICacheSetBits 0..8。PDS和CoreMark运行清单保存实际指令索引位数；ISA矩阵清单记录覆盖参数，因为同一矩阵包含不同数据容量。省略选项的旧命令行为不变。

配置字[11:8]保存数据索引位数，[15:12]保存不同于数据侧的指令索引位数；0兼容历史对称编码。显式相等的两侧也编码为0。I=8 KiB/D=2 KiB快速256项配置为0e8e86f9，I=8 KiB/D=4 KiB为0e8e87f9；旁路保留几何描述但不表示缓存启用。解析器显示icache_set_bits/dcache_set_bits并拒绝非法或不匹配字段。旧ILA网表映射拒绝非对称容量，不套用旧探针图。

compare_coremark.py新增ICacheSetBits与CacheSetBits容量变量，要求另一侧实际容量、其他参数、固件及已核验源码一致；旧清单缺少ICacheSetBits时继承CacheSetBits。仍要求120 MHz等目标时序通过、性能种子CRC正确、至少10秒，不能用于以下短测宣称正式收益。

## 测试脚本纠错

发现run_cached_tests.ps1中fastData先由FastDCacheRead赋值，又被FastDCacheWrite重复覆盖。本轮移除重复赋值，并加入test_cached_run_contract.ps1：从实际脚本AST提取赋值及编译命令，在不调用WSL的替身中检查全部读写开关组合和容量参数，并拒绝四种错误脚本，共12项检查。

该问题只影响这一个CPU差分入口中读写开关不同的组合，不能把旧日志名称当作当时真实读模式；两开关同为1的候选、直接模块测试，以及独立的CoreMark、SoC和ISA入口不因此失效。修复后的全部原有回归与独立读/写模式重新执行，不能追溯声称旧覆盖完整。
