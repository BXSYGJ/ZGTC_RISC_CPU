# 数据缓存同步读与写回预取

日期：2026-09-07。本轮在固定680F缓存和通用H1/C2预测器上，尝试消除数据RAM异步读选择网络；不采用上一轮时序失败的标签流水化，不增加load-use气泡，不改变生产输入，不上传GitHub。

## 修改的电路

READ_ONLY=0的数据存储拆成两路同步读数组。接收请求的同一边沿启动两路读取，下一LOOKUP拍依旧输出命中字；逐路记录读写同址旁路，保持同字重叠写/读及末拍回填后立即命中的行为。写命中和回填写入合并成每路一个写入口，字节合并仍使用旧字和strobe掩码。

写回和CPU查找复用读口：WB_CMD预取被替换行的第0字；WB_DATA仅在当前拍真正握手且非末拍时预读下一字，背压时保持当前字。脏行刷新也使用同一路径。存储数组及数据输出不复位，写使能和旁路有效标志保留异步复位保护；未使用no_rw_check，也未增加告警豁免。

- 固定参考：experiments/cache_tag_pipeline/baseline.sv，SHA-256 680F03DF60A726DAB321904A2F72FF2C2A94B9E7D7D5D20842B4492B1CDC57F5。

## 首拍错误及修复

初版只在WB_DATA前进读地址，没有在WB_CMD强制第0字。正常替换会先清零beat，但FLUSH_SCAN转WB_CMD可能保留上一次回填的末拍beat；因此第一次刷新写回会预取错误字。逐周期参考比较在16个可写基础模式中捕获写回载荷不一致。

初版完整保存在initial_writeback_rejected.sv，SHA-256 433F378C44DA80B2F2A16FA1F18CAC5B5FD2ACD9039C0C7914608CFCCF29D81C。修复WB_CMD预取地址后，所有正例再运行通过，并将该错误保留为独立负例。初版在正例失败时得到的变异拒绝不计作最终有效性证据。

## 验证范围

scripts/test_cache_synchronous_writable.py完成4个测试方法：

- 32种基础组合：16/32位地址、只读/读写、快读、快写和重叠开关。
- 16种只读实际容量组合：64/256组，16/32位地址，快读和重叠开关；每组额外运行固定参考。
- 32种可写实际容量组合：64/256组，16/32位地址，快读、快写和重叠开关；每组额外运行固定参考。
- 共80种候选正例、48次独立参考驱动，均以4字缓存行为前提。每周期比较控制、有效响应、有效后端命令、写回载荷、计数器、状态及valid/dirty/LRU。
- 13个编译成功、功能断言拒绝的错误注入：读索引、两路旁路、写回选路/首拍/前进/背压、写路选择、字节合并、旁路载荷及读取使能；不把编译失败或只有覆盖率失败算作拒绝。

新增实际容量可写驱动检查：两路脏行替换、失败写回不提交年轻写、失败刷新后的保留与重试、所有16种字节使能、512笔全64 KiB地址随机读写、读错误、早/晚last、未对齐/越界请求及零字节写。三次刷新后逐字比较全部16384个后端字。旁路两路、写碰撞、写回首拍、握手拍和背压拍均有强制非零覆盖；旧驱动默认行为保持。

完整非对称CPU/SoC/独立参考/旁路/独立提前读写及严格板级lint通过；196次外部ISA与8个拒绝通过并独立核验，不等于完整ISA认证。原有同步只读、标签流水化、ready载荷、请求捕获测试均通过，validate.ps1语法与UTF8 BOM通过。

## 执行拍数与原生RAM

相同132 MHz、10轮性能/验证固件的两次短测为3251073/3258866周期，退休2748941/2749614；完整UART与通用H1参考逐字节相同。固件及18份编译输入独立核验，只有Cache不同；这不是正式CoreMark分数。

原生综合网表中，数据缓存模块GTP_RAM64X1DP从536降到24，数据部分的512个LUTRAM实例消失，剩余用于标签。两路256×32存储被合并为一份256×64、独立字节使能的GTP_DRM36K_E1简单双口RAM。此处是原生结构证据；最终LUT分母仍取布局布线报告，不能直接把原语差值当作LUT节省。
