# 无 Cache 基线：实现与边界

`rv32_memory_system.ENABLE_CACHE=0` 在 elaboration 时移除两路 Cache，换成 `rv32_uncached` 单请求桥。它不是把 Cache 容量缩小，也不在后台保留命中路径。两路桥仍共享原轮转仲裁器和同一个同步片上 RAM，MMIO 路径不变。

## 协议

- 每次普通读产生一条长度为 0 的单拍 burst 命令；重复读取同地址仍重新访问后端。
- 整字写只发写命令、单拍数据，并等待写应答后才向 CPU 应答。
- 原 burst ABI 没有 byte strobe；部分字节写必须先读整字，再按 strobe 合并后写回。读错误时禁止后续写，零 strobe 不访问内存。
- 此读改写不是多主写入的原子操作。当前另一路是只读取指、没有 DMA/其他写主机，故适用于本项目；未来增加其他写主机时必须扩充 byte-strobe ABI 或提供跨读写锁定。不能将它冒称 RISC-V A 扩展。
- 响应和命令在反压期间保持；读协议出现多余数据拍时排空至 last 并返回错误；无 last 的坏后端不保证自行恢复。
- flush 等待已接受访问完成，不产生写回。原系统按先 D 后 I 的维护序列握手，CPU 仍执行 FENCE.I 前端排空。
- 命中、缺失、写回计数全为 0，表示 Cache 被关闭，不是 100% 命中，也不是零内存访问。消融报告必须另外标出配置。

部分写读改写的开销必须出现在消融解释里：比较的是本项目现有 burst ABI 上的完整有/无 Cache 系统，不是所有可能的最优无 Cache 架构。

## 已完成验证

`run_tests.ps1` 包含读写桥 5105 项检查和只读桥 3652 项检查，覆盖全部16种 strobe、256次随机写读、请求锁存、命令/数据/响应反压、读写错误、非法对齐、只读写入拒绝、多余读拍排空、flush 优先级及全部内存比较。严格 Verilator lint 通过。

`run_cached_tests.ps1 -Uncached` 使用同一 CPU 自检镜像，预测关闭/开启两组均通过独立指令模型和全部 16 KiB RAM 比较：各794个退休事件、13个异常，周期分别5767和5641。这不是 CoreMark，更不能按此短指令序列外推正式性能。该组合已加入 `validate.ps1`。

开关已接入 memory_system、SoC、板级和 PDS 模板；`run_soc_tests.ps1`、`run_coremark_test.ps1`、`run_pds.ps1` 使用 `-CacheEnabled 0` 关闭，默认 1 保持原 Cache。配置 MMIO bit1=1 标记旁路，五项 Cache 计数必须为0。裸机自检按实际配置验证快照，无 Cache 的 UART/三种中断/维护故障封锁测试均通过；完整回归及两种板级严格 lint 通过。
