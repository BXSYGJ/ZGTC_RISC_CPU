# 缓存入口错误分类寄存重排候选

## 目标和改动范围

父方案有效位分组已把最差端点移到D-cache的rsp_error，但146.25 MHz仍差0.036 ns。该路径从缓存返回数据bit1，经地址字节进位及高位范围检查到错误寄存器。本候选不降低时钟要求，也不删除非法地址检查，而是把入口错误分类移到请求寄存器之后。

候选为experiments/cache_error_retime/rv32_cache.sv，SHA256为984B45FECD7D5AFF9410638DD0234649F2BCB99198EC2933C761B7D6FD5C4343；隔离工程为build/cache-error-retime-stage。20份物理输入仅该cache文件改变；字节进位核心、有效位分组、原memory_system、146.25 MHz PLL、固定固件与工具参数保持不变。父方案是失败参考，不授予任何物理资格；生产RTL不替换。

## 周期和错误语义

入口接受请求时，stored_state统一进入LOOKUP，同时寄存地址越界位、低两位对齐信息，并用request_check_pending记录这一次接受。原request_address仍保留原来的截断和ready窗口采样行为。

接受后的周期，由寄存的错误位及只读写请求生成request_input_error；无错时有效state仍是LOOKUP，有错时有效state组合地呈现RESPONSE，rsp_error立即为1、rsp_data为0。因此错误请求仍在接受后第一周期响应，并不多等一拍。所有存储写入、LRU、命中/缺失统计和后端命令仍使用有效state，错误请求不会先进入正常LOOKUP而产生副作用。

下一时钟沿把错误状态保存到stored_rsp_error；如果响应尚未接受，stored_state显式保持RESPONSE。这样一次性的request_check_pending清除后，错误响应仍保持稳定。若已接受，返回IDLE，保留原来的闲时错误电平。若同沿overlap接受后继请求，底部原有接受优先级清除旧错误，新的检查信息取代旧信息。有效state是语义状态，stored_state是实现内部状态；测试比较前者和全部外部握手/副作用，不要求不同实现的内部寄存编码相同。

此解释是结构推理；是否改善时序必须等待实际PDS，不能由寄存器位置推断已通过。

## 物理资格和未完成项

实际PDS构建20260908-104835-8439a5fa已经结束，PG2L200H-6FBB676、146.25 MHz、种子1、RemoteLab UART 115200，使用同一6000轮性能固件。原生网表确认request_check_pending与request_error_address；20份源、顶层、完整Tcl、种子和固件绑定审计通过，但实际时序失败：8989 LUT、5170 FF、WNS -0.194 ns、14个setup失败端点。未生成通过manifest，没有执行完整计分，不产生本候选完整分数。物理审计2项方法29.535秒、4类拒绝控制通过，包含缺失原生有效位分组、缺失错误检查寄存状态、错误PLL反馈比、解析与元数据一致但错误的时钟周期。

与相同种子的父方案8771 LUT、5132 FF、-0.036 ns相比，增加218 LUT和38 FF，裕量反而下降0.158 ns，不能作为优化采用。最差路径从D-cache返回bit23经过字节符号扩展、地址高字节计算、effective_address bit31及MMIO/RAM分类，再进入缓存stored_state寄存器使能；逻辑3.320 ns、布线3.276 ns。说明仅移走入口范围检查，仍未切断“返回数据→新地址→路由分类→请求控制”的完整组合路径。

后续需要从路由请求控制边界继续分析，任何提前接受或错误响应丢弃方案都必须先证明MMIO无重复副作用、非法请求不触发后端RAM、响应归属/背压和零等待响应等边界，再考虑实际PDS。这里仅记录下一实验方向，未实现或赋予资格。
