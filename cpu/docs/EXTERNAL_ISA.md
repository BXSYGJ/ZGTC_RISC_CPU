# 外部 RV32UI 指令测试

本工程已运行 RISC-V 上游 `riscv-tests` 的 RV32UI 测试程序，不只依靠项目自己的汇编自检。41 个上游测试在四种 CPU/存储配置中通过，共 164 次成功运行；另有四个明确失败的负向控制。这里的“通过”是该固定测试集在本项目适配环境中的仿真结果，不是 RISC-V 官方认证，也不等同于完整架构合规测试。

## 来源与可复现入口

上游仓库为 `riscv-software-src/riscv-tests`，固定提交 `2ebecad997fa58cd9e5724340ba75aa4b59bd1d0`。Codeload 归档 SHA-256 为 `1B6BBCA3A60B81FD3B94FA5DB6497D48918944C80C74E5BCF39BBD5DDC63C483`。脚本只使用这一归档，哈希不符直接失败；每次重新解包到独立构建目录，不信任曾被编辑的旧解包目录。

```powershell
pwsh -NoProfile -File cpu/scripts/run_isa_tests.ps1
```

需要先按 `TOOLCHAIN.md` 构建真实 RV32 GNU 工具链。原始上游源文件和 `test_macros.h` 不修改，许可保留在解包目录。测试清单直接读取固定上游 `isa/rv32ui/Makefrag`，不手写一个更小的“全通过”子集。新源码仅为本地执行环境 `sim/isa/riscv_test.h`、链接布局、testbench、执行脚本及负向控制。

首次完整运行目录为 `build/isa/20260906-080801-c6ae08d8/`。此后每次运行使用新目录；`build/isa-latest.json` 仅在整轮通过后更新为新结果位置。`run.json` 保存提交、归档、工具链身份，`results.json` 保存清单、逐测试结果及输入文件 SHA-256；各测试另存编译/反汇编、符号表、UART无关的仿真日志、退休 trace，以及 Cache 清理后的完整 64 KiB RAM 内容。日志中的周期是 RTL 仿真周期，不是实板主频或 CoreMark 成绩。

## 适配边界与失败检测

- CPU 只有 M-mode；这些用户级整数指令程序仍在 M-mode 执行。环境只设置陷阱向量、关闭中断、提供起始地址和成功/失败邮箱，不模拟不存在的 U/S 模式或虚拟内存。
- 成功需要上游检查程序写正确邮箱值，且没有任何陷阱，最后 Cache 维护成功。主机还检查模拟器正常退出、唯一的 PASS 行及配置身份。仿真有 200000 周期 watchdog，主机进程另有 120 秒超时。
- `ma_data` 要求未对齐访存透明成功，而本 CPU 对未对齐半字/字访问产生精确异常。因此它不算通过项，清单显式列为不适用；实际执行它得到预期的 load-address-misaligned 异常（cause=4），并作为第四个拒绝控制保存原始失败日志。不能把这个结果称为 `ma_data` 通过。
- 另外三项负向控制分别验证：`RVTEST_FAIL` 的 testnum=99 被拒绝，非法指令 cause=2 被拒绝，无限循环因 watchdog 被拒绝。这些是测试框架有效性检查，不计入 164 次上游通过数。
- 本轮使用上游自检查结果，不声称已与 Spike/Sail 做完整 signature 比对。项目原有独立 Python 指令/异常/内存差分回归仍保留，二者互补。M-mode 异常和中断由原有定向及 SoC 测试覆盖，不以本轮 RV32UI 结果替代。

该轮未改变 CPU RTL 或已经上板的固件，不能据此新增硬件运行次数，也不替代长期稳定性及最高工作频率测试。
