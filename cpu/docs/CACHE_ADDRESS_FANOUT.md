# Cache地址寄存器扇出限制

## 范围

当前候选在除法操作数预采样、132 MHz PLL分支基础上，只把rv32_cache.sv中的request_address声明拆开并添加Verilog-2001属性syn_maxfan=64。req_ready/rsp_valid、请求采样边沿、Cache读写/替换/刷新状态机和CPU流水停顿逻辑均未改变。不增加流水级，也不声称执行效率提高。

缓存候选SHA-256：AC24EDFB561B454437519B452E5F6F90AA4C7DC538400D919919BC011877D633。去掉属性并合并声明后与D5D6D3C2FDC5A877F04A664A46F38DBFB0CEC6DFB53F59E0C2941A15A253D757基线逐字节相同。M单元仍AA1BF3E9AC51E8179B9C52B7ADA90DE816B219AC7263D7FB973A9289D5164C79，PLL仍B1AD88A943CBEC1AF172560D7B22919E298A64FF1D033F19F7A27D23B1BD7CBB。

## 原厂依据与实际生效

原厂ADS_Synthesis_User_Guide.pdf第52页支持Verilog-2001属性语法；第87–88页说明syn_maxfan用于net/register等对象，允许工具复制逻辑来减少扇出。该属性不是RTL仿真加速开关；必须检查实际综合网表，不能因源码中有属性就宣称生效。

132 MHz综合网表确实出现PAP_MAX_FANOUT=64、PAP_PRESERVE="TRUE"及request_address_1_copy寄存器。新增audit_cache_address_fanout.py读取原生GTP_DFF_CE结构，按同一地址位核验副本D/CE/CLK/C及初始化参数一致、Q不重复驱动，并统计直接命名引脚连接次数。它不宣称完成一般Verilog解析、形式等价或布局后扇出证明。

| 原生缓存模块 | 地址FF数量：基线→候选 | 最大直接负载引脚次数：基线→候选 |
| --- | ---: | ---: |
| rv32_cache | 14→153 | 1325→64 |
| rv32_cache_1 | 14→62 | 341→64 |

两模块地址FF共增加187个，其中36个D恒为0的地址位被保留。工具的复制不是免费收益；属性作用于整个32位request_address时，也保留了原本可以消除的位。最终资源代价以布局报告为准，不能只报减少的LUT而隐去FF增加。审计原文为build/cache-address-maxfan64-native-audit.json。

test_cache_address_fanout.py共5个测试方法，覆盖实际连接计数、名称子串误计数、D/CE/CLK/C/INIT错误、重复Q和重复端口、属性缺失/错误、没有复制以及超过64的直接引脚计数。最后一种如实报告超额，而不是把属性值当作测量结果；Windows和WSL运行均通过。已接入后续validate入口，本次完整回归启动时尚未包含这项新增调用，因此本次以完整回归加单独审计测试共同记录。
