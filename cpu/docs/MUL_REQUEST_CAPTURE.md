## 先保留失败证据

尝试一：关闭 LoadUseBubble，使用响应当拍的加载结果直接前递。旧乘法器下，性能短跑383478周期、验证383408周期，CRC通过；但构建 `20260906-161540-f0f6d11e` 在120 MHz失败，WNS -1.814 ns、7639 LUT、4260 FF。最差路径经过缓存标签/数据选择、加载提取、forwarded_a、effective_address、MMIO快照寄存器使能。未降低频率、添加假路径或用短跑结果冒充可实现成绩。

尝试二：把原32×32乘积寄存器直接接到请求操作数，并提前到请求接受沿计算。功能测试通过，短跑393604周期；但 `20260906-162307-e2202e5e` 的WNS为 -1.640 ns，6974 LUT、4234 FF。最差路径从MEM目的寄存器比较、操作数前递经过四个级联APM乘加节点。减少LUT不代表满足120 MHz，此位流同样拒绝。

并行方案首次使用 `32'(expression)` 显式尺寸转换，Icarus/Verilator接受，但PDS构建 `20260906-163228-732ee558` 报 Verilog-4005、Syntax error near apostrophe，未进入有效实现。最终改为32位目标寄存器的上下文定宽，不屏蔽警告或修改原厂工具；严格lint和算术正负测试重新通过。

## 最终电路

原设计先锁存32位操作数，下一拍经过32×32级联乘法计算，再在PRODUCT状态响应。本轮将输入拆成低16位与带符号扩展的高半字，在接受请求的同一上升沿锁存四份并行半字乘积；PRODUCT阶段组合这些寄存结果。每条输入到乘积寄存器的路径不再跨四级APM级联。

令 B=2^16，A=A_low+A_high×B、C=C_low+C_high×B：

- low_low=A_low×C_low；两个低半字均按无符号解释。
- low_high=A_low×C_high，high_low=A_high×C_low，high_high=A_high×C_high。高半字根据MULH/MULHSU/MULHU的有符号要求扩展为17位；MUL取无符号拆分，其低32位与有符号乘积一致。
- middle=low_high+high_low+floor(low_low/B)，使用有符号35位中间值保留进位与负数。
- 低32位由 middle[15:0] 与 low_low[15:0] 拼接；高32位为 high_high+算术右移middle的16位，结果按32位取模。
- 不再在乘积之后串行减去两个32位操作数做符号校正；符号已经包含在半字乘积内。

MUL/MULHU在接受沿之后的周期即提供有效响应，不是无寄存器的组合直通；相对旧设计少等一拍。MULH/MULHSU仍经响应寄存器再多一拍，除法状态机和除零/溢出规则不变。四份乘积仅在IDLE更新，忙碌和响应背压期间保持；cancel立即抑制握手并丢弃该事务，恢复后必须重新接受请求。

## 剩余目标

本轮没有下载新位流或采集实板长时运行，120 MHz达到3.0 CoreMark/MHz的硬目标仍未完成；既有已确认实板成绩不变。新设计ILA映射、GPIO独立输入、SCBV和IO电气约束仍需验收。All Constraints Met仅覆盖已设约束，不自动补齐这些缺口。

后续优先评估缓存标签比较和访存前递关键路径；任何地址宽度简化都必须保留越界访问错误，不能通过直接截掉高地址位制造缓存别名。
