# 有界BTB地址存储与容量复测

2026-09-06。承接CACHE_ADDRESS_BOUNDS.md的120 MHz直接加载前递候选。硬门槛仍是120 MHz下3.0 CoreMark/MHz；本文不把短仿真当作正式成绩，也不把有限容量筛选称为三指标物理极限。

## 地址范围与架构边界

rv32_btb新增ADDRESS_BITS，单位为字节地址位数，通用默认32位。rv32_core通过BTB_ADDRESS_BITS传入；rv32_soc绑定MEMORY_ADDRESS_BITS+2，当前64 KiB可执行后端对应16位字节地址。有效参数须满足INDEX_BITS+2 < ADDRESS_BITS <= 32。

- PC标签为ADDRESS_BITS-INDEX_BITS-2位；64项表由24位缩至8位，256项表由22位缩至6位。
- 跳转目标只存ADDRESS_BITS-2位对齐字地址，当前为14位，输出显式补高位零和低位00。旧目标的低两位本来就恒零，不能将源码少掉的每一位都算成实际面积收益。
- 取指地址在完整32位上检查高位和对齐，再允许命中；范围外预测缺失仍输出完整PC+4，保留32位回绕。
- 更新PC或更新目标有越界/未对齐时，不分配、不覆盖现有表项。不能只截断高位，否则不同地址会错误共用预测记录。
- 分支方向计数器、索引冲突替换、失效优先级不变。地址边界只限定预测表可存范围，不替代CPU实际跳转目标计算或取指访问错误检查。即使已有旧目标，EX仍按原逻辑重定向和精确报告异常。
- FENCE.I和复位仍清空有效位；最终类型存储修订不要求清空无效表项的数据，详见下节。没有增加流水拍、放宽时钟或添加假路径。
- 配置字不新增位，容量编码沿用BTB_CAPACITY.md；必须用源码快照区分内部修订，不能从旧配置字追认本次压缩。

## 类型位存储修订

仅压缩地址范围不能保证后布局面积减少：64项构建20260906-175817-bad1046a为7080 LUT、4147 FF、WNS +0.192 ns；相对上一轮7007 LUT增加73，周期仍374184。256项同源码构建20260906-175842-02e92e22为7702 LUT、4516 FF、WNS +0.181 ns，短跑363290周期；与64项相比工作率/LUT代理指标反而下降5.31929%。两份20输入快照、位流和固件实际SHA-256均已核验。不能将这一步描述为已实现面积改善。

进一步检查发现conditional类型数组有不必要的异步复位和逐位更新。最终改为不复位的数据数组，以允许工具推断分布式存储；有效位仍异步复位。无效记录不能命中，首次分配一定重写类型、标签、目标和方向计数器，因此不依赖类型数据上电为零。复位/失效优先级和方向预测行为保持不变。

最终64项性能实现20260906-180842-b1af7ce5通过120 MHz：6935 LUT、4080 FF、WNS +0.141 ns。相对上一轮响应保持候选7007 LUT、4146 FF、WNS +0.076 ns，周期不变，LUT减少1.02754%、FF减少1.59190%、同频短跑工作率/LUT代理指标提高1.03821%；不是执行周期改善。相对仅有界地址中间版本减少145 LUT和67 FF，但WNS从+0.192减为+0.141 ns，不能省略此权衡。

128项最终类型存储候选性能短跑366605周期/276244条（20260906-181715-131750c8），验证366655/276457（20260906-181756-4b47bbf7），CRC及实际固件SHA-256均通过。然而独立120 MHz构建20260906-181644-c6ba6ce5为7029 LUT、4133 FF、WNS -0.185 ns，被拒绝；脚本据此停止，没有生成该候选的验证种子合格实现。不能把其短跑周期和面积拼成已达120 MHz的效率成绩。

本轮保留64项最终类型存储版本作为新的面积优化候选；并保留中间256项的已通过时序快照作为不同面积/执行效率权衡，而非把失败的最终256项覆盖成通过。后续应从实际失败路径继续缩短缓存到核心的组合控制链，或开展有对应时序/面积证据的非对称Cache实验，而不是只继续增加表项并宣称达到物理极限。
