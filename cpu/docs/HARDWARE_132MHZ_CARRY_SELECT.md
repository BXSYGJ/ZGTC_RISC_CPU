# 132 MHz折叠BTB与分段ALU实板复测

## 结论与三指标

实验箱2 / PG2L200H完成性能6000轮、验证6000轮、重新烧录后的性能6000轮。两次性能UART逐字节一致；两次独立check_frequency_candidate均通过132000000 Hz、至少3.0 CoreMark/MHz、至少0.031 CoreMark/LUT、CRC与至少10秒门槛。该结论绑定本页的源码、固件和位流，不替代后续修改后的验证。

| 指标 | 上一已测132 MHz | 本次132 MHz | 变化 |
| --- | ---: | ---: | ---: |
| 执行效率 / CoreMark/MHz | 3.0129694974344834 | 3.02972052980729 | +0.5559642% |
| 吞吐 / CoreMark | 397.7119736613518 | 399.9231099345622 | +0.5559642% |
| 资源效率 / CoreMark/LUT | 0.03863531898789118 | 0.038628717273694796 | -0.0170873% |
| 布局后LUT | 10294 | 10353 | +59 |
| 布局后FF | 5041 | 5023 | -18 |
| APM | 4 | 4 | 不变 |
| setup WNS / ns | +0.001 | +0.103 | +0.102 |

主频不变，执行效率提高，资源效率微降但仍高于0.031。不能称三个指标全部改善；旧版本仍保留作为面积/效率折衷。性能周期减少11010208（0.5528903%），退休指令不变。对比使用同一性能固件、相同频率和6000轮，但ALU、BTB、M单元三个RTL文件改变，不冒充单变量实验。分段ALU本身在同源短测中不改变周期；折叠BTB筛选与M载荷时序实验分别见BTB_FOLDED_INDEX.md、DIVIDER_ZERO_PAYLOAD.md。

独立Chrome端口19506通过页面预约20分钟，确认实验箱2/PG2L200H；未改动原19474浏览器。新串口页最初未获取设备是初始化瞬态，等待状态更新后才操作，没有重复预约。三次烧录前核验实际位流SHA-256，均取得“固件下载完成且设备已唤醒！”页面终态。每次重新烧录、打开串口、连续三次空读后，发送一次新的G加换行。实际服务deviceId=7仅记录为内部标识，不据此推断箱号。

记录来自实际serial-port/read响应，接收时预分配顺序槽、等待异步正文解析完成，逐包核对hex长度、bytesRead与UTF-8 data，再按原顺序拼接；不修剪、去重、重排或合成结果。每份UART均由对应总会话区间独立重建并与落盘文件逐字节一致。计分区前读取保留在总会话，不将其混入计分文件。无串口采集异常，三个实际发送请求与三次烧录、三个独立区间一一对应。
