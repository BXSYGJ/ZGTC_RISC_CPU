# EX提前分支恢复：功能通过，但148.5 MHz时序拒绝

## 目的与电路

该候选旨在减少错误预测后的恢复周期，而不是只增加时钟。规范核心experiments/early_branch_redirect/rv32_core.sv的SHA-256为40A6F85019055DAE2AA8A8763E9425FA21DB49AB6533B1968844689EDA8DB5FE，隔离工程为build/early-branch-redirect-stage。父工程是完整配对的148.5 MHz carry16版本；20项物理输入只改核心，其余19项相同。生产RTL没有替换，本轮未提交或上传GitHub。

原核心在MEM阶段发现实际下一PC与预测PC不一致后恢复前端。候选在EX指令能够推进、确定无异常且确为条件分支/JAL/JALR时，提前比较下一PC并清除年轻指令。新增mem_early_redirect状态只抑制同一分支下一拍重复恢复；原始mem_prediction仍保存，MEM阶段仍处理精确异常、MRET、FENCE.I以及预测器训练。旧MEM异常优先于EX，未完成的取指响应仍排空，不取消已接受的总线事务。

- 9个真实编译运行的错误变体均被拒绝，包括忽略EX推进/异常门槛、误恢复非分支、MEM重复恢复、旧异常目标错误、年轻译码未清除、丢失提前状态、错误取指重叠、丢失排空标记。
- 六次预测器开关/随机总线延迟CPU运行通过独立退休轨迹与内存参考；14项精确M中断/取消通过。八种严格板级lint通过，没有添加警告豁免。
- 实际I9/D6缓存CPU两种预测配置6469/6360周期，均13次陷阱，零/正/负偏移加载旁路与独立参考通过。
- RV32UI 20260908-072943-7d3df208完成164次，RV32UM 20260908-073247-268e629b完成32次，另8个拒绝控制。来源审计逐份校验16份RTL、适配器、固定上游、固件与原始日志；不是完整ISA认证。

Icarus仍不处理声明赋值上的syn_keep属性，且提示原有cache generate写法；这些仿真警告未用于宣称物理属性已经验证。

## ISA退休数差异：保留失败并核实原因

首次完整功能来源审计early-branch-redirect-functional-audit.log拒绝了“除周期外退休数必须完全相同”的旧假设，未直接放行。定位发现23个ISA配置多退休1或2条指令，全部出现在成功之后的自跳转循环。

实际isa_tb在成功MMIO写入之后继续等待16周期，再请求最终缓存刷新；程序RVTEST_PASS写0x10000000=1后执行j自身。因此提早恢复可能改变结束前空转次数。对196个实际用例逐一检查：成功前的完整退休轨迹前缀逐行相同，最后三条确实设置成功邮箱地址/数据并执行存储；允许变化的后缀必须仅为同一PC处的JAL x0,0；原始轨迹长度必须等于各自报告退休数，退休差必须完全由该后缀解释。最终内存文件也逐字节相同。

新核验器scripts/early_redirect_isa_trace.py不忽略任意退休差异，也没有修改ISA程序或原适配器。七项测试0.011秒通过，拒绝真实工作、空转PC、成功邮箱、存储、报告计数与最终内存的篡改。修订后early-branch-redirect-functional-audit-terminal-qualified.log通过；原失败日志保留。

GPIO与UART两种固定固件的正常/故障4对8次SoC运行也通过原断言及外部结果比较：正常保持74项检查、完整23字节UART、软件/定时/外部中断各1次，故障保持41项检查。候选正常周期8226/8221、故障4402/4707；正常退休4614/4732，与父工程4611/4724不相同。这组带中断的SoC轨迹不宣称逐周期或逐条退休等价；检查范围是原功能断言和相同外部结果。

候选位流SHA-256为346818A220696982C445D433BBCC68F406926B46F99483E56F175D7C1AF190DD。build/audit_early_branch_redirect_physical.py独立核验20份捕获/当前源、同频父固件、生成顶层、真实布局命令、原生PLL与原始时序，确认没有合格manifest；--require-timing明确拒绝。没有恢复元数据来伪称通过，也没有重跑或更改该失败实现。

最差路径从D-cache同步数据存储器输出，经加载数据拼接/旁路、branch_operand_b、条件比较、branch_taken、actual_next与预测PC比较，再进入前端/I-cache状态使能。提前恢复把原来跨级的加载返回数据与取指控制连接到同一长组合路径，是下一步必须切断的数据依赖。104.4386 MHz只是该失败实现的PDS估计，不是另一个频点已通过的证明。

该候选没有自己的配对6000轮、合格时序或实板成绩，不能把短测效率乘148.5 MHz，也不能拿父版本分数除8656 LUT来声称资源效率改进。

## 下一步与未完成项

优先评估将提前判定与加载返回旁路结构性分离：涉及待返回加载值的分支继续保留正确的MEM恢复路径，能够仅由已寄存操作数确定的控制流再尝试提前恢复；需要新的独立候选和相同强度验证，不在冻结失败工程上覆盖修改。该改进现已作为独立候选实现，并完成直接/加载回退/精确错误、ISA、SoC及双短测功能验证；详见EARLY_DIRECT_REDIRECT.md。新候选实际PDS为8798 LUT、5120 FF、WNS -0.176 ns，仍被148.5 MHz时序门槛拒绝；最差路径转为返回加载值到高地址/MMIO及D-cache控制，尚不采用。

148.5 MHz carry16完整版本仍保留为已验证本地成绩；新版实板、ILA、独立GPIO输入、电气/SCBV、应用/稳定性和三指标继续优化仍未关闭。不把有限实验当作物理极限证明。
