## 初始串口缓存边界

首次打开串口显示了前一会话的162 MHz验证输出及实验箱3之前的RV32I PASS缓存，未观察到本次首次READY。原文保存在 `coremark-box3-f180-precommand-session.txt`，**不作为180 MHz通过记录**。等待后清除旧日志，再发送新的G；取得唯一完整START至FINISHED、180 MHz/当前配置、对应CRC的响应，才纳入首轮结果。后四次重烧均观察到180 MHz READY，清除旧内容后再发送命令。

每个`-session.txt`保留发送回显47；`.uart`只去掉START之前的发送回显，不修补字节、拼接多次运行或删除内部错误。对应文件前缀为 `coremark-box3-f180-loadbubble-`，后缀r1、r2、validation-r1、stress-r1、stress-r2。

## 优化收益与局限

- 相对箱5默认162 MHz/4751 LUT基线，主性能增加11.1008%，CoreMark/LUT增加7.7444%，布局后LUT增加3.1151%；每次迭代的周期仍微增0.00927%。收益来自可通过的更高时钟，不是load相关停顿减少。
- 相对箱5同为寄存前递的162 MHz，周期、退休数与Cache计数一致，分数按180/162提高11.1111%。这是跨板结果，不是同一块板上的单变量控制实验；主频为经过PLL/约束和固件匹配检查的配置值，没有独立频率计测量。
- 默认180 MHz WNS=-0.086 ns，194.4 MHz两模式均违反约束，均未下载。180 MHz为当前已上板并满足所施加时序约束的最高测试点，不能称绝对Fmax。+0.085 ns余量较小，下一阶段需进一步分析关键路径和长期运行，不应改判负余量为通过。
- SCBV告警、电气网络证据和异步I/O约束边界仍按CONFIGURATION_ASSURANCE.md处理。成功运行不替代该审核，亦不关闭独立GPIO按键输入验收。

