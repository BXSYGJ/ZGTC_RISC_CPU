## 一行RTL变化与等价边界

规范源experiments/fetch_address_select/rv32_core.sv，SHA-256 5905ABC44DEEF053EEF8A8FE3BB5D4B35CE884EFE0190FA0FDD6B5308B4CEC51。独立工程build/fetch-address-select-stage，相对直接父工程20项物理输入只有CPU不同，缓存保持EE88049C2B8FB3F8BD94A8C42B184CBE3181269DC40DCDA49DFD8784E4C653B1。

原i_req_address=fetch_overlap ? next_pc : fetch_address，改为由寄存器fetch_sent选择，其他源码逐字保持。原选择信号依赖响应ready，而ready受到中断/前端背压影响；因此定时器比较和流水线控制经过地址选择器进入I-cache有效位预读路径。改用已经寄存的事务状态，不增加流水拍，也不修改i_req_valid、i_rsp_ready、中断、冲刷或维护条件。

只在有效请求阶段保证地址等价：fetch_sent为0时，i_rsp_ready必为0，所以fetch_overlap也为0；fetch_sent为1且i_req_valid为1时，请求有效条件要求fetch_overlap为1。因此i_req_valid为1时两个选择器相同，包括请求未被接收的背压阶段。

i_req_valid为0时地址可以不同，缓存的ready空闲预读也可能采样不同地址。不能声称逐周期全端口相同或全内部状态等价；需要验证有效事务、空闲预读后续行为和取消/排空过程。
