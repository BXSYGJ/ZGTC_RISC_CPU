# 整字加载地址候选的151.2 MHz目标实现

## 更新后的硬门槛

当前阶段必须同时达到CoreMark/MHz不少于3.18、CoreMark/LUT不少于0.052、实际通过频率不少于150 MHz，达标后只接受执行效率、资源效率均不下降的进一步升频。有限次实现不能证明物理极限，且本地RTL/PDS资格不等于实板资格。原有146.25 MHz候选虽达到前两项，但频率不足，不能算本阶段完成。

用户更新目标时，148.5 MHz试验仅创建了4份未执行的准备/运行/契约脚本，尚未建立隔离工程或启动物理构建；这些本轮新建脚本已撤去，不再沿低于150 MHz的目标继续消耗实现轮次。

## 实现来源

隔离工程为build/word-load-address-151200-stage，直接父工程为已经双种子完整合格的word-load-address-stage。CPU仍为734B1D48A89D4A60A32A24154593BBA0AC6D33F226959AA1BD50CCD158C93CFF，缓存、机器态、MMIO路由和其他硬件输入不变，20份物理输入中只有PLL改变。

新PLL为experiments/clock151200/rv32_pll.sv，SHA256为67677D07E5D35699AFA9C588B7D92DCB3D81DCBEC881CC4CB44D1060D360D0BF。保留已有频率配置，仅为151200000 Hz增加反馈分频14和输出分频5的选择；输入分频1、倍频参数2。名义输出27 × 2 × 14 / 5 = 151.2 MHz，PFD为27 MHz，VCO为756 MHz。参数范围依据本机原厂PDS PLL配置脚本核实，另用安装目录中的原厂GTP_GPLL仿真模型实测，不用更改报告标签假装升频。

原有build_coremark.ps1、run_pds.ps1、run_pll_tests.ps1和check_coremark.py各只明确增加151.2 MHz这一入口，其他白名单和拒绝规则不变。四份固件均重新以-DCPU_CLOCK_HZ=151200000u编译，两种10轮及两种6000轮分别有自己的HEX/ELF/二进制与来源元数据，不复用146.25 MHz固件进行重标。

## 已完成验证

- 23项Python频率/CRC/计数/时长检查0.044秒通过；原检查器仍拒绝151.2 MHz，新增检查器必须明确指定预期频率，不允许相邻或未列出频率，不给短测计分。
- 3份PowerShell脚本的UTF-8 BOM、语法、精确文本差异及8项参数绑定拒绝通过。
- 新目标采用整数交叉相乘判定，三个条件必须同时满足；6项门槛测试0.002秒通过，包含边界、非正/非整数输入及250组独立有理数对照。旧146.25 MHz结果被频率门槛明确拒绝，旧3.128执行效率也不能冒充新目标达成。
- 7个频率的原厂PLL模型频率/复位/重新锁定检查通过，包括151.2 MHz的200周期跨度1322.785716 ns，落在原台架容差内。模型跨度受参考时钟仿真量化影响，不能当作实板时钟测量。
- 独立输入审计核验19份不变输入和PLL、四份固件的实际时钟宏及元数据、ELF转二进制与填充HEX逐字节相等、移植源文件与CoreMark上游源文件未变。
- 双10轮构建20260908-135800-41cf20e5和20260908-135813-354baf2e通过，分别3151519/3156276周期；CRC正确，仍是短测，不产生本频率完整成绩。

## 实际物理验证

实际PDS构建20260908-135824-a3c22c88已经完成并被时序门禁拒绝：151.2 MHz、周期6.613 ns、8841 LUT、5178 FF、WNS -0.052 ns、TNS -0.172 ns，4个建立时间失败端点。原始报告给出的估计150.0375 MHz不能当作实际通过的150 MHz实现，也不能把151.2 MHz固件或报告重标为其他频率。

独立来源审计通过，确认只有PLL改变、四份新时钟固件真实、原生PLL参数和生成时钟边沿匹配，陷阱向量边界保持；6项审计方法111.252秒通过，11种来源/面积/时序/布局/固件/波形/原生选择器/PLL篡改被拒绝，实际时序和完整双种子门禁均正确拒绝。没有开展不合格频率的完整计分。

实际最差路径由timer_compare[5]经过64位比较、interrupt_pending、execute_common_exception和fetch_overlap到I-cache状态使能。后续timer-compare-split-stage保持3.181370版本CPU与151.2 MHz PLL不变，只将该64位定时比较拆为并行高低32位比较，不增加IRQ延迟；见TIMER_COMPARE_SPLIT.md。
