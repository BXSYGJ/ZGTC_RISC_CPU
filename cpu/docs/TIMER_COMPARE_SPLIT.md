# 定时器高低位并行比较候选

当前目标已提高到160 MHz，见FREQUENCY_TARGET_160.md；本文保留旧150 MHz阶段的过程与证据，不代表新版目标已完成。

## 目标与来源

继续以已经完整验证的3.181369716 CoreMark/MHz CPU为基础，当前必须同时达到≥3.18 CoreMark/MHz、≥0.052 CoreMark/LUT及≥150 MHz。达标以后，后续升频不能降低执行效率或资源效率。当前CPU核心仍为734B1D48A89D4A60A32A24154593BBA0AC6D33F226959AA1BD50CCD158C93CFF，没有退回3.128版本。

直接父工程word-load-address-151200-stage的实际151.2 MHz实现WNS -0.052 ns、4个失败端点，最差路径由timer_compare[5]经过64位比较、CPU中断/异常判断和取指重叠控制进入I-cache。其估计最高频率不是已通过的真实主频，因此本候选针对该实际路径，而非把标称频率下调或忽略约束。

新工程build/timer-compare-split-stage保持19份物理输入不变，唯一变化为rv32_peripherals.sv。父外设SHA256为412D393DD1FB9B5706AC7927F79CF8686C0115CA9754178BD75220A65E133F6E；新源experiments/timer_compare_split/rv32_peripherals.sv为8C46872D243E7AA61B379FED21D85893C45F5466B1E8CC04C8870D239AA83F75。PLL仍为已通过原厂模型的151.2 MHz版本67677D07E5D35699AFA9C588B7D92DCB3D81DCBEC881CC4CB44D1060D360D0BF。

## 电路改变

将timer_value >= timer_compare拆为：高32位大于，或者高32位相等且低32位大于等于。三个比较结果使用syn_keep保持边界，以缩短原64位串行进位比较链。对无符号64位值，这是按高位优先的恒等分解；没有新增寄存器，没有改变计数器加一、MMIO字节写入、计数回绕或IRQ采样周期。其余外设源码逐字相同。
