# 紫光同创选题一：RV32I处理器设计与性能分析

版本日期：2026-09-06。本文是当前工程的汇总分析报告，不是“全部比赛验收完成”的声明。依据原赛题PDF第10–11页（印刷页8–9）；仅高阶任务3的AI加速按用户要求暂缓。工程源码与历史已测位流分别标识，不宣称当前源码重建会与历史位流逐字节相同。

## 1. 设计目标与平台

目标为自研支持RV32I的流水线处理器，集成UART、GPIO、两路组相联I/D Cache、突发传输、动态预测与机器态异常/中断，运行CoreMark v1.0并实现CPU控制的波形采集应用。开发平台为PG2L200H-6FBB676，参考时钟27 MHz；WSL负责GNU软件编译、Icarus仿真与Verilator检查，Windows PDS负责ADS综合、布局布线、时序报告及位流。

默认基线及应用上板使用RemoteLab实验箱5；180 MHz寄存前递候选在确认PG2L200H及UART引脚后使用实验箱3。网站串口约束是RX AC26、TX AB26，与板载UART B24/C24不能混用。KEY0 C22、KEY1 C23；异步复位同步释放，UART和GPIO输入经过同步器。详细连接见 `PERIPHERALS.md`。

## 2. 微体系结构

取指请求通过单个在途事务与IF缓冲进入ID、EX、MEM、WB五级顺序流水线。ID译码并读取寄存器；EX进行算术、比较、地址生成；MEM发起访存并顺序提交异常或控制流更正；WB写回。x0固定为零。MEM/WB向EX前递，等待期间保存操作数；错误路径不允许提交存储或CSR写入。

分支预测器为16项直接映射BTB和两位饱和计数器，由MEM确认真实控制流。错误预测冲刷年轻指令；已接受的旧取指响应仍需完成后丢弃。FENCE.I先排空前端、完成D-cache写回和I/D失效，再清除预测状态，避免把自修改代码测试“通过”建立在仿真直接改指令信号上。

I-cache与D-cache均为2路、16组、每行4个32位字，即默认各512 B。SoC片上RAM为64 KiB；CPU早期独立差分测试使用16 KiB，二者不混淆。D-cache采用写回和写分配；填充错误不安装有效行，写回错误保留脏行。仲裁器以整笔突发锁定归属并轮转，MMIO经无缓存桥连接，非DDR后端。握手与错误约定见 `BUS.md`。

异常支持机器态CSR、非法指令、未对齐和访问错误、ECALL/EBREAK、MRET、mtvec直接/向量入口，以及软件/定时/外部中断。陷入时保存mepc/mcause/mtval，并阻止故障指令或年轻指令错误写回。未实现U/S态、MMU、PMP及M/A/C/F扩展；不能将本设计描述为完整所有特权级或所有可选扩展实现。WFI为可被中断唤醒的合法空操作，不含节能时钟门控。

## 3. 软件与验证方法

真正的 `riscv32-unknown-elf-gcc` 10.2.0与Binutils 2.35从固定GNU源码构建；不是将riscv64驱动改名。采用rv32i/ilp32、freestanding启动、链接脚本和libgcc软件运算例程。工具链安装、源码哈希与复建命令见 `TOOLCHAIN.md`。

验证分为单元、独立参考模型差分、集成SoC、外部ISA、PDS及真实板卡六层。`validate.ps1` 检查译码/ALU、CSR、中断优先级、Cache错误/背压、UART/FIFO、外设，逐条比对PC、指令、写回、陷入原因及最终16 KiB内存，并严格运行Verilator，不靠告警屏蔽通过。测试解析器还运行损坏、截断、重复、配置不符等负控。

固定上游RV32UI的41项测试在四种Cache/预测配置下共164次通过；默认和load寄存前递实验各有独立记录。另有四个预期拒绝控制，包括未对齐访问、非法指令、显式失败与看门狗。要求透明未对齐访问的ma_data被真实执行并按设计产生异常，不计为通过项。该覆盖不是官方ISA认证，也不代替所有CSR/中断场景的测试。

## 4. CoreMark测量规范与主结果

固定EEMBC提交 `1f483d5b8316753a742cbf5590caf5bd0a4e4777`；原算法源文件保持不变，自有移植位于 `sw/coremark`。2000 B静态数据集、单上下文、O2、无LTO/PGO，所有计分源文件使用同组编译选项。具体命令、CRC与门禁见 `COREMARK.md`。

串口等待命令与打印不在计时区。用64位mcycle差值计算时间，避免把原程序整数秒打印导致的粗粒度Iterations/Sec直接当精确分数。设N为迭代数、C为周期、f为实际Hz、L为本次布局后LUT，则：

- 时间：T=C/f；CoreMark=N/T。
- 赛题执行效率：CoreMark/MHz=N×10^6/C。
- 资源效率：CoreMark/LUT=N×f/(C×L)。L为布局CLMA LUT加CLMS LUT，不重复加分布式RAM。

当前默认162 MHz实现的1000次性能种子独立重烧录运行两次，结果一致：

| 周期 / 退休数 | 2729377421 / 752528394 |
| CoreMark | 59.3541951192 |
| CoreMark/MHz | 0.3663839205 |
| 布局后LUT / FF | 4751 / 3509 |

周期和退休数含读取例程的小额边界开销，CPI不冒充零开销逐算法统计。性能种子CRC为e9f5/e714/1fd7/8e3a/d340；验证种子另运行1000次，17.940915秒且CRC通过。4000次压力运行有一次完整67.764330秒通过，另一次串口采集损坏被明确拒绝，不能挑选片段拼成通过记录。108 MHz另有两次约101.65秒通过，仍不代表多小时或温度范围稳定性。

## 5. 消融与时序优化

更新后的最高已验证频点为180 MHz寄存前递候选，箱3独立重烧性能种子两次、验证种子一次、4000次持续运行两次均通过。1000次主性能65.9429948088 CoreMark、0.3663499712 CoreMark/MHz、0.0134605011 CoreMark/LUT，布局后4899 LUT/3531 FF，setup WNS +0.085 ns。两次持续运行各60.9935166278秒，结果一致；不称多小时稳定性。详细位流身份、初始旧串口缓存排除和五份全量记录见 `HARDWARE_180MHZ.md`。第4节保留默认162 MHz基线，默认RTL参数不因该实验自动改变。

27 MHz、同固件200次迭代的Cache开关各重复两次：开启549984604周期，旁路1014745239周期，周期减少45.8007%。同条件关闭预测器为655538964周期，开启减少16.1019%。不能从这些总周期反推BTB预测准确率；推测取指和计数器读取区间也使I-cache访问数不同于退休指令数。原始报告 `HARDWARE_CACHE_ABLATION.md`、`HARDWARE_PREDICTOR_ABLATION.md` 中历史LUT口径应按具体报告区分，不能与本报告布局后4751 LUT跨版本混算。

默认180/194.4/216/270 MHz及寄存前递194.4/216 MHz均有失败实现，故不采用这些失败位流。180 MHz寄存前递是当前已实测且满足所设约束的最高测试点，不是已经证明的绝对Fmax；工具报告估计值不当实板成绩。频率探索记录见 `PDS_FREQUENCY_SEARCH.md`、`PDS_FREQUENCY_REFINEMENT.md`。

load寄存前递实验在162 MHz同频时性能59.348695，布局后4808 LUT；相对默认周期增加0.00927%，LUT增加1.19975%，同频负收益仍保留。180 MHz候选相对默认162 MHz吞吐提高11.1008%、CoreMark/LUT提高7.7444%，但更换了板卡和前递参数，不能冒充同板单变量对照。收益来自更高的已通过时钟，不是每迭代周期减少。默认选项保持关闭；更高频率部署须显式选择已验证参数。见 `LOAD_FORWARD_EXPERIMENT.md` 和 `HARDWARE_180MHZ.md`。

## 6. ILA关键算法流水线分析

真实PDS DebugCore位流、匹配FIC、同一固件ELF符号表，在27 MHz、200次性能运行中捕获六个1024深度、109位通道窗口。不是仿真VCD，也不是软件GPIO采样替代。每窗验证1023组相邻周期的ID fire→EX有效/PC传递和EX fire→MEM有效；原始CSV、波形图和函数映射保存在包内。

| 窗口 | WB有效/1024 | EX保持 | 已发load等待 | 主要算法 |
| --- | ---: | ---: | ---: | --- |
| 0 | 291 | 0 | 4 | 软件乘法、矩阵位提取 |
| 1 | 293 | 0 | 6 | CRC16、链表 |
| 2 | 276 | 0 | 8 | 软件乘法、矩阵位提取 |
| 3 | 293 | 0 | 14 | 软件乘法、矩阵乘法 |
| 4 | 199 | 8 | 34 | 状态转换、状态机 |
| 5 | 298 | 0 | 0 | CRC32辅助例程 |

![状态机窗口4实板波形](../build/hardware/ila-analysis/ila-algorithm-4.png)

图中显示该窗口前128个样本以便阅读，表格统计仍基于全部1024个样本，不将图示子窗口误当完整采集深度。

窗口4局部退休率0.19434，低于其余窗口约0.27–0.29，并出现取指命令有效80拍；80拍不是80次miss。其他窗口虽几乎无EX保持，仍有大量前端空槽，故优化不应只看数据相关停顿。RV32I矩阵中大量软件乘法符合没有M扩展的事实。redirect包括多类冲刷，不能直接等同于预测失败。这些短窗口不覆盖整段CoreMark，也不能与162 MHz无插核结果混为同一测量。详细分析及插核扰动见 `ILA_RESULTS.md`。

## 7. 应用：CPU软件波形记录器

CPU经GPIO MMIO采样KEY1及UART_RX原始引脚电平，按mcycle安排采样、存入RAM、串口导出。它不是直接读取UART数据寄存器冒充波形，也不是高带宽硬件采集器。27 MHz应用使用9600 8N1命令，目标间隔216周期、256点，记录真实时间戳、迟到数和滚动校验。

箱5实际注入0x55及0xAA，两次均256点、late=0，离线从GPIO波形独立解码正确；相邻间隔172–223周期，约2.038 ms采样跨度。late=0不意味着严格等间隔。KEY1保持0，独立按键边沿仍未实板验证。原始数据、波形图和重放步骤见 `SCOPE_APPLICATION.md`。

## 8. 可复现交付与未完成项

`package_release.ps1` 只选择源码、分析文档、指定已测位流及证据，不复制浏览器配置、登录凭据、PDS安装程序、许可证文件或整个构建目录。保留本项目原LICENSE；依赖软件许可证不被该许可证替代。压缩包内manifest逐文件记录大小与SHA-256，校验器拒绝缺失、额外、重复、损坏和路径穿越条目；这保证内部完整性，不是数字签名或比赛认证。

必须继续完成：最高可用频率区间细化、足够长期的硬件稳定性、独立GPIO按键输入、异步I/O与SCBV约束边界确认，以及最后逐条赛题验收。当前异步输入设false path，LED/UART输出没有源同步外部延时契约；内部All Constraints Met不等于外部接口所有时序已经获证。不得随意猜SCBV电压消除告警。

AI加速与其识别率评估明确暂缓；其余未验证项不因此免除。打包结果固定标注 `engineering_snapshot_not_final_acceptance`。详细包装和离线校验步骤见 `DELIVERY.md`。
