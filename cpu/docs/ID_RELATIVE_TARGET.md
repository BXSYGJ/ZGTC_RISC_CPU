## 修改依据

递增边界父版20260909-014133-12495d99在157.5 MHz下9295 LUT、5179 FF、WNS -0.110 ns失败。最差路径是EX立即数[1]经过PC相对地址加法、预测目标比较到IF指令寄存器CE。当前候选保留父版定时器、共享移位器及传递事件感知前递匹配，将这次加法移到ID向EX传递时捕获；不改变EX分支判定时刻。

experiments/id_relative_target/rv32_core.sv新增32位ex_relative_target，复位清零，仅id_fire时赋值id_pc+id_decode.immediate。early_target以及非JALR的branch_target均改用该寄存器；JALR仍取有效地址并清最低位，其他PC+4计算不动。没有新增流水级或改变基准工作量。规范CPU SHA-256为6273B0EE857DD0F9D38B1048E9F76D2BC5B6F888CBA986ED74723E16DB6C63F3；其余19份物理输入与实际父版捕获逐项相同。生产RTL及发布版本未修改。

## 最终物理结果

Windows PDS 20260909-022522-f1351b42、会话32497已退出1：157.5 MHz、种子2、9292 LUT、5223 FF、WNS -0.206 ns，不合格。没有启动长测或验证种子实现。实际最差路径为EX操作数B[26]经原始操作数对的无符号比较、分支条件选择、fetch_overlap至指令缓存stored_state寄存器，共10级，逻辑2.112 ns、布线4.121 ns。SCBV未设置警告仍保留，不把本地生成的位流当成可接受板级交付。

## 后续方向与边界

新最差路径可考虑原始操作数对比较的时序前移，但不能只在ID传递时捕获：实际ex_operand_a/b还会在ex_valid时刷新为forwarded_a/b，且id_fire赋值具有覆盖优先级。任何比较状态必须同时保持两种更新以及四态、停顿、前递语义；此方向目前仅分析，尚未实现。
