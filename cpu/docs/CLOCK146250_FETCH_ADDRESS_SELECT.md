# 146.25 MHz：寄存状态取指地址选择器

## 实验范围

本实验只在已通过144 MHz物理时序的取指地址选择候选上更换PLL。不是将旧固件、旧频率报告或旧完整CoreMark成绩改标签。

父工程：build/fetch-address-select-stage，合格性能PDS 20260908-040859-4aa56eb5，8793 LUT、5125 FF、WNS +0.195 ns。新工程：build/fetch-address-select-146250-stage。

20项物理输入中19项逐字节相同，唯一变化为fpga/rv32_pll.sv。CPU 5905ABC44DEEF053EEF8A8FE3BB5D4B35CE884EFE0190FA0FDD6B5308B4CEC51，缓存EE88049C2B8FB3F8BD94A8C42B184CBE3181269DC40DCDA49DFD8784E4C653B1，PLL 12ADDA60AB651073B605DACA732AFB4960A01E9896E2B0B26EC40A7BCE91222C。

保持I-cache set bits 9、D-cache 6、BTB 8、本地历史3位/计数器2位，预测、缓存、加载停顿、I/D快速命中、取指/数据重叠、早发D请求及M扩展全部开启，布局种子1，RemoteLab UART 115200。

CPU语义依据父版本344064组合用例、12对慢读/背压/重叠程序、196次ISA、SoC和精确中断测试，加上本次19项硬件源完全相同的绑定。不能把这些父版本测试改称新频点重新执行的196次ISA，也不能据此关闭实板时序或完整ISA认证。

## 真实频率输入与短测

27 MHz输入，PLL I=2、M=1、F=65、O=6，PFD 13.5 MHz、VCO 877.5 MHz、输出146.25 MHz。五频点模型及重新锁定检查通过；新频点200周期跨度1367.556925 ns。四个频率入口仅增加精确146250000 Hz白名单，3个PowerShell语法/BOM/差异检查、8个实际参数拒绝和23个检查器测试通过。

本次实际重编译性能/验证各10轮和6000轮四套固件，使用原RV32 GCC 10.2.0、RV32IM、O3/unroll/relax以及-DCPU_CLOCK_HZ=146250000u。6000轮的CONSOLE_DELAY_CYCLES=2700000是每个串口字符之后的节流，不是一次性启动延迟；10轮不加该节流。固件构建不是计分完成。

## 物理实现与审计

性能PDS 20260908-044857-d6992920已终态通过：8843 LUT、5129 FF、WNS +0.070 ns，All Constraints Met。相对144 MHz直接父版本，频率增加2.25 MHz，LUT增加50、FF增加4、裕量减少125 ps；不能称所有指标同时改善。位流SHA-256 FA2120D61138A5B554DD4E498CE9C5367A431E558F0EC5F32234C78D2A75FB60。SCBV未设置警告仍存在。

原始报告产生时钟为6.8370 ns、波形{0.0000 3.4180}；以报告参考时钟37.0370 ns和真实PLL比例计算，再将周期与下降沿分别截断到1 ps，结果一致。这是本次报告的量化观察，不是一般厂商规范，也不是修改报告去适应审计器。147.776 MHz只是PDS估计，不是另一个已通过频点。

最差前三条路径均从D-cache可写数据存储输出到缓存状态/采样有效位使能。第一条经过read_way0[16]、current_word[16]、load_byte0[0]、地址加法进位至effective_address[28]和MMIO区域选择，到state_reg[9] CE；13级逻辑，逻辑3.245 ns、布线3.028 ns。原生memory_system N0_4确实组合当前/保持地址第28、29位，缓存N2066继续结合第30、31位和握手条件，不把这一高地址区域判断误称为被删除的定时器路径。

原生网表已确认第12位地址仍由GTP_LUT3 N225[12]的11100100真值表实现：I0=fetch_sent，I1=fetch_address[12]，I2=next_pc[12]。这只是该真实映射位的检查，不是所有内部节点的形式等价证明。

build/audit_fetch_address_select_146250.py --require-timing已通过，检查四套真实频率固件的ELF/BIN/HEX一致性、原始报告、20项物理输入、布局命令、原生PLL/地址选择器及双短测。3项负对照测试33.306秒通过，拒绝8类元数据篡改、原始时钟下降沿修改及地址选择器改回fetch_overlap，共10类。篡改仅注入内存读取，不改变原始物理产物。

验证PDS 20260908-050031-2ca8f8b7也已终态通过，8843 LUT、5129 FF、WNS +0.070 ns，与性能实现一致；验证位流SHA-256 54BEA9403CB4E736FD9317596F607CB339F6148A39E30ADB21FFD7F3BC762585。

首次性能6000轮仿真20260908-050057-c4990ab6使用了不适合本固件的30亿总周期预算，完整UART尚在输出编译器参数时实际报FAIL Compiled CoreMark cycle limit exceeded，终态退出1，不计为通过。原因是控制台每个字符节流2700000周期；旧完整144 MHz基线实际采用100亿总周期预算。仅将运行入口MaxCycles修正为100亿，不改固件、计分区、CRC、硬件或时序约束；保留首次日志和失败manifest。

修正后的性能20260908-051255-ed428b16和验证20260908-051212-11d77763均终态退出0，各自ImplementationInputsBound=true，绑定相应合格PDS。性能1918110244计分周期、1649428424退休，13.1152837197秒，CRC e9f5/a14c；验证1921816141周期、1649775523退休，13.1406231863秒，CRC 18f2/18e1。两个计分区均超过10秒。

包含逐字符日志节流的总仿真周期分别4804475474和4805481749，不是CoreMark计分周期；30亿旧预算确实不足。首次失败仍列入not_accepted，不借用其部分输出报分。

配对PDS通过但长测未完成时，另2项门槛测试20.539秒通过，确认时序门槛允许、完整成绩门槛仍拒绝。双长测结束后，build/audit_fetch_address_select_146250.py --require-timing --require-full终态通过；旧144 MHz完整基线的独立--require-full审计也重新通过。
