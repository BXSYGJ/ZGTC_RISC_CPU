# MMIO 载荷采样与请求资格解耦

## 目标与原始路径

上一版已实板验证 126 MHz，详见 HARDWARE_126MHZ.md。本轮只修改 rv32_memory_system 的 MMIO 请求载荷寄存器采样条件，保持 CPU、Cache、PLL、固件、配置不变。相对 build/pds/20260907-010518-97b194c6 的 20 份输入，只有 rtl/rv32_memory_system.sv 不同，新 SHA-256 为 B2BFA122B9112A8BFCD55B6D4C918BD765B376156275E355C9F6AFD529BB8A3E。

该实测实现的原始最差 setup 路径从 Cache request_address[3] 经数据选择、前递和有效地址加法，终止于 mmio_request_address[20] 的 CE。报告为 15 级逻辑、2.334 ns 逻辑延迟加 5.058 ns 布线延迟；末端资格网驱动 70 个负载。不能只看到端点寄存器就推定整条路径都被消除，修改后仍须重新布局验证其他端点。

## 修改及接口不变量

原设计只有 d_req_valid && d_req_ready && request_mmio 时才同时置 pending 和采样地址、数据、写使能、字节掩码。现在 pending 的置位和清除保持原表达式/优先级；69 位载荷仅在 !mmio_request_pending 时预采样 CPU 总线。这里预采样不是提前执行外设访问。

- 空闲阶段：载荷可以变化，但 mmio_req_valid 仍为 0，不会访问外设。
- CPU 真正接受 MMIO 的那个时钟边沿：d_req_ready 对 MMIO 明确要求 pending=0，因此同时满足载荷采样条件，记录的仍是同一个被接受请求。
- 请求等待外设就绪：pending=1，全部载荷保持，即使 CPU 无效总线不断变化也不覆盖。
- 外设接受请求的边沿：旧 pending=1，因此仍保持旧载荷；清 pending 后外设已经自行保存请求，下一周期的无效载荷变化无权改写其响应。
- 旧响应与新请求交接：原 data_active/data_mmio 的清除/置位优先级保持。新 MMIO 请求只有 pending=0 才能接受；Cache/MMIO 选择、异常和维护门槛不放宽。
- 复位：pending 和载荷仍清零；被取消请求不能复活或到达外设。

这些是依据当前 RTL 的归纳式设计解释，不声称已经完成形式验证。可能增加空闲总线变化引起的寄存器翻转，尚未测量动态功耗，不宣称功耗改善；资源效率仍按实际 CoreMark/LUT 和单独报告的 FF/APM 判断。

## 验证

新增 mmio_payload_tb.sv 与 test_mmio_payload.py，真实实例化完整内存系统，覆盖 Cache 开/关、响应重叠开/关、快速 Cache 开/关八种组合。每种完成 72 笔事务，其中 MMIO 48、RAM/Cache 24；含不同写掩码、0至5拍外设等待、响应背压、每周期无效总线扰动、错误响应和待发请求复位取消。

独立 CPU 接受记录用于检查每个有效 MMIO 的全部载荷及每个返回响应；无所有者时出现 MMIO valid 会失败。既有 memory_overlap 系列及其资格/所有者优先级反例继续覆盖 Cache/MMIO 同拍交接、五拍外设背压和异常交接。

八模式覆盖结果保存在 build/mmio-payload-coverage.json。每模式有效事务72笔、待发载荷保持检查196次；空闲预采样检查483至599次，错误响应24至25次。随机序列也随事务等待长度推进，因此不同配置的错误样本数可能不同，不把这些不同序列当成性能消融。

四个反例：恢复旧载荷资格、pending时仍覆盖载荷、仅凭地址制造请求、强制全部字节有效。各被专用断言拒绝，无 watchdog 代替有效失败。恢复旧资格是优化结构保护，不表示旧版接口功能错误。

## 单改动终态：拒绝上板

126 MHz 性能实现目录 build/pds/20260907-013146-a4a97f70；135 MHz 性能实现目录 build/pds/20260907-013213-f5af4bd1。两者使用对应频点既有6000轮固件，新设计是否有时序/面积收益取决于终态原始报告，而不是位流文件是否存在。

完整回归 validate-mmio-payload.log 已终态通过；外部 RV32UI 41项/164次、RV32UM 8项/32次及每套四个拒绝控制通过，报告为 build/isa/20260907-013325-05de0b90 与 20260907-013513-2ee5c9e0。

126 MHz布局结果10265 LUT/4804 FF/4 APM，WNS -0.076 ns；135 MHz为10273 LUT/4809 FF/4 APM，WNS -0.282 ns。两者时序失败，未上板，不给出名义频率下的新CoreMark/资源效率成绩。PDS估计124.8128/130.0559 MHz不是实测频率。

MMIO CE不再是这两份报告的最差端点，但126 MHz瓶颈转到除法器remainder进位链，135 MHz转到Cache请求地址CE；不能将一个端点改善当成全芯片时序改善。后续组合试验仅再改变除法余数空闲清零资格，见 DIVIDER_IDLE_CLEAR.md，单改动失败快照完整保留。

## 尚未证明

本轮两阶段试验均未上板，不继承旧源126 MHz成绩。后续组合版本虽通过126 MHz时序但更耗资源，135 MHz仍失败，故两份实验RTL隔离于experiments/idle_qualification，生产20份输入已恢复到实板126 MHz快照；定向脚本显式测试隔离版本，见DIVIDER_IDLE_CLEAR.md。新源 ILA、独立 GPIO 输入、电气约束/SCBV和长期稳定性仍需独立验证；有限搜索不能证明三项物理极限。没有 Git 提交或推送。
