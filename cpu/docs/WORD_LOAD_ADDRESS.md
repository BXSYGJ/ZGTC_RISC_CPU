# 整字加载地址直接前递候选

## 目标与实现

父工程 trap-vector-boundary-stage 已隔离陷阱向量链，但146.25 MHz仍有WNS -0.109 ns。最差路径经过缓存命中选择、返回数据、子字节扩展、地址高字节到MMIO接受控制。本候选把“加载结果作为下一次加载的地址”拆为整字快路径与子字节等待路径，避免要求所有负载格式都通过同一个长组合地址路径。

候选 experiments/word_load_address/rv32_core.sv 的SHA256为 734B1D48A89D4A60A32A24154593BBA0AC6D33F226959AA1BD50CCD158C93CFF；隔离工程 build/word-load-address-stage。20份物理输入相对父工程只改变核心。机器态陷阱向量结果边界、缓存、MMIO路由、PLL、固定固件与实现参数不变，生产RTL不替换。

原有 mem_load_route[9] 只在合法整字格式且字内偏移为零时置位。因此 load_address_bypass 改为 ex_decode.is_load && mem_load_route[9]。当现有 branch_load_forward 所规定的MEM负载、写回目标、无异常及寄存器依赖条件同时成立时，word_address_forward 直接选择 d_rsp_data 作为地址操作数，跳过字节选择与符号扩展；其他情况使用原 forwarded_a。

LOAD_USE_BUBBLE=1时，依赖LB/LBU/LH/LHU结果的后继加载不再豁免load-use等待；旧负载在MEM完成后，后继指令保持在EX一拍，下一周期从WB取得正确扩展结果再计算地址。LOAD_USE_BUBBLE=0仍通过原通用MEM前递支持全部格式。分支相等比较、算术/存储前递、异常优先和八位分组地址加法均未改变。

本候选明确改变部分程序的执行周期：不能因为CoreMark恰好没变，就声称任意程序零代价。

## 正确性验证

scripts/test_word_load_address.py 最终4项方法205.709秒通过：

- 原核心与新核心各在LOAD_USE_BUBBLE=0/1运行完整操作数台架，每次2631680项，4次共10526720项。保持原有控制位、寄存器别名、x0、WB/MEM优先级、格式/偏移、符号边界、分支和存储检查；新台架仅调整加载地址操作数与等待条件两个期望式。
- 跨周期台架在气泡开关和早期数据请求开关的四种组合下共3328项，包含合法字节/半字/整字格式、不同偏移和正负负载、地址位移、请求背压、旧总线故障、MEM捕获与最终退休。气泡开启的每组832项里，384个正常子字节依赖确实等待一拍；整字保持直接执行。等待后主动改变外部response_data，验证必须使用已保存在WB中的指针，而不是误读下一次总线数据。
- 每组416个旧负载故障验证陷阱优先、禁止后继请求和错误退休。7个实际运行错误变体均被具体断言拒绝；变体运行前先要求未修改实现通过同一台架。
- 源码还原检查确认只改变快路径资格与地址操作数选择，台架也只改变明确列出的两个期望。

另外，新核心早期分支回归3项方法2.666秒通过，7424项场景与12个错误变体；独立返回故障回归2项方法0.697秒通过，24项与4个错误变体。8种严格板级lint通过。
