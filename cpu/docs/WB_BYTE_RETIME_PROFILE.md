# WB字节预计算版的实际退休间隔诊断

## 范围和输入

本诊断只观察当前候选，不改RTL、固件、CPU输入或计分流程，不是新的性能优化候选，也不是正式长测或板级分数。以两份已通过的十轮短测为基准，18份编译输入只把C++驱动替换为原已验证退休观察器；其余17份逐字节一致。观察器SHA256为54E439C391BEA141D0E1D87074AC614743B8A6B8D1838C976CDE63E73BB2D114。

隔离阶段为 build/wb-byte-profile-stage。build/run_wb_byte_profile.py只在原脚本基础上选择独立阶段、独立调用记录目录和当前157.5 MHz解析器；历史观察脚本和阶段均未覆盖。Windows准备入口通过PowerShell解析及UTF-8 BOM检查。

两份UART分别与各自未插入观察器的短测逐字节相同，周期、退休、缓存统计和CRC全部相同。start_time/stop_time的mcycle指令地址由实际ELF反汇编提取并与HEX逐字节校验：性能0x5a70/0x5a8c，验证0x5a78/0x5a94。首尾记录周期差精确等于UART测量周期。记录数与UART retired相差12是既有计数窗口边界差，不强行合并。

## 当前观察结果

每对相邻退休记录形成一个间隔。这里用“间隔周期减一”作为算术开销，仅用于定位，不是内部stall计数，不代表可以独立消除的周期。每种分类维度单独完整划分同一组间隔；不同维度不得相加。

- 性能：2748928个间隔，总3151519周期，算术开销402591周期。
- 验证：2749601个间隔，总3156276周期，算术开销406675周期。

按前一条控制流指令分类：

| 前一条类别 | 性能算术开销 | 验证算术开销 |
| --- | ---: | ---: |
| 条件分支 | 276368 | 279114 |
| JALR | 10076 | 9956 |
| JAL | 6960 | 10179 |
| 其他 | 109187 | 107426 |

按当前消费者分类，两种种子都含93960个乘法间隔；93925个间隔恰为2周期，其余35个为9或10周期；此维度乘法的算术开销为94219。不能将它与上表直接相加，也不能把长间隔全部解释为乘法器延迟。

当前相邻load依赖维度的算术开销仅5495/4416周期，其中load地址46/46，分支96/8。这与旧“完全停顿减去原前递”的194862/199451周期差不是同一种测量。不能继续用旧差值声称当前仍能消除相同数量的load停顿。

两种种子最突出的一条间隔均为0x514→0x518：2040次全部6周期，算术开销10200；前一条为条件分支。0x4a0c→0x4ae8、0x49b8的两条后继、0x4bc0→0x4c04同样突出。下一步应追踪这些实际分支的预测/训练和重定向接续状态，再选择低面积预测改进或更短重定向流程；这些观察尚未证明是哪一内部原因，不能直接称为已测误预测数。

## 文件与复验

- scripts/retirement_gap_profile.py / scripts/test_retirement_gap_profile.py：流式统计、各维度周期守恒、重复边及非法/非单调输入拒绝。
- build/analyze_wb_byte_profile.py：重新执行来源/ELF/轨迹审计、12项真实观察器反例，再生成只写一次结果。
- build/wb-byte-gap-profile-v0.json / build/wb-byte-gap-profile-v1.json：完整分组、所有转移、实际来源及原始轨迹哈希。
- build/wb-byte-profile-local-state.json：终态和证据索引。

本诊断没有改变两组6000轮计分仿真，没有生成或烧录新位流，没有Git操作。500分本地基线现已完成验证长测、完整目标门及最终反例验收并冻结；后续按时钟、精确资源效率均不下降的约束提升执行效率，实板证据仍需独立取得。
