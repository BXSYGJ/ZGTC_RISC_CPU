# 仅BEQ/BNE使用加载前递的隔离实验

2026-09-07。目标是缩短加载响应到分支控制的组合路径，不承诺减少所有程序的执行周期。生产核心、已发布版本及GitHub不变。

## 电路变化

基于分支专用前递和直接数组LRU组合，新增equality_branch：条件分支且funct3为000/001。只有BEQ/BNE的加载相关指令可以跳过通用加载停顿，并使用MEM加载结果作为相等比较操作数。BLT/BGE/BLTU/BGEU改用已有通用forwarded_a/b；加载相关时先停顿，在WB前递得到操作数后执行。JALR、地址计算、普通ALU和存储数据继续使用原通用路径。

不把所有分支都称为“零代价”：关系比较的相关加载会增加等待。非法funct3=010/011不会启用此旁路；异常、无效响应和冲刷依旧由原mem_ready/mem_flush/execute_exception控制。bubble=0维持原全前递功能。

唯一核心源为experiments/load_use_equality_bypass/rv32_core.sv，SHA-256为952F587D921CEDD72E91CCCA2F25565FB3EFB8C4C497E4DCE04225CB161508E0。build/load-use-equality-bypass-stage从141.75 MHz候选复制，20项硬件输入仅更换该核心；PLL和固件沿用对应频点的实际输入。缓存测试台另作隔离适配，生产测试台不变。

## 为什么尝试这个方向

已审计的十轮退休轨迹中，相邻加载相关条件分支全部是BEQ/BNE，性能种子分别74670/57450次，验证种子76500/59320次。这是程序行为观察，不是内部停顿计数，也不证明所有未来程序或完整6000轮都没有其他分支。

同固件重新运行新候选，两种十轮构建20260907-202628-7b5842d5、20260907-202636-deb40275分别为3262506/3270362周期、2748941/2749614条退休指令，与全条件分支前递版本相同。短测不满足正式时长，不据此推导正式分数或宣称更高频率。

## 定向验证

scripts/test_load_use_equality_bypass.py共5个方法通过，73.097秒。两种bubble配置各1052672次比较，共2105344次，覆盖全部分支funct3、符号边界、加载扩展、寄存器零号、转发优先级，以及通用操作数不被分支专用路径污染。

14个组合逻辑/停顿条件变异被拒绝，包括误开所有分支旁路、错误funct3、错用加载结果进行关系比较、去掉异常或零寄存器保护；拒绝不能靠未完成测试次数的断言蒙混过关。四种预测器/停顿配置通过无效数据毒化测试，另3个错误响应控制变异拒绝。独立缓存测试还验证恢复全停顿版本被拒绝，而正确候选通过参考模型与内存比较。

缓存CPU两预测器配置均通过13个精确陷阱以及参考/内存差分；14个精确乘除法中断用例通过。UART SoC通过74项检查，8259周期、23个UART字节、三类中断各一次；相比前一候选8238周期增加21周期，说明该改动不是所有工作负载无代价。故障SoC通过41项检查。
