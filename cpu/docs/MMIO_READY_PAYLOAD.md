# MMIO载荷寄存器使能实验

## 动机和精确改动

16 KiB指令缓存候选的135 MHz最差路径从D-cache同步DRM输出，经加载前递、有效地址加法与MMIO译码，进入mmio_request_address[30]的CE，WNS为-0.191 ns。生产代码把地址、数据、写标志和字节使能共69位载荷的更新与真正MMIO接收条件绑定。

本候选仅把载荷更新条件改为!mmio_request_pending。待发寄存器为空时可以跟随CPU输入，即便输入不是有效MMIO；有待发请求时完全保持。mmio_request_pending仍只由原来的d_req_valid && d_req_ready && request_mmio置位，外设侧有效性、请求接收、应答所有权、异常、维护、重叠和复位优先级不变。外设只能在mmio_req_valid时使用载荷，无效周期的变化不能当成副作用。

保持旧复位行为，不新增流水拍，不修改CPU或Cache，不假定外设恒ready。该结构旨在移除地址译码至69位载荷CE的依赖，真实资源和时序收益必须由PDS证明。

源码SHA-256：2080990BFB20C6D6660EF63235E6C1716ED1DF1D1C4FD626A9B042E1CE86F2DD。参考memory_system为A19CA7E5EE539E2CA3249D6265E4F1B3250A7BE75286481256DE8F73DA1E5058。使用DB55同步可写缓存与826F H3/C2预测器，分别测试I-cache组位数8、9；其余参数完全相同。

## 已完成回归

scripts/test_mmio_ready_payload.py将真实候选与独立命名的原始memory_system并行实例化，使用相同DB55缓存、后端和激励，逐拍检查握手、有效应答、有效MMIO载荷、计数器及维护接口。

24组双实例等价性正例（各含候选与参考）覆盖快速读/写各0/1、I-cache组位数1/8/9、外设停顿0/5拍；包含缓存与MMIO双向交接、应答反压、外设反压、错误应答、一次性副作用、flush写回以及未发送MMIO的复位取消。4个真实编译的故障候选均由功能断言拒绝：待发载荷仍覆写、反向载荷使能、无请求即发MMIO、错误字节使能。编译错误和watchdog不算拒绝成功。

性能/验证短测均为132 MHz配置、10轮。I8为3239409/3247040周期，I9为3199743/3206720周期；各自与相同容量参考的UART逐字节一致、周期/退休数/CRC/缓存计数一致。不是正式分数。build/mmio-ready-payload-i{8,9}-short-audit.json核验原始文件、可执行文件、固件、硬件快照和范围检查工具的精确差异。

## 物理实现与原生网表核验

两份135 MHz种子1性能实现均已终态：I8为20260907-155150-fbb5dbc8，7580 LUT、4933 FF、WNS -0.008 ns，未通过；I9为20260907-155219-4ef234fa，9220 LUT、5726 FF、WNS +0.117 ns，通过。相同I9参考原为9260 LUT、5731 FF、WNS -0.191 ns；同固件、同参数和种子，只改变memory_system。不能据此称该改动对所有容量和布局都有效，I8本次结果反而不如原通过版。

I9验证PDS 20260907-155959-6097eed9也取得9220 LUT、5726 FF、WNS +0.117 ns；两份原始报告、20份相同输入、顶层参数、对应精确6000轮固件和位流通过独立配对核验。性能位流SHA-256为914AAC24A70AEE187069876DBB9FAD3723997BB7B58873E9EF0FE9AC64DFA2A5，验证为9595BCE2D68F9F0E2C7F6C18F105EE2BA687BDB9EE60ABC36F9387EFA0AD1F0A。

原生综合网表保留67个载荷触发器，全部CE由mmio_req_valid反相驱动，而mmio_req_valid是mmio_request_pending触发器Q。参考CE驱动是含d_req_address[30]/[31]的LUT5。build/mmio-ready-payload-native-audit.json保存驱动实例、寄存器清单及原始网表SHA，3个网表依赖故障均被拒绝。改后最差路径转到next_pc[16]至next_pc[29]进位，不再是原MMIO载荷CE端点；不能将整个WNS改善全部分解归因于单门延迟。

两版CPU/SoC/参考模型/随机指令/旁路/独立快速读写与重叠及lint均终态通过。外部ISA共392次正例、16次拒绝完成独立审计，所有正例与相同容量参考的精确固件、退休数和周期数一致，不是完整ISA认证。

## 独立长测完成

最初性能20260907-160050-45212a9f和验证20260907-160806-d07a638a均在2300000000总周期上限终止，UART只输出到报告开头，SimulationPassed=false；这是本轮启动参数预算设置错误，不能算通过，也不能从半截UART恢复分数。历史同串口延迟固件完整仿真实际分别需要4828688439/4830754080总周期，明显多于约19亿计分区周期。两次原始失败日志、UART及哈希均保留于build/mmio-ready-payload-budget-failures.json。

确认两个旧进程各自终态后，使用历史已验证的10000000000总周期预算重新运行：性能20260907-161425-f0f61f91、验证20260907-161605-230195d4。两份新快照与各自失败运行的18项源码、硬件参数和精确固件一致，从开始绑定各自合格PDS，未裁剪串口延迟或放宽CRC/至少10秒检查。两份均已终态通过。

性能6000轮为1914911883周期、1649428424退休指令、14.184532467秒，CRC e9f5/a14c；验证为1919205743周期、1649775523退休指令、14.216338837秒，CRC 18f2/18e1。build/mmio-ready-payload-full-{performance,validation}-audit.json已独立核验各自至少10秒、CRC、固件、源码、实现与位流。真实历史合格H3长测会因MMIO源码不同被明确拒绝，未借用旧运行作为新结果。
