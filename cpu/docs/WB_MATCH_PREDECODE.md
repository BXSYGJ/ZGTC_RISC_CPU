# WB寄存器匹配预译码实验

2026-09-07。基线为完整双种子已通过的全偏移加载旁路版：144 MHz、8626 LUT、5123 FF、WNS +0.005 ns。该基线的前三条慢路径包含WB寄存器号比较到mem_result。本实验尝试把比较结果提前寄存，不改变指令、流水线拍数或软件。生产RTL及GitHub保持不变。

## 电路改动与不变量

WB是写回级：结果即将写回通用寄存器，年轻指令可能必须直接使用这个结果。原实现当拍比较WB目的寄存器编号与EX源编号，再选择WB数据。现在增加ex_wb_match_a/b两个状态位，使用当前MEM即将形成的WB身份，以及下一拍EX的真实身份计算匹配；下一拍数据通路直接使用这两个位。

下一拍WB必须满足MEM完成、无错误、确实写寄存器且目的编号非零。下一拍EX的源编号在id_fire为真时来自当前ID，否则保持当前EX。不能总用旧EX编号，也不能总用ID编号，更不能在EX停顿时保留过期匹配位。

独立验证的不变量是：时钟沿之后，匹配位等于该时刻真实WB有效/写许可/非零目的编号与真实EX源编号的比较。原MEM覆盖WB的优先级、未使用源及x0清零、加载专用前递、各类停顿、异常优先级和请求握手都保留。没有提前提交，也没有增加一拍指令延迟。

核心源experiments/wb_match_predecode/rv32_core.sv，SHA-256为D48A84EEF6B7245EBA9ABA502163352072D1614741B27C23E117A2BEB2382ABD；隔离阶段为build/wb-match-predecode-stage。审计根据基线完整文本重建且只允许四处改动：两个状态位声明、WB数据选择、复位值、下一状态计算。20项物理输入中其余19项不变。

## 分层验证，避免循环论证

组合地址/分支矩阵中，两个匹配位由参考比较结果强制提供；这一层只检查匹配已正确时的数据选择、MEM/WB优先级、加载扩展和通用操作数隔离，不能作为状态位更新正确的证据。该矩阵在两种bubble配置合计5263360次比较，另有4227072次全部4096个合法有符号12位立即数的地址算术比较。

独立sim/wb_match_state_tb.sv让EX/WB寄存器随真实时钟沿更新，然后直接读取沿后的寄存器身份核对匹配位，而不是再次使用生成匹配位的同一下一状态公式。覆盖32种ID接收/MEM完成/MEM错误/MEM写许可/冲刷控制组合、32个目的编号及两组32个保持源编号，共1048576组。每组先建立保持的EX，再提供不同的ID编号并推进，共4194304次沿后比较，另检查前后两次复位。

输入ID编号由保持编号作固定异或得到，以区分ID替换和EX保持；并未穷举所有彼此独立的前后源编号组合。这个测试允许人工握手组合，只证明相应元数据状态关系，不冒充真实指令程序、整个处理器形式证明或实板波形。

真实core_tb.sv与cached_core_tb.sv另在每个下降沿检查上述不变量，且要求A/B均实际出现非零匹配，覆盖正常运行、停顿、跳转、异常和复位后的状态。缓存两预测器分别完成12996/12758次匹配比较；实际匹配A均101次，匹配B分别47/70次。

完整scripts/test_wb_match_predecode.py的8个方法一次通过（417.073秒），包括12个数据/依赖逻辑变异、10个状态更新变异、3个错误/无效响应毒化变异及1个恢复全停顿变异的拒绝。三类定向矩阵合计13684736次比较，其他CPU/协议检查另计。错误必须由指定不变量拒绝，不能以未完成用例数冒充有效拒绝。日志为build/test-wb-match-predecode.log。

## 审计与保留决策

build/audit_wb_match.py核验四处文本变换、原始物理快照和每项文件、生成顶层及实际固件路径、原始资源/时序、位流、双短测、逐案ISA、整机/严格lint、逐拍匹配计数，以及12组随机等待的24份原始轨迹/内存文件。输出build/wb-match-predecode-qualification.json明确evidence_consistent=true、timing_qualified=false、full_score_available=false。--require-timing另已验证按实际负WNS拒绝。

保留这一功能正确但物理失败的实验，不替换原全偏移加载旁路候选，不自动启动本候选的完整分数长测，也不借用基线3.128078805 CoreMark/MHz套入本候选8658 LUT。后续优先研究报告中实际出现的Cache前递/请求控制路径，同时保留精确异常、无效响应隔离与全部性能计数。有限试验不证明物理极限，实板及整体五项任务验收仍未完成。
