# 两槽循环旁路加 WB 目的编号非零资格捕获

## 已确认的瓶颈

两槽旁路版双短测各节省9900周期，但157.5 MHz实现20260909-062346-a8dbec11以9475 LUT、5301 FF、WNS -0.258 ns失败。单槽版随后为9538 LUT、5292 FF、WNS -0.332 ns，因此不叠加单槽修改。

两槽版最差路径从wb_rd[4]进入N1986_5，再经N1986_inv、WB前递选择、ALU减法到mem_result[24]。实际综合网表确认N1986_5是五位WB目的编号的OR归约，INIT为32位除最低位外全1，并非猜测的完整寄存器匹配比较。相关两段原始布线为0.591和0.636 ns。

本次曾考虑扇出属性，并实际查阅本机原厂手册；确认判零逻辑后改为将这一判定提前捕获，不添加扇出属性，也不盲目换布局种子。

不变量是每个时钟沿后wb_rd_nonzero等于实际wb_rd!=0。没有增加流水级、改变退休工作量或修改CoreMark程序。源差异可精确还原732509AD父CPU；相对于两槽父版仅CPU改变，相对于冻结501.065730222本地基线累计为CPU和BTB两份输入改变。
