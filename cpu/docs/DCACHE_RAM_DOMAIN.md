# RAM分支地址域约束：单行隔离候选

## 已核实的逻辑依据

现有rv32_memory_system以request_mmio=OR(d_req_address[31:28])选择MMIO或RAM/cache，RAM分支请求有效条件含!request_mmio。因此RAM/cache请求有效时，高四位必为0；MMIO缓冲仍须保留全部32位地址。

候选仅将RAM分支的cache_req_address[1]由d_req_address改为{4'b0,d_req_address[27:0]}。它不截断真实有效RAM请求，不把非MMIO非法地址伪装成合法RAM地址，不清除未对齐低位，不改变MMIO地址、请求/响应握手或错误优先级。目标是使综合工具不必在RAM范围检查中重复处理已由路由排除的高四位，不预先承诺实际时序或资源一定改善。

规范源为experiments/dcache_ram_domain/rv32_memory_system.sv，SHA-256为5463530856B489C99396AEBF14EAB2844DB21D9445EDD731CCCF676C0D2989F5。隔离工程build/dcache-ram-domain-stage从146.25 MHz直接分支/8位地址候选派生，20项物理输入只改memory_system；核心FCD29C622EFA23A666398EC27324A97A2291D1079A24CC6949FE91A74E1DFF99及PLL12ADDA60AB651073B605DACA732AFB4960A01E9896E2B0B26EC40A7BCE91222C保持不变。父方案两个布局种子均失败，不作为新候选的时序资格。
