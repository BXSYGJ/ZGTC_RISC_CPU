# Cache 查找数据与命中响应资格解耦

## 设计与边界

保留前递数据版本的执行、异常和提交门槛，只把 rv32_cache 的提前响应数据选择从 fast_hit 改为 fast_lookup。fast_hit 仍等于 fast_lookup 与有效 tag 命中的合取，rsp_valid 仍由原有 RESPONSE 状态或 fast_hit 产生。未命中查找周期可以出现无效待选数据，但绝不能产生响应；错误响应仍输出零。hit_line 的有效位/tag/路选择不变。

这去掉数据多路器上重复的命中资格，不新增指令、Cache 状态或 CPU 配置位。上一版实板结论见 FORWARD_DATA_QUALIFICATION.md；本页的本地实现不能借用它的板测结果。

## 定向测试与完整回归

新增 test_cache_lookup_data.py 使用实际 cache_tb 和生产 RTL 临时副本，覆盖七种只读/读写、快速读写和响应重叠组合。监测未命中不制造响应、每个有效响应与旧表达式值一致，并统计提前查找命中/未命中；随机读写、写掩码、回写/填充故障与重试仍走原有黄金内存比较。

四个反例分别恢复旧数据资格、让 miss 产生响应、强制取第零路、去掉错误清零；各自被对应断言拒绝。恢复旧选择的反例是优化结构保护，不表示旧设计功能错误。既有快速写命中反例同步到新锚点，没有改变其错误响应/背压检测语义。

完整 validate-cache-lookup-data.log 终态通过；外部 RV32UI 为 41 项/164 次，RV32UM 为 8 项/32 次，各含四个拒绝控制。报告分别在 build/isa/20260907-005521-c7fbb496 和 20260907-005721-6bd57127。它们不是完整 ISA 认证。

七模式详细覆盖保存在 build/cache-lookup-data-coverage.log，所有模式有有效响应覆盖；启用快速路径的模式都有命中与未命中覆盖。额外覆盖命令末尾无匹配文件的 rg 返回 1，与此前成功的测试退出状态不同，不把该搜索退出码算作 RTL 失败。

## 更细频点

135 MHz 未闭合后，新增显式 126 MHz 候选：27 MHz 输入，STATIC_RATIOI=1、STATIC_RATIOM=2、STATIC_RATIOF=21、STATIC_RATIO0=9。依据已安装的原厂 GTP_GPLL 模型分频实现进行仿真，后续仍须由 PDS 实现和实际板测分别确认，不以模型输出代替器件时序/电气验证。

构建、仿真、UART 检查器和 PLL 频点回归同步支持 126 MHz；固定 120 MHz 的 check_performance_target.py 验收语义保持不变。高频候选使用 6000 轮，必须再次检查实际计分时间不少于 10 秒、性能/验证种子 CRC、资源效率至少 0.031，不能套用旧频率 UART 或旧位流资源。

新增 check_frequency_candidate.py 显式要求 --clock-hz，复用原有数值计算和完整构建/UART 检查，并强制源码快照核验。check_performance_target.py 的命令行仍没有可改频率参数，默认 assess(case) 仍只接受 120 MHz；公共计算函数新增仅关键字 expected_clock_hz，候选频率不得低于 120 MHz。两种入口均使用整数交叉乘法判定 3.0 和 0.031，不用展示浮点值四舍五入决定通过。

18 个受支持 PLL 输出频点的原厂模型测试通过，126 MHz 包括 200 周期频率测量与复位重新锁定。新增候选门槛 6 项、原门槛 9 项、UART 检查器 17 项、构建比较器 26 项、旧 ILA 来源保护 7 项测试全部通过；CoreMark 运行契约 14 项通过，修改过的 PowerShell 脚本语法及 UTF-8 BOM 检查通过。

真实旧版 120 MHz 构建和原始 UART 通过固定门槛重验，但作为显式 126 MHz 候选被退出码 2 拒绝。证据在 build/hardware/fixed120-gate-after-frequency-support.json 与 frequency126-reject-original120.json。它们是验收工具回归，不是新一次板测。

新增 PLL 选择后的源码与本页 120/135 MHz 源快照不同；即使旧频点数学配置不变，也不谎称文件哈希完全相同。原 Target120 ILA 来源锁不更新，当前 Core/Cache 必须原生重新查询/映射后才能使用新插核结果。
