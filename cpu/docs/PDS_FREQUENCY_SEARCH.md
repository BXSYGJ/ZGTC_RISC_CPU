本轮只改变合法GPLL分频、对应约束及固件频率参数，没有把普通逻辑用作时钟，也没有通过放宽时序门槛换取成功。以下频率都是请求值，不把PDS估计值称作实板测量。

## 自动审计与失败保留

`scripts/pds_report.py` 读取实际 `.rtr` 和PDS标准输出，交叉核对器件、速度等级、封装、CPU时钟周期、同步负载、性能摘要及请求频率。它同时保存综合LUT和最终CLMA+CLMS的LUT总和，后者不再叠加Distributed RAM栏。GPLL数量也必须符合直连/PLL时钟选择。`SCBV has not been set` 仍作为独立警告保存，不隐去。

`run_pds.ps1` 已集成此审计。只有通过后才写成功 `manifest.json` 和 `pds-latest.json`，并将资源摘要嵌入manifest。约束失败仍保存 `resource-summary.json`、时序和实现日志，但返回非零状态，不签发成功manifest。

**216/270 MHz虽然生成了.sbit文件，但不代表工程成功。** 两次均被自动拒绝，未写成功manifest，也未被下载到远程板卡。不得仅凭位流文件存在就绕过门槛。报告解析器的五项单元测试包含重复/缺失字段、错误器件、时钟不一致、无负载、负slack与成功摘要矛盾、PLL数量不符；实际27/108 MHz旧报告也通过重读验证。

## 已定位的优化方向

216 MHz慢角最差路径由 `core/mem_address` 经 `mem_value`、前递选择、`alu_b`、ALU进位链到 `mem_result`，报告给出13级逻辑，数据路径逻辑2.029 ns、布线3.082 ns。应优先检查load结果到下一条EX运算的组合前递路径，而不是仅修改时钟数字。

根据该路径提出的load寄存前递实验现已实现，默认关闭。162 MHz硬件对照及收益边界见 `LOAD_FORWARD_EXPERIMENT.md`；后续180/194.4 MHz细化见 `PDS_FREQUENCY_REFINEMENT.md`。必须同时比较正确性、周期数、有效频率和布局后CoreMark/LUT，不能以单一时序估计代替整体收益。

162 MHz通过与216 MHz失败并不能严格证明所有中间频率的结果，更不证明所有可能布局的绝对Fmax。中间频点、实板长期运行与更深入结构优化仍应逐项验证。
