# D-cache写命中提前响应

后续测试覆盖纠正（2026-09-06）：run_cached_tests.ps1曾将读快路径开关覆盖成写开关，只有该入口读写开关不同的旧运行受影响。已修复并重新执行独立读写组合与全回归；直接模块测试、独立CoreMark/SoC/ISA以及两开关同为1的候选不受该错误影响。详见ASYMMETRIC_CACHE.md，不追认受影响的历史覆盖。

2026-09-06。本轮在原120 MHz、O3 + unroll RV32IM候选上增加可独立开关的写命中提前响应。不是写后不管的posted store，也不是给MMIO提前确认。3.0 CoreMark/MHz与全部验收仍需后续证据。

## 做了什么、为什么、在哪里

原Cache在LOOKUP沿完成命中字节写入，但写请求仍要等待RESPONSE状态。新增FAST_WRITE_HIT让可写Cache在LOOKUP命中时即可给出有效响应，CPU接收沿与字节写入沿相同；背压时仍写入一次并进入寄存响应状态。配合DATA_OVERLAP可在旧响应接收沿接受下一数据请求。

- rv32_cache的FAST_WRITE_HIT与FAST_READ_HIT独立，默认均保留原值0。没有让“提前读”参数偷偷启用写优化。
- FAST_DCACHE_WRITE贯通memory_system、SoC、板顶层与PDS包装层；只有D-cache启用，I-cache仍只读。
- PowerShell的FastDCacheWrite取0/1；cached测试使用同名switch。CoreMark、PDS、SoC和外部ISA的编译参数、运行清单、文件名后缀及身份检查均贯通。
- 硬件配置字bit19从保留位变为有效提前写模式；旁路强制该位为0。默认配置不变。64项BTB/B0为0e6606f9（关）与0e6e06f9（开）；128项开启为0e7e06f9。
- 严格比较器新增FastDCacheWrite单变量模式，保留同固件、同源码、同频、有效长时和其他参数一致的门槛；不允许用短跑或多参数变化绕过门槛。
- 旧ILA插入脚本明确拒绝尚未验证的FastDCacheWrite=1网表，不冒充已经完成ILA映射。

## 必须保持的语义

1. 写响应数据仍为写入前的完整字，不是写入数据或更新后的字；背压期间值与错误位稳定。
2. 所有16种字节选通均按原合并规则写入；零选通不修改存储，也不将干净行标脏。
3. 背压、连续同址写和同拍后继请求均只处理各请求一次；当前CPU输入变化不能修改已锁存请求。
4. 写缺失仍先完成必要的脏行写回与完整填充，只有回到有效LOOKUP后才能提前响应。写回/读错误、越界、未对齐和只读写入不被早确认吞掉。
5. 维护仍等待已接受事务；复位发生在请求接收后、LOOKUP提交沿前时，未提交写不会泄漏响应或存储副作用。
6. MMIO仍经过memory_system的已注册请求与外设真实响应，不能将本优化用于推迟报告外设错误。

## 三指标如何比较

与64项关闭写提前的合格控制组相比，128项开启组合：

- 短跑周期374184至352805，减少5.71350%；同频短跑工作率提高6.05972%。
- LUT增加248，即3.57606%；FF增加50。计入面积后，短跑工作率/LUT代理指标提高2.39791%，未测动态功耗。
- 两者均通过120 MHz设置；WNS由+0.141变为+0.165 ns，不把工具裕量或估算频率冒充实测最高频率。
- 这是BTB容量与写响应两项变化的组合效果，不是FastDCacheWrite单变量实板消融。64项开写模式的失败不能被128项通过覆盖。

128项验证种子构建20260906-193159-014b25ce通过120 MHz，WNS +0.165 ns、7183 LUT、4130 FF；位流SHA-256为EC819F97B12B425C407B33B59788955B5131C5363396145F21DFE9B58916A696。验证固件SHA-256为0913A391B44B037868C9D0FB24482759518428295EF59E04DD19F6664A41BAE1，20份快照与性能构建及当前源码一致；实际快照、位流和固件字节均核验通过。
