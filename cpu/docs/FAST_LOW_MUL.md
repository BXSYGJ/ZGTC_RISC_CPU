# 低位乘法同拍响应试验

## 动机与边界

2026-09-06的120 MHz真实矩阵ILA窗口中，136个EX有效但未fire样本有134个落在mul指令。基于这个线索试验低32位乘法同拍响应，而不是修改CoreMark算法。目标仍是维持至少0.031 CoreMark/LUT并提升执行效率与主频；短跑收益不能抵消失败的正式时序。

本页为候选试验，不替代HARDWARE_120MHZ_TARGET.md的已达标实板版本。新源码不复用旧ILA输入锁和映射，也没有再次上传GitHub。

## 电路变化

rv32_muldiv的FAST_LOW_MUL参数控制低32位结果的即时路径。低位乘积由16x16低乘积和两个交叉乘积低16位组成，共用原半字乘积表达式；MULH/MULHSU/MULHU和除法保持原状态机。只在IDLE且收到低位乘法请求时给出即时rsp_valid；若rsp_ready为0，则锁存结果进入RESPONSE，不能随输入变化。cancel立即压低握手并清除事务。

CPU在请求与响应同拍完成时，原ex_fire优先清除muldiv_started，不额外产生第二次请求。单元增加同拍请求、连续请求、背压、取消和故障注入检查；原muldiv_tb配合生产模块保留旧延迟反例，另将它与隔离候选FAST_LOW_MUL=1编译，执行全部12544项运算/保持检查。

精确中断测试不能再等待低位乘法的muldiv_started寄存位：零附加等待时该位不置起。新测试对即时MUL在接受前的负沿注入中断，高位乘法和除法仍保留原来启动后各延迟点；目标指令不得在处理程序前退休，恢复后必须且只能退休一次。

## 初步收益，不是实板成绩

同配置、同固件10轮性能短跑从3326116周期降至3232485周期，退休指令保持2748941；验证种子从3329203降至3235582，退休指令保持2749614。两套种子均通过对应CRC。性能周期减少2.815025%，验证减少2.812114%，不把不足0.03秒的模拟运行当正式CoreMark分数。

候选编译式仿真位于build/compiled/20260906-235345-1933fa88和20260906-235353-8d87b89b。正式性能主对照使用相同C++驱动的20260906-211808-a2c438bf：逐项核验固件、硬件参数、实际C++字节以及移除构建目录差异后的全部编译命令一致，可执行输入仅rv32_muldiv.sv改变，证据为build/fast-low-mul-primary-comparison.json。早期211304/211312驱动存在修订差异，初版差异清单保留在build/fast-low-mul-short-comparison.json，不隐去非RTL差异；验证种子对比作为辅助而非严格单因素证据。所有候选模拟清单明确ImplementationInputsBound=false，输入为参数探索配置，并非已完成PDS实现绑定。

## 正式实现结论：拒绝采用

2026-09-07 00:02:25完成位流生成，但正式时序审计返回失败：120 MHz setup WNS为-2.291 ns，PDS估计94.1265 MHz（不是实测Fmax），9990 LUT、4905 FF、4 APM。成功生成.sbit不等于允许上板；本位流未烧录，也没有可接受的正式120 MHz CoreMark或资源效率成绩。不能把3%左右的短跑收益与未通过的120 MHz布局结果相乘作为新成绩。

全工程validate-fast-low-mul.log终态通过，包括参考模型、内存比较、严格lint、协议反例和新乘法测试；外部ISA结果见上节。因此本轮是“功能通过、物理时序失败”，不是软件CRC失败。失败清单build/fast-low-mul-failure.json绑定原始时序、位流、候选源码及回归日志哈希。

最差路径起于D-cache valid[98]，终到core/mem_result[26]，途中经过响应资格、load前递与ALU算术；不能只凭试验名称就把全部-2.291 ns归咎于乘法器本身。该路径提示下一步要检查前递/ALU长组合链与布局影响，或用有依赖资格检查的提前计算隐藏乘法等待，而不是继续盲目增加单拍组合逻辑。

已将候选隔离到experiments/fast_low_mul/rv32_muldiv.sv，并保存当时使用的muldiv_core_tb.sv。生产rtl/rv32_muldiv.sv恢复到A6E78FB4开头的原达标文件；全部20份生产RTL/约束/PLL输入重新逐哈希匹配原达标源快照。原sim/muldiv_tb.sv和sim/muldiv_core_tb.sv也恢复；新test_fast_low_mul.py显式测试隔离候选，不会悄悄把它接入实际工程。隔离后新/旧乘法测试各三项再次通过。
