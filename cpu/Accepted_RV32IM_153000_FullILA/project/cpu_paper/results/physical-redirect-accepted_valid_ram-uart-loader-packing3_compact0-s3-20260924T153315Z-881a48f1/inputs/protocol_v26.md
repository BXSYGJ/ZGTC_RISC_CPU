# Protocol v26: one qualified UART loader image for Embench

The FPGA Lab repository at commit `08dbfa1b930f87981fe213367f3c25a4e4f4134a` supplies a native HTTP/serial bridge and a flow-controlled RAM-loading protocol. Its `ram_load.py` programs a prebuilt image and sends `R`, a little-endian 32-bit byte count, and 256-byte chunks acknowledged with `K`. It does not synthesize the FPGA. Its older bitstream, demo-specific success parser, and Flash path are not qualification evidence for the accepted processor.

Build one RAM-only UART bootloader image from the unchanged accepted RTL, constraints, GPIO/UART/caches, redirect priming, fetch factoring and nominal BTB. Preserve the full historical 42-data/33-trigger/1024-sample ILA and independently qualify this new image at configured 153 MHz with native Windows PDS/ADS. No changes to the accepted source tree or downloaded upstream sources are permitted.

Reserve 0x0000–0x0fff for the loader. Relink every pinned Embench workload and the dummy at 0x1000 in the remaining 60 KiB, retaining a 16 KiB stack reservation, GCC 10.2 flags/libraries, heat=1 and scale=1. These relocated binaries and their initialization differ from v25; preserve v25 observations separately. Do not combine their cycle counts into an undifferentiated suite or substitute them for a matched ablation pair.

Use only RAM loading. The accepted design has no requirement for the newer SPI controller, and upstream documents an unusable board Flash path. After loading, execute the accepted fence.i maintenance path to write back data and invalidate instruction state. Compute and report CRC32 over the received RAM image, check it against the host binary, then launch the application. K acknowledgements provide flow control, not integrity proof. For N bytes, the protocol sends floor(N/256)+1 acknowledgements, including its final acknowledgement.

Cold-program the same immutable loader bitstream for each workload, thereby resetting caches, predictor, counters and RAM before each upload. This repeats programming but avoids synthesis/place-and-route. Preserve loader and application hashes, serial transfer events, RAM CRC32, Embench correctness, atomic cycles/retirement intervals, CPI, programming receipts, actual device identity, and the shared native resource/timing evidence. Send G only after the application's READY record. UART G/output remain outside the measured interval.

Exercise the actual bootloader, transfer, cache maintenance and relocated binaries in RTL before hardware qualification. Include the dummy, crc32, and the largest application xgboost; check independent cycle/retirement observers and stack bounds. Capture every workload's actual board verifier result. Report failed, interrupted or unavailable board runs explicitly. There is no official normalized Embench score or independently measured frequency in this experiment.
