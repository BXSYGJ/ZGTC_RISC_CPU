# Protocol v4: CoreMark atomic measurement boundaries

Prospective amendment to v1–v3, recorded before new CoreMark execution.

The archived CoreMark port snapshots cache counters, then reads retirement and cycle CSRs in different orders at start and stop. Its historical evidence is retained without reinterpretation. New comparative CoreMark firmware uses one write to PERF_SNAPSHOT at each boundary and reads the resulting frozen 64-bit cycle and retirement values and cache counters. This provides a common interval for CPI. The unchanged peripheral snapshot mechanism has a separate wrap, backpressure, and atomicity test; the RTL observer checks both boundaries against pre-edge counters.

Upstream CoreMark remains pristine at the commit in dependencies/COREMARK_LOCK.json. The external port is derived from the project's existing port, with provenance hashes and an explicit preparation script. CPU RTL is not changed by this amendment. V0 uses performance inputs; V1 uses validation inputs. Their instruction counts and cycles are not expected to match each other. Each A/B pair uses the same firmware bytes, reset state, memory image, and configuration. Compilation follows v2, including xPack GCC 10.2.0 and RV32IM/ILP32; memory follows v3 (64 KiB with 16 KiB reserved stack).

Initially run ten iterations of each configuration to validate CRCs, UART, counters, stack bounds, and matched execution. These short runs are not reportable CoreMark scores. Three repetitions per variant use AB, BA, AB ordering. Subsequently use a duration sufficient for the ten-second benchmark rule for any score-bearing result, and separately satisfy physical timing and board-validation gates. A firmware time-conversion constant is configured frequency, never an independently measured clock. RTL cycle ratios do not establish physical throughput or resource efficiency.

The observer also counts resolved frontend redirects, eligible priming opportunities, instruction request stalls, outstanding fetch waits, and frontend barrier cycles within the same snapshot interval. Redirect classes are conditional branch, JAL, JALR, trap, MRET, FENCE.I, and other, with memory-stage flush priority. These are frontend events, not all retired branches. Eligibility is measured within each variant's own schedule, so equal event totals are not assumed. The observer is simulation-only and must not be included in synthesized resource comparisons.
