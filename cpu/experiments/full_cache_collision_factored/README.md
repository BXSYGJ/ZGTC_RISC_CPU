# Current-core cache collision factoring

## Scope and measured reason

This isolated candidate builds on full_raw_relation_payload. That parent fails full-ILA timing at both tested placements: seed 1 uses 9458 LUT / 5089 FF / WNS -0.066 ns; seed 2 uses 9509 LUT / 5082 FF / WNS -0.092 ns. No additional blind placement seeds are started for that parent.

The seed-1 limiting path reaches synchronous_writable.forward_way1 through data-cache tag/hit logic, load-address bypass and read-index comparison. The new candidate moves collision comparison before the store/read-index multiplexers: a store hit compares the saved request index with the incoming request when ready, while a refill compares victim/beat with the saved request. Store hits occur in LOOKUP, refills in FILL_DATA; runtime assertions check the state assumptions and equality with the original collision equation. Storage, byte merging, refill errors, writeback, cache geometry, request handshaking, clock and software remain unchanged.

These predicates reuse the earlier cache_collision_forward experiment rather than inventing a new algorithm. Its older 135 MHz implementation failed overall timing; that is not evidence of success here. This is a newly tested combination with the later core, banked validity and error handling, motivated by the actual current limiting path.

Only rv32_cache.sv is new RTL in this directory. candidate_sources.py explicitly selects the unchanged core/predictor from full_raw_relation_payload and other files from full_redirect_clock151200; each simulation/physical staging captures actual source bytes and verifies their identity.
