# 架构修订：音频适配、软件UI、UART启动与片上存储

> 最终交接入口：[正式开发交接总规划](HANDOFF_DEVELOPMENT_MASTER_PLAN_20261104.md)。任务优先级与性能取舍以该文档为准。

日期：2026-11-03。修订上份双模式规划；本轮为实测审计与设计，未修改生产RTL、未运行新PDS/烧录。

## 1. 决策变更

- 缩小模型不是必要前提。优先修复真实推理可观测性与片上存储结构；保持现有模型作为精度/数值基线，缩小仅在吞吐或存储仍不达标时实施。
- 前端优先验证24k路径，同时保留48k原生对照；不以16k必然更优为假设。先锁定信号时间/频率语义，再重训或以精度验证决定输入转换，不给旧模型直接换频谱。
- 新正式系统必须支持CPU软件改变文本、位置、颜色、概率条/波形/频谱布局；不再通过改Verilog/ROM字库表来修改常规UI内容。
- 应用程序从UART加载到可执行RAM，不再随位流固化完整业务固件。保留最小只读bootloader用于复位入口与故障恢复；“应用不进ROM”不等于系统完全没有ROM。
- 大容量数据以DDR为主，片上保留实时计算/扫描的必要工作集；禁止把每周期依赖的行缓存直接改为DDR随机读。

## 2. 为什么缩模型不一定省硬件

现有卷积计算通路按16 lane复用，改变网络通道数主要改变迭代次数、DDR权重/activation容量和流量。若并行MAC数、RAM最大深度和物理端口保持，LUT/APM/DRM不一定显著下降。

缩模型能省的部分必须具体落实：把最大行宽/通道数参数缩小才能缩行缓存；把最大tap数缩小才能缩wbuf；减少输出channel只能减少DDR数据和执行时间时，应如实报告，不能称FPGA资源同比下降。当前更直接的收益来自跨层互斥缓存共享、lane打包和小表去复制。

决定保留原模型的条件：完整top时序通过、片上余量够新增CPU/UI功能、实测整窗吞吐满足要求、板上数值正确。否则先比较降几何/降存储与改小模型的代价，再决策。

## 3. 音频究竟如何适配模型

当前模型吃的是量化log-Mel时频图（频率×时间），不是原始I2S、波形截图，也不是任意FFT幅度图。生产八类是64×258的uint8特征；五组现有资产是64×130、使用自己的尺度/zero point。通道选择、PCM幅值/符号、采样率、STFT/Hann、FFT、Mel表、log/dB、归一、量化、帧顺序都是模型输入契约。

PCM1808仍按48k接收：I2S输入不因模型选择16/24k而要求模块改时钟。硬件接收后做抗混叠FIR再整数抽取：48→24为2倍，48→16为3倍；不可以简单隔点取样。先以单声道计算，左/右/混合策略训练与板上保持一致。是否保留24位全部精度或截为16位由已定义PCM缩放契约决定。

| 路线 | 有效频带上限（Nyquist，实际通带略低） | 前端代价 | 评估 |
|---|---|---|---|
| 原生48k | 24kHz | 无数字重采样；FFT较大 | 最少转换，保留高频作参考 |
| 24k | 12kHz | 2倍抽取FIR，FFT可降到1024 | 建议优先候选，通常保留较多音色谐波，但须实测 |
| 16k | 8kHz | 3倍抽取FIR，FFT可更小 | 可能足够，也可能损害镲/打击、高音和音色区分，保留对照 |

公平比较示例：48k/FFT2048/hop512与24k/FFT1024/hop256均为42.67ms窗口、10.67ms hop。128帧约1.4秒上下文而非3秒；若保留3秒，帧数也必须相应增加。降低采样率本身不会自动让Mel张量或NPU工作量减半；只有降低FFT、Mel bins、帧数或模型几何才有对应收益。Mel表的fmax不得超新Nyquist；所有表由配置重新生成。

先比较48/24/16k的float精度、逐类召回、弱音/噪声/混音，再冻结INT8和RTL。可把24k频谱重映射到旧输入当诊断对照，但不能当无需验证的正式兼容方案；丢失高频或改变归一语义时通常需要重训/微调。F2是更有价值的候选实验，不是未经数据评测就选中的最终架构。

## 4. 真实DRM占用审计

这里是片上DRM（厂商块RAM资源），不是板外DDR动态内存容量。来自下午真实推理1497FAF4的完整综合映射报告，与device_map总量150.5一致。统一按DRM36K等价计数：一块18K计0.5，36K计1；器件总量155。

| 模块 | DRM等价数 | 原因/处理优先级 |
|---|---:|---|
| Mel/FFT整个前端 | 32 | 其中整窗谱8.5，FFT延迟/输入/旋转表约18，其余framer/Mel；优先较小FFT与整窗谱DDR化实验 |
| 激活暂存store0+store1 | 32 | 各32个lane小bank、每bank最少占18K，物理碎片大；先审查生命周期是否允许共享/打包 |
| 卷积行缓存 | 19.5 | 四层各三行bank并存；互斥层可尝试共用最大工作集，保留计算局部性 |
| 显示谱双页 | 16 | 每页16512B跨16384界，被映射为32768深的8个36K；边界拆分/较小显示图/DDR分页优先 |
| UI文字/字库 | 12 | ascii索引12份18K=6，字模4，tile2；解决并行查表复制再考虑DDR |
| 池化缓存 | 8 | 多bank端口需求；先共享/压紧真实尺寸，不直接逐像素DDR读 |
| 权重工作缓存wbuf | 8 | 1728×128bit，约27KiB；权重本体已在DDR，缓存为MAC复用所需 |
| DMA参数缓存wdma | 8 | bias/M/shift宽bank和小深度导致碎片；可压紧/小LUTRAM/寄存器或tile预取 |
| CPU | 6 | 8KiB指令ROM两份各2块，8KiB数据RAM2块；改boot+RAM/DDR取指需重新分配 |
| PCM1808重采样 | 4.5 | 系数与历史；原生48k能省此模块，24k仍需更简单抽取滤波，不可将4.5全算净节省 |
| 波形显示列包络 | 3 | 当前显示工作集；可降列数/分辨率后放大，保留小片上读缓存 |
| CDC/HDMI/softmax | 1.5合计 | audio CDC、HDMI、softmax各0.5 |
| 合计 | 150.5/155 | 97.1%，几乎没有新增软件UI/缓存余量 |

完整加总与逐memory明细见 reports/drm_storage_audit_20261103.json。该数据是旧版实际结果，优化收益均未经过新综合，不得直接相加作为新资源结果。

store每份逻辑194×32字节约6.06KiB，却用了16个36K等价资源；这是32路独立bank的最小块粒度问题。目标不是把它全改成单bank然后丢失写吞吐：先核实每周期写lane/读宽、用串并转换/宽bank加byte enable或小LUTRAM实现；任何节省要与吞吐和时序一起验证。

UI ascii表逻辑128×8，仅128B却因并行读端口复制12份18K。可以由CPU事先把数字转换成glyph ID，或在blanking期串行格式化写入tile，像素侧只读最终glyph。无需搬DDR就能消除多数多端口复制。

## 5. 什么应该放DDR，什么留片上

| 数据 | 目标位置 | 原因/动作 |
|---|---|---|
| 两模型全部权重 | DDR，已如此 | 不再把它当尚未外移的大头；片上仅权重tile/cache |
| PCM环形窗/长测试录音 | DDR，生产PCM已如此 | 保留小CDC/FIFO，测试流有独立区 |
| 整层activation | DDR，已有replay | 继续保留；优化的是片上row staging而非再搬整层 |
| 完整log-Mel/中间谱 | DDR候选 | 替代整窗片上多遍存储；用tile/burst读写和小缓存；精度语义不变时可以先不重训 |
| 历史显示谱、图像/字体资源库 | DDR | 像素侧使用预取、glyph/tile/scanline cache，不直接随机阻塞扫描 |
| 应用代码/大数据/heap | DDR目标 | 需新增CPU DDR总线桥/取指小缓存与仲裁，不是改linker即完成 |
| 卷积三行、FFT实时延迟、权重tile | 片上工作集 | 每周期计算依赖；优先共享与缩尺寸，DDR只负责批量补给 |
| 音频异步FIFO、HDMI行FIFO、boot/小stack | 片上 | 时钟隔离、确定性响应、故障恢复必须保留 |

DDR搬运必须给音频/视频预留服务预算，NPU突发有长度上限与公平仲裁；DDR IP读数据无法反压，必须在发读命令前预留接收FIFO。新增CPU/显示主设备不能破坏现有m0..m3契约，应统一仲裁和地址图，而不是复用别人的地址/端口绕接。

## 6. CPU软件可改UI：采用场景描述，不先上全屏软件绘图

推荐CPU维护scene/text/tile描述符：文字glyph序列、位置、颜色、矩形、概率条值、波形/频谱区域和缩放、显隐/模式状态。通过MMIO或DMA写back bank，frame boundary一次commit，active bank由pix域只读。CPU控制内容与布局，硬件负责1080p扫描、字模取样和实时图表，避免RV32I逐像素绘图。

普通改文字/颜色/坐标/8行或5行/区域大小不重新PDS；新增硬件不支持的图形算子、视频分辨率或PHY仍需位流改动。字库可从软件资源包加载到DDR/glyph cache，首次支持约定字符集合，不能承诺任意Unicode字体无需资源。

接口至少包含ABI版本、场景长度/上限、描述符类型、坐标/裁剪、颜色、资源地址/长度、frame_id/mode_epoch、commit与ACK/error。CPU先检查资源范围，硬件限边界；禁止坏描述符读穿模型权重。UI CDC使用bank/toggle握手，复位与跨模式提交测试必须覆盖。

不建议第一步全屏framebuffer：1920×1080 RGB565单帧约3.96MiB，60Hz扫描仅有效像素约249MB/s；32bit像素约498MB/s，均未含写屏/突发低效/仲裁。软件场景只更新低频描述符，吞吐明显更低。以后确需图片背景，可加DDR图层+行缓存，不要求CPU每帧重画全部像素。

验收：同一bit加载两个不同UI应用/资源包，文字、布局、颜色、5/8模式改变；波形/频谱仍由真实采样更新，无撕裂/underflow。不允许两套bit分别显示不同UI来声称软件UI通过。

## 7. UART加载应用与启动

当前CPU只接TX FIFO，没有可供软件接收应用的UART RX MMIO；没有CPU DDR访问接口。现有UART权重loader写DDR不等于CPU能执行DDR程序，必须显式新增。

推荐复位链：最小片上boot ROM→DDR初始化/自检状态→UART接收APP镜像→校验→写入可执行RAM/DDR→处理取指缓存一致性→设置stack/entry并跳转→APP配置UI和模型。boot保持故障恢复路径，不把完整业务应用固化ROM。应用/RV ABI/内存图/header/版本/长度/entry/CRC32是独立契约，与权重和PCM注入帧使用类型字段分流。

两步实现：先UART加载小应用到片上可写指令RAM，证明收包/校验/跳转/恢复；再提供CPU DDR桥与小取指缓存，应用/资源主驻DDR。第一步可使用独立实验build，不承诺在已经150.5/155的旧top直接增大SRAM。正式最终架构以统一预算重新构建，淘汰复制的整份应用ROM。

协议覆盖chunk序号/长度/CRC/ACK、超时重传、重发去重、地址/entry边界、镜像整体校验；收包未完成不执行，掉线可重开会话。应用上传前有限停推理/停止DMA、原子切换，不能边写当前取指区边执行。先无cache或明确invalidate；若使用fence.i必须核对当前RV核实际支持，不把指令存在当硬件已实现。

CPU DDR桥最初采用单outstanding、非缓存数据访问和小只读指令cache，减少一致性面；NPU/UI共享数据通过显式flush/快照约定，禁止暗含cache coherent。boot/DDR错误时可通过片上UART报错，不依赖尚未可用的DDR代码。软复位后应用可保留但必须重新确认完整性/有效标记，不保证掉电保留；掉电自动启动另由Flash任务解决。

115200bps 8N1理论约11.52KB/s，64KiB应用约5.7秒、256KiB约22.8秒，实际另加协议开销。提速到更高波特率需验证，不默认线路支持。UART资源包/模型和应用共用协议仲裁，不能两个host程序同时占COM口。

验收：不重烧bit，上传App A与B，能改变UI及模式；错误CRC/非法入口/断包不跳转、恢复后可再次成功；应用trap有可读错误和受控恢复，不能靠重烧位流维持日常调试。

## 8. 修订后的并行顺序和门槛

1. 存储/数据流审计与旧模型已知特征板测并行：先解决恒小号可定位性，不等待新模型。
2. 音频24k/48k/16k实验独立推进；按精度冻结前端。模型缩小只是可选支线。
3. CPU/UART启动与软件UI团队先冻结总线/ABI；显示团队可用仿真CPU写事务独立验收scene渲染，CPU团队先串口RAM小程序，不互相等待完整NPU。
4. NPU/存储团队优化row/store共享、参数bank与显示数据布局，提供同模型逐层golden、吞吐和新map节省证据。UI格式化去复制可先做，不依赖降采样。
5. 集成负责人统一DDR地址/仲裁/调试接口，合入CPU/UI与两模型；单PDS资源门控和十表时序后，按feature→PCM→I2S三层做整板对拍，最后真实PCM1808。

并行任务按模块独占编辑，顶层与总线由集成负责人统一；一次一条PDS、一次一个UART/JTAG持有者。规划没有授权并发下载服务，绝不重启/杀死/新增cdt_js或操作既有cdt_cfg。

新功能增加DDR桥/取指cache/软件UI，原1–2周估计不应沿用为承诺。建议按2–4周工程量级重新排期，首个最小UART应用+可配置UI先交付，再集成双模式；真正进度由各阶段仿真/新资源/时序/板测证据决定。Flash固化作为随后独立阶段。
