# 硬件适配模型与双模式真实推理开发规划

日期：2026-11-03。性质：后续开发执行计划；目标与预算是拟定验收条件，不是已完成结果。实时进度仍只认 STATUS.md。

> 后续修订：用户要求软件可改UI、UART加载应用、优先存储架构优化；缩小模型不再是前置条件。具体决策及实测DRM分解见 [架构修订与存储审计](SOFTWARE_UI_BOOT_AND_MEMORY_ARCHITECTURE_20261103.md)。本文件涉及“轻量模型优先”的表述以该修订为准。

## 1. 任务目标与范围

1. 从 PG2L100H、PCM1808、现有 DDR/时钟能力出发重新选择和训练模型，避免继续照搬不适合硬件的训练前处理和大网络。
2. 简化为一套音频前端、一套可调度 NPU、一套 RV 控制与 UI，支持八类单标签识别、五组独立活跃度两种运行模式。五组模式保留已有独立主导头的兼容能力，是否默认显示主导组不妨碍五路活跃度验收。
3. 仿真先行，最终必须在真实 FPGA 上用确定性 I2S 输入完成数值对拍，并用 PCM1808 实际音乐完成准确性测试。不能以 done、WOK、显示有变化或一次正确分类代替推理验收。
4. 正式推理开发与紧急曲线演示隔离；保留当前可用演示、下午版冻结源码及全部失败证据。此次不把 Flash 固化、五类新 UI 美化当推理正确性的前置任务。
5. 实施位于 XSY 的 instrec_fpga/；不得改 CPU 历史用户 diff、PCB、obj_dir。不得改写 releases/pacerv-instrec8-20261103 的冻结基线来冒充新成果。

| 项目 | 已有事实 | 尚不能推出的结论 |
|---|---|---|
| 真实八类板测1497FAF4 | BOOT/DDR自检/WOK通过；30秒10轮完成、CPU ACK，无超时 | 全部top1=6；未证明识别正确 |
| 正式版时序 | core setup -1.071ns、338端点 | 未收敛，可能影响计算；尚未证明是恒小号根因 |
| CPU/NPU联合仿真 | 两轮不同特征、无reset、逐层golden通过 | 未覆盖实际I2S→完整前端→物理DDR→NPU整板数值 |
| PCM1808独立板测 | 48k输入、44.1k输出、非零动态样本、无overrun | 不代表正式整机输入特征正确 |

先做受限根因定位，避免把旧问题带到新架构；不以旧大模型全部修好作为模型实验的串行前置。

## 3. 双模式可行性与难度

推荐第一版采用“同一位流、两套模型镜像、共享算子、一次执行一个模式”。两个模式可有不同权重，但必须落在同一有限算子和形状集合内。DDR容量允许时驻留两套镜像，否则切换时加载对应镜像；先核实真实地址图和DDR容量再锁定。

| 路线 | 优点 | 难点 | 决策 |
|---|---|---|---|
| 两个独立骨干，串行复用同一NPU | 可分别训练，精度风险较低；硬件无需复制 | 镜像/描述符与安全切换；不能随意支持无限网络 | 首选落地路线 |
| 共享骨干，8类头+五路activity头+可选dominance头 | 双结果可共用一次特征提取，权重更少 | 不同标签/数据域，需联合训练和缺失标签mask；可能互相损害 | 精度实验胜出后才采用 |
| 两套完整NPU并行 | 两任务同时计算 | 现有DRM接近上限，时序和调试复杂 | 本轮不采用 |

双模式控制本身中等难度；重新训练/量化、前端契约和真实板测是主要难点。已有五组大模型不能简单改成5个softmax输出：activity是5个独立sigmoid，不要求和为100%。八类仍为单标签softmax。若保留主导结果，使用独立dominance head与activity mask，不用activity argmax冒充主导头。

## 4. 模型与前处理的硬件适配策略

模型缩小作为可选对照实验。先优化缓存共享/端口/搬运，原模型若满足资源、时序和吞吐则保留，不因资源接近上限就默认重训小模型。

### 4.1 先建立统一输入契约

PCM1808当前实测输出48kHz。优先比较下面三条路线，必须用相同录音/固定split评估，不能只比较不同数据的准确率。

| 候选 | 前端 | 硬件影响 | 进入下一阶段条件 |
|---|---|---|---|
| F0兼容基线 | 48k→44.1k，现有2048 FFT/64 Mel | 保留旧重采样器，用于定位和参考 | 仅作基准，不默认继续扩大 |
| F1首选简化 | 直接48k、2048 FFT、64 Mel，统一约128帧输入 | 删除48→44.1k多相重采样；重生成频率/Mel表和训练特征 | 留出精度/弱音性能达标，完整前端golden一致 |
| F2进一步压缩 | 48k→24k或16k，较小FFT/Mel与统一帧数 | 更小FFT与带宽，但仍需抗混叠降采样滤波 | 八类尤其高音乐器与五组打击精度达标，否则淘汰 |

128帧是候选，不是已冻结设计：需明确窗口时长、hop、center/padding、首末帧规则。先比较1.5秒与3秒上下文对准确率/响应时间的影响，再由训练配置生成RTL常量。所有模式优先共享采样率、FFT/Mel、归一与输入几何；有必要差异时必须显式版本化。

不能直接删除：ADC自身抗混叠措施、降采样抗混叠滤波、模型依赖的Mel特征算子。可以消除的是不再需要的采样率转换、重复滤波/重复缓存和未被证明有收益的处理。所谓“卷积滤波器过多”通过减少通道/层数并重训解决，不能删权重后沿用旧模型。

### 4.2 归一化与算子简化

- 评估固定训练集均值/方差或固定仿射量化，替代现有整窗max/均值/方差的多遍处理；必须实测音量变化、静音、噪声和设备差异，不因硬件省事直接改变语义。
- BN折叠入卷积、INT8权重/激活、int32累加、逐通道requant；保留round-half-even、输入zero point与padding契约。
- 统一使用已有可验证算子：普通3x3/必要1x1卷积、ReLU、2x2池化、GAP、小FC。不引入训练方便但RTL缺少的动态算子。
- 深度可分离卷积另列实验：MAC下降不等于当前硬件延迟下降。只有精度收益、真实调度/DDR流量收益成立才增加专用算子。
- 不强求CPU处理音频逐样本乘加。CPU负责模式、快照、后处理、异常与UI，FFT/卷积由硬件承担。

### 4.3 网络候选与选择

保留旧1→48→96→192→256模型作为teacher/参考，不作为新资源目标。至少训练三组普通卷积候选：16/32/64/96、16/32/64/128、24/48/96/128；通道按16分组，最后GAP后直接小分类头，比较是否需要隐藏FC。网络层数/池化次数随精度实验确定，不预先承诺最小网络必然够用。

两套独立模型先分别建立精度基线，之后再比较共享骨干多头。可用teacher蒸馏，但需要实测，不能用蒸馏替代真实标签。类别表固定来源且带hash；演示曲线的八类顺序与正式模型不同，绝不能混用。

### 4.4 数值和精度门槛

- 按原始录音/来源分割，禁止相邻窗口跨train/val/test泄漏；训练split校准，验证split选参，独立test只在冻结候选后报告。
- 八类报告macro-F1、balanced accuracy、逐类recall、混淆矩阵、静音/未知音行为。五组报告逐类precision/recall/F1、macro/micro-F1、PR-AUC、多活跃/无活跃；subset accuracy只作补充。
- 建议准入：INT8相对同结构float的macro-F1下降≤2个百分点，轻量候选相对旧模型参考下降≤3个百分点；任何单类recall下降>5个百分点必须分析并显式决策。旧基线若不可靠，先重测，不编造绝对准确率目标。
- 打击乐现有数据正例稀少，单列支持数与置信区间；需要补数据时记为外部依赖，不用总体分数掩盖。
- sigmoid阈值在验证集确定且版本化；默认先0.5，不能在测试集调阈值。平滑/迟滞默认关闭，另报引入后的响应延迟。

## 5. 推荐系统架构与简化边界

```text
PCM1808外部I2S / 内部确定性I2S源（互斥）
  → 同一生产I2S接收器 → PCM快照/CRC → 共用前处理 → 特征快照/CRC
  → 共用NPU(conv/pool/GAP/FC) → 完整logit快照
  → RV32I后处理/模式管理 → 原子UI提交/串口报告
DDR：独立模型镜像区、activation区、音频/调试区，统一地址图
```

- 用生成的有限模型描述符替换散落几何常量；第一版只允许审核过的两套模型，不做任意神经网络解释器。
- 一个权重DMA/FC引擎/行缓存体系；按生命周期复用scratch RAM，显示只保留必要双缓冲，不保存多份相同特征。
- 设资源设计目标：DRM≤124/155（80%）、LUT≤46620/66600（70%）、APM≤168/240（70%），给时序/调试留余量。超过属于评审门槛，不假称器件放不下；必须用完整top映射核验。
- 同步RAM模板与分拍优先；降低合理核心频率是允许的时序手段，但先计算实测窗口吞吐，不盲目追频。
- 处理时间必须低于约定窗口提交周期并保留≥20%余量；以整板cycle/丢窗计数测量，不以理论MAC替代。

### CPU/MMIO与模式切换

CPU读取model_id、mode_id、frame_id、输入与权重CRC、全8/5/双头logits、完成/错误码和cycle。结果寄存器用bank或锁存握手形成完整快照，不能只读last_p。UI提交同一frame_id的完整向量。

模式切换状态：REQUEST→停止接收新推理请求→当前事务完成或受控abort→清旧结果与epoch→选择并校验镜像/描述符→等待完整新窗口→RUN。禁止忙时改权重基址；切换后的结果必须带新mode/epoch。非法模式、镜像CRC错误或不兼容前端应显式拒绝。首版切换可丢弃一个窗口，但必须计数和显示等待状态。

八类CPU执行stable softmax/argmax，五组执行五路sigmoid及阈值判定；保留dominance时再做其softmax/mask。RV32I无FPU，用定点LUT/整数运算并测cycle；是否打开M扩展由资源和后处理预算决定，不为展示CPU而搬卷积到软件。

| P3RTL单元/联合 | 几何/共享引擎/双模式/MMIO；真实RV固件参与 | 每层逐元素匹配；连续A/B无reset、切换/异常测试通过 |
| P4整top仿真 | 序列化I2S→生产接收/前端→DDR事务模型→NPU→CPU→UI | 至少各模式3个不同完整输入、静音、模式切换逐级CRC/结果匹配；不把feature注入当全链通过 |

| P6确定性板测 | 板上I2S源→生产接收→真实DDR/NPU/CPU；逐级抓取 | 与同一PCM的整数golden全链一致；类别正确不是唯一标准 |

P0与P1并行。P3允许对已冻结子契约推进，但数值未定的生产RTL禁止大面积返工。P5之前必须有P4；P6数值不对时停止准确率宣传，抓首个不一致点。

## 7. 板上模拟I2S与定位流程（核心验收）

### 7.1 三层注入，分别回答不同问题

1. feature注入：UART/DDR写入已知uint8特征，绕过音频前端，仅验证NPU+物理DDR+CPU数值。至少选八类不同预测样本、五组单活跃/多活跃/全无活跃，不能用全零特征代表模型正确。
2. PCM注入：已知PCM送前端入口，验证FFT/Mel/归一+NPU。用于与第一层差异定位，不宣称I2S接收已通过。
3. I2S串行注入：板内ROM/DDR PCM播放器生成BCK/LRCK/DATA，经生产接收器到全链，真实DDR与CPU参与。这是确定性系统验收；必须记录注入点，不能用上游旁路数据覆盖接收结果。

### 7.2 板内I2S源设计

- 通过受控mux在接收器前切换内部源/外部PCM1808，外部接口BCK/LRCK始终是输入；内部源不驱动紫卡外部时钟脚，不与PCM1808争用。
- 格式固定为生产接收支持的Philips I2S：明确24bit有效位、32bit slot/声道、64 BCK/立体声帧、LRCK翻转后一bit延迟、采样沿与符号扩展；如实际模块不同，按观测冻结而非猜测。
- 用独立于core的音频时钟域生成串行信号，覆盖相位偏移/不同起始边沿；片内同源测试不能证明引脚电气或全部异步边界。
- 短向量放ROM；整段录音通过UART加载到独立DDR区后按真实音频速率播放。用小双缓冲FIFO隔离读延迟，记录underrun；不得用理想零延迟ROM掩盖DDR争用。
- 48k精确时钟优先独立音频PLL/外部时基，先审计PLL余量；若用27MHz分数使能，只作为带抖动功能测试，单独报告平均采样率/周期抖动，不冒充精确48k外部源。
- 可选物理环回：由审核后的空闲IO输出测试时钟/数据，用跳线送生产I2S输入；必须先断开PCM1808的对应输出，核实3.3V、引脚、地线。不能默认用户已接跳线，也不能直接驱动ADC输出线。

### 7.3 测试向量与比对点

基础：全零、正负常数、脉冲、左右不同序列、walking-bit/PRBS、单频/双频、幅度阶跃、录音片段；异常：半帧启停、断BCK、LRCK卡死、左右错位、恢复、溢出。用可辨认L/R序列先排除声道/符号/位移错误。

按顺序捕获：I2S接收PCM→重采样/降采样PCM（若保留）→FFT/选定Mel中间值→最终量化feature→各层activation→GAP→logits→CPU概率/阈值→UI快照。完整阵列可分多次确定性重放导出，不要求所有debug RAM同时驻留。CRC是定位工具：发现差异后必须导出实际字节找首个不一致点，不能只报CRC失败。

调试路径：feature注入就错→查权重/DDR/NPU/时序；feature正确而PCM注入错→查前处理；PCM注入对而I2S注入错→查格式/CDC/采样；所有整数对拍正确而真实分类差→查模型数据域/训练/归一。各分支有证据才下结论。

每轮保存bit/source/model/weight/vector/contract hash，输入采样率/幅值、输入源、reset与mode epoch、逐层比对、UART原文、完整STA和资源。时序失败时只能记故障复现，不作为通过的生产基准。

## 8. 并行调度要求与共享资源纪律

后续实施必须使用有边界的并行任务，禁止多人同时编辑同一生产顶层。下表是执行分工要求，本次规划阶段未启动训练、PDS或烧录。

| 工作流 | 责任/独占编辑范围 | 可并行时间 | 交付/依赖 |
|---|---|---|---|
| A模型与数据 | 新模型目录、训练/评测脚本、数据manifest | 立即，与B/C并行 | F0/F1/F2实验、双模式指标、冻结契约给C/D |
| B旧故障与可观测性 | 独立诊断testbench、快照/注入模块草案 | 立即，不改冻结release | 复现恒小号、定位首个数值差异；与D约定MMIO |
| C共享NPU/存储 | NPU内部、形状生成器、单元回归 | 契约稳定后 | 通道/几何支持、资源估算，交集成负责人 |
| D CPU与I2S测试 | instrec本地固件、MMIO协议、内部I2S源与测试 | 先协议/仿真，后接C | 定点后处理、模式状态机、I2S注入/恢复回归 |
| E集成与构建负责人 | 顶层接线、约束、构建清单、STATUS/证据 | 汇入已验收提交 | 全链仿真、唯一PDS和唯一板级会话、最终验收 |

并发能力有限时先A/B/D，契约冻结后B转C；集成负责人统一合入。各任务使用独立build标签/输出目录；GPU训练独占或有显存配额，禁止两进程互相OOM。共享文件修改先约定归属。

PDS全机只允许一个有效流程，禁止并发综合/PNR。每阶段记录日志/CPU/内存/进展和截止；compile/synth/map初始总预算30分钟、PNR120分钟，超时先保存证据再仅处理本轮PDS进程，不动cdt_js/cdt_cfg。截止可在启动前依据规模调整，不能无记录无限延长。JTAG/UART同一时刻一名负责人持有，训练与纯仿真可继续。

每日/每阶段交接必须包含完成项、失败项、阻塞、下一步、文件hash与精度/仿真/时序/板测四类独立结论。禁止用仿真通过替代板测，禁止用板上跑完替代准确率。

## 9. 工作量与优先级评估

以下为工程工作日估算，非完成承诺；训练数据/算力、FTDI掉线、PDS长尾与新前端精度均可拉长。

| 工作包 | 初估 | 最大不确定性 |
|---|---|---|
| 旧故障复现与注入/快照最小链 | 1–3天 | 物理DDR/时序问题与可观测性不足 |
| 前端/轻量模型搜索、重训、INT8 | 3–7天 | 数据覆盖、共享骨干负迁移、稀少类别 |
| 参数化NPU、CPU双模式、联合仿真 | 3–6天 | 形状硬编码、RAM推断与快照一致性 |
| 新源PDS、确定性整板与真实音频 | 2–5天 | 时序/下载器/真实前处理差异 |

可并行后的首个可靠双模式版本按约1–2周量级规划，若需补数据或重做前端应预留2–3周以上；不是把各项最短时间简单相加，也不保证首轮模型即达标。单模式已知向量板测必须先于双模式演示发布。

优先级：P0可定位性与固定向量 → P1/P2硬件适配数值真源 → P3/P4双模式全链仿真 → P5/P6时序通过的确定性板测 → P7真实音乐 → P8耐久。Flash在稳定镜像/header/恢复协议冻结后再接入，避免固化错误模型。

## 10. 最终交付清单与禁止跳过项

- 两模式功能规格、统一前端/类别/输入输出契约、模型镜像版本与地址图。
- 数据split和样本来源manifest、float/INT8精度报告、逐类指标与失败样本；只读原始训练资产。
- 可重建训练/导出/量化流程、确定性整数golden、RTL测试与同源bit/hash。
- 完整top资源表及十表STA全部通过；外部I/O/异步时钟约束清单和未验证边界单列。
- feature/PCM/I2S三层注入的整板比对报告、真实音乐双模式结果、切换/恢复/耐久报告。
- 当前演示与冻结下午版完整保留；生产系统UI明确区分采样中/推理中/有效结果/错误，禁止加载预设曲线冒充模型输出。
- 在STATUS明确写出“数值正确、精度、时序、板测、耐久”各自PASS/FAIL/NOT_RUN，任一缺失不可宣称整个系统验收完成。
