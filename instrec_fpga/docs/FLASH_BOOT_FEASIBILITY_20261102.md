# 位流与权重固化可行性评估（2026-11-02）

## 结论

可以作为增量功能，优先利用现有板载Flash，不先增加器件或改PCB。位流持久化难度低至中，权重自动加载难度中至高，关键是配置专用时钟在用户模式下的访问，不是Flash容量。此评估不代表已经固化，也未进行Flash扫描、擦除、写入或新的PDS构建。

## 已核对硬件

100Pro配套核心板原理图第3页标注U15/SPI0与U9/SPI1两颗W25Q128JVEIQ或XT25BF128FSSIGU-W，均128Mbit（16MiB）；实物是否均焊接及JEDEC ID未读，不能当板级检测结果。两颗共享SPI_CLK，连接FPGA CFG_CLK H13。图中主配置模式标注001/MSPI。完整页面已渲染并视觉核对，hash见reports/flash_boot_feasibility_20261102.json。

当前2673246E位流文件3791112B，八类权重镜像691040B；五类双头纯INT8权重716976B，完整新镜像还需加bias、逐通道requant、头部与对齐。容量足够考虑位流和模型共存，但必须依据实际芯片、SFC配置镜像范围和扇区大小规划分区，不可把.sbit与权重简单拼接后盲写。

历史CPU工程记录过普通IO无法布局H13，且flash.fdc是占位引脚，因此旧软SPI控制器不能直接搬用。历史记录不是对当前100H用户模式Flash通路永久不可用的证明。当前PDS提供GTP_CFGCLK（CLKIN、CE_N）且有Logos2映射文件，是可验证候选；仅有库文件不能证明PG2L100H实际用户访问可用。需核对官方原语语义、配置引脚保留/释放选项及CS/data用户映射，再做最小JEDEC读回验证。禁止给H13强行指定普通输出约束。

## 两项功能的工作量

| 功能 | 工作内容 | 难度与条件估算 |
|---|---|---|
| 位流固化 | 确认芯片/启动模式；备份原内容；PDS转换SFC并擦写校验；断电重上电验证DONE/CPU/HDMI | 低至中；工具和板载Flash正常时约0.5至1工作日 |
| 权重固化＋自动加载 | 模型镜像分区、用户模式Flash读、缓冲到DDR、完整性/模型契约校验、启动门控、故障恢复 | 中至高；读通路证实后额外约1至3工作日，包含仿真/重构建/上板 |
| 用户模式读配置Flash不可用时 | 核对厂商原语/配置选项，或增加独立3.3V SPI模块连接已核验空闲GPIO | 需重新估时；不能承诺当天完成 |
| 在线安全更新/A-B槽 | 写擦控制、掉电提交记录、版本选择/回滚 | 独立后续任务，不纳入最小脱机启动 |

以上是条件性的工程投入估计，不是交付承诺。现有完整系统仍有静态时序缺口，新固化功能仍需正常资源门控与时序验收。新三项分拍源153.5/155 DRM，权重不能整体塞入片内ROM；应小块流式加载，片上只留有限缓冲。

## 推荐实现

先固化位流；CPU固件prog.hex、字体及系数ROM已经编进位流，不需要再做独立CPU程序Flash启动。此阶段重新上电可显示和启动CPU，模型仍可通过UART上传。

然后验证用户模式Flash的JEDEC ID与小块只读。优先使用板载第二颗存权重，或在第一颗经工具验证不重叠的独立区域存权重；具体选择待ID和访问确认。不要现在改板或购买外接器件。

建立Flash镜像头：magic、版本、模型ID、完整镜像长度、量化契约标识和CRC32等完整性字段。权重始终从Flash拷到DDR再推理，不改变NPU现有DDR读路径。UART loader的DDR写/读回、master1仲裁与weight_ok门控可以复用，但它当前是UART逐字节握手接口；SPI连续突发需加缓冲/ready，不能把快速字节流直接接rx_valid并假定不会丢数据。现有WOK折叠摘要较弱，不应冒充CRC32或镜像身份校验。

CPU保留监督/状态报告和有限重试角色，批量搬运由小硬件SPI读取器＋DDR加载器承担。当前RV32I只有8KiB RAM且没有模型DDR直接访问接口，不适合为本任务把全部权重先读进CPU本地RAM。读回校验成功才置weight_ok；失败显示错误、保持推理禁止并保留UART恢复加载。首版Flash写入由外部工具完成，不实现运行中擦写。

目标上电序列：Flash配置FPGA → 片内CPU固件启动/PLL与HDMI初始化 → DDR自检通过 → Flash权重读入DDR并核验 → weight_ok → 完整音频窗口到达 → CPU请求/NPU推理/显示。当前真实音源未接，脱机启动验收不等于识别准确率验收。

## 验收与边界

先验证冷启动（真正断电，不能只按reset），下载器不参与配置、电脑不再传权重，CPU/DDR/模型身份/推理与HDMI均有证据。至少覆盖正常镜像、CRC错、模型版本/长度错和UART恢复；错误镜像不启动NPU。保留已验收八类位流及权重，实施时先备份板载Flash内容，避免覆盖原厂启动资产。

本轮只做可行性评估与资料核对，不把“用户建议增加Flash”解释为已经允许擦除未知原始Flash内容。现有SDD把Flash列为范围外；用户新要求可形成后续范围扩展，实施时需同步规格/设计/验收条目，旧范围文字不妨碍当前评估。五类模型迁移仍独立推进，避免把模型误差、启动问题与新Flash接口问题混在一次联调中。
