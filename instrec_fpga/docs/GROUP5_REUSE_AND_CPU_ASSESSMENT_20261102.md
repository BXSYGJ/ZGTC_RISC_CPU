## 模型与容量事实

冻结资产为 models/group5_v3_float_20261102，epoch22的DualHeadInstrumentCNN。重新校验全部资产hash，严格重载冻结float权重后，五个参考样本的activity/dominance logits均逐值完全一致；这只是参考资产完整性，不是新的精度评测。参考向量小，不能用于校准全部网络。已确认兄弟训练工程完整all_features/labels/dominance/mask及train/val split仍在，可只读使用训练split校准，验证split保留评估，无需用户重新提供模型或校准资产。

- 卷积权重650160个，单个head的两层FC权重33408个；双head合计66816个。若全INT8，纯权重716976字节，尚不含bias/requant、对齐及镜像header。旧八类纯权重683952字节，增加33024字节，约4.8%。双头可复用计算器，不必复制完整NPU。
- 输入空间：64x130 → 32x65 → 16x32 → 8x16 → 4x8；旧为64x258 → 32x129 → 16x64 → 8x32 → 4x16。
- 理论卷积MAC从461445120降为231413760，约50.2%；每个FC head为33408 MAC。不能把MAC比例当板上时间或时序保证。
- 现有完整映射DRM147.5/155，余量很小；130帧有望降低特征/激活/显示页占用，但只有去掉固定最大深度后才可能释放DRM，必须用新源资源门控验证。训练权重在DDR，不因多一个head必然成倍增加BRAM。
- config记录训练打击乐正例仅157，分布偏斜。需要独立检查各类及主导组留出集，尤其打击乐、混合/弱主导与无活跃；不能引用activity subset accuracy 0.754当五类主奏准确率。dominance MAE也不是主导分类准确率。

## CPU 当前到底做什么

生产完整顶层显式ENABLE_M=0、ENABLE_PREDICTOR=0，所以当前实例实际是RV32I，尽管封装与固件注释仍称RV32IM。CPU从8KiB ROM运行，8KiB本地RAM，不直接访问模型DDR，也不执行FFT、卷积、FC或逐像素绘制。

固件读取ID/DDR状态，执行ISA与整数工作负载自检，通过NPU_CTRL提交推理请求。默认NPU_ENABLE=0，顶层把CPU请求保持到Mel完整窗口及DDR/权重/owner安全条件均满足才启动；因此CPU确实参与生产链路，不只是观察日志。完成后CPU读top1、最后一个概率事件和cycle，串口报告、清sticky并请求下一窗口。逐层调度、DMA、权重接收、自检与安全FSM仍由RTL控制，UI也直接消费NPU结果。

当前限制：MMIO只暴露最后一条概率事件，不是完整8类向量；报告last_class=7/last_p不是获胜类置信度。CPU没有给UI发布业务结果，也没有做阈值、平滑或主导决策。timeout分支只清sticky、不重试，持续请求恢复策略不完善。ID/ISA失败目前仍打印后继续执行。忙轮询与串口阻塞在慢窗口节奏下可工作，但不算成熟的任务调度。

结论：作为轻量控制核合理，重算子交给NPU也合理；当前应用层职责偏薄，如果项目要展示RISC-V+AI协作，五类迁移正好让CPU承担真正可配置的业务决策，无需为了“CPU参与”把卷积搬回软件。

## 推荐新分工

NPU保留Mel/四层conv/pool/GAP与双FC计算。对同一个GAP向量先后执行activity、dominance两头，提交同一frame ID下的10个定点logits及量化尺度/版本信息。

CPU读取一次完整快照，完成五路定点sigmoid、五路stable softmax、activity mask、主导分布再归一、argmax及无活跃判断。若mask只需阈值，可在统一正scale logit域比较0；真实显示仍需sigmoid。采用定点LUT/整数运算，不要求FPU。五项exp/查表及归一量很小，先测实际cycle预算，不先打开M扩展。两个head本身仍由FC引擎计算，避免RV32I软件执行大量乘加。

CPU再负责可配置阈值、可选时间平滑/迟滞、结果序号/ACK、超时有限重试与错误状态、UART输出，向UI提交完整五组activity和主导结果的原子快照。显示引擎继续纯硬件实时扫描。任何平滑默认旁路，不能把未平滑golden与平滑显示混作同一验收。

需要新增MMIO的完整logit快照/valid/frame ID/双头完成位/commit ACK以及UI输出快照寄存器。现有结果末事件寄存不足以实现这套分工；必须让CPU读取与显示都不会混入相邻帧。

## 实施顺序与通过标准

1. 完成当前八类分拍源资源门控并保留旧基线，当前运行位流不覆盖。五类资产、参数与报告独立命名，避免旧8类回归被新常量悄悄替换。
2. 从训练split采校准集，BN折叠、双头INT8契约/镜像；留出集分别报activity与dominance/主导组误差，并比较float/INT8。先得到可接受的新数值真源。
3. 新130帧前端golden，验证66150样本、reflect、归一及所有计数/DDR版图；参数化conv/pool/replay/GAP。
4. 同一FC引擎串行双头；CPU完整快照与定点后处理先用软件/RTL联合对拍，多活跃/无活跃/近阈值/不同A-B无reset均覆盖。
5. 五类UI复用已验收结构，主导组大字与五路独立activity明确区分；RTL全帧预览后单PDS资源/时序门控，上板启动/WOK/双头CPU/UI闭环，最后接真实音源验收。

最不确定的是新量化精度、固定尺寸散落的修改面及最终时序，绝不能把“8输出改5输出”当完整移植。当前架构适合迁移，预计工作量显著低于从零重做；没有量化留出集结果与新资源门控前不承诺完成时刻。
