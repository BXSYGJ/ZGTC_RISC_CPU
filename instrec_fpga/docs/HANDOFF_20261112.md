## 三、Option A 详细记录（已完成，但劣化）

方法论约束（已遵守）：
- 一次只改一个瓶颈
- 每次改动必须位级等价
- synthesize 确认 block RAM 未退化 → 单编译/综合通过 → 下一步

### B1：activation_row_store_dynamic.v — 写口打拍

**文件**：`src/npu/activation_row_store_dynamic.v`

原路径：`beat[1]` → `cmd_addr`(24-bit 进位链) → `act_cmd_ready` → `mem_we` → DRM WEA

改动：每个 bank 的 `always @(posedge clk)` 内新增三个寄存器 `wd_r / wa_r / we_r`，写命令提前一拍寄存，由寄存器输出驱动 block RAM 写口。

- **位级等价性**：写延迟一拍，但 WDATA 重放 / EMIT 读口都在本行所有写落盘后才触发，无读写冒险。
- **DRM 验证**：单独 synthesize 确认 `lane_bank[N].mem` 仍为 256×8 `SIMPLE_DUAL_PORT GTP_DRM18K_E1`，未退化为 LUT RAM。
- **劣化原因**：真正的违例后来落在 `beats[1]` 的 `done` / `lane[]` 使能链，不是写口路径。

### B2：standardize.v — S_SCAN_Q 拆两拍

**文件**：`src/mel/standardize.v`

原路径：`S_SCAN_Q` 拍内 `qprod_reg`(DSP 输出) → round-half-even → 取负 → +zp → 钳位 → 写 spec_bank（7 级组合）

改动：新增状态 `S_SCAN_QW = 4'd14` 和 `feat_byte_reg`，拆为两拍：
- S_SCAN_Q：计算 feat_byte 并寄存到 feat_byte_reg
- S_SCAN_QW：执行 feat_wr + scan_cnt 递增

- **位级等价性**：feat_byte 值与 addr/data 关联不变，仅延迟 1 拍（+16512 拍/窗）。
- **劣化原因**：真正的违例后来落在 `scan_cnt[12]` → `spec_bank.ADB` 的**读地址**路径，不是写地址。

### B3：dashboard_renderer.v — 波带打拍

**文件**：`src/ui/dashboard_renderer.v`

原路径：`col_min_mem(DRM36K)` → `wave_min` → `neg_magnitude(~wave_min+16'd1)` → ... → `graph_s3`

改动：新增寄存器 `pos_amp_r / neg_amp_r / x_s2 / y_s2 / wave_s2 / wave_ready_s2 / mute_s2`，波带块改用延迟信号。

- 显示路径，波带整体均匀延迟 1 像素，不可见。
- 最轻微违例（−0.381 ns）。

### Option A 总结

三处打拍均通过：
- ✅ `check_rtl.py` — 0 violations
- ✅ `pytest` — 466 passed, 26 skipped
- ✅ DRM 未退化（130/155，84%）

但 **WNS −0.872 → −1.294**，说明 RTL 打拍只是挪路径，没有触及根因（布线拥塞 + 高扇出网）。

### 历史佐证（multi-seed 有效性）

- `a0d347c2` — multi-seed (`pnr -parallel 4 -gplace_seed 7 -seed_step 3`) 在 **iteration 15 即 Unrouted 0**

## 七、真正的违例路径展开（供 Option B 或后续 RTL 优化参考）

### 路径 #1：beats[1] → lane_bank[*].CE

**文件**：`src/npu/npu_top.v` + `src/npu/activation_row_store_dynamic.v`

```
u_npu/u_store0/beats[1]         ← 高扇出 (fanout 206)
  → done (组合输出)
  → u_store0 lane_ce 使能链
  → lane_bank[*].CE
  → 各 bank 的 q 输出（DRM 读口）
  → NPU 下一级 mux / 累加器
Route delay ~7.8 ns | Logic delay ~0.8 ns | Total ~8.6 ns (slack −1.294)
```

逻辑深度仅 ~5 级，但布线拉满了周期（5.798 ns）。
**这是 Option A 没改到的真正热点**。若 Option B 仍不收敛，下一步在 `beats[1]` 的 `done` 输出后加一级寄存器复制（寄存器复制降低高扇出网布线压力）。

### 路径 #2：scan_cnt[12] → spec_bank.ADB

**文件**：`src/mel/standardize.v`

```
u_standardize/scan_cnt[12]      ← 同时驱动多个地址口
  → db_rd_addr (dB RAM 读)
  → feat_wr_addr (feat RAM 写)  ← 已打拍（Option A B2）
  → bank_ra (spec_bank 读口)    ← 没打
  → spec_bank.ADB
Route delay ~6.3 ns | Logic delay ~0.76 ns | Total ~7.06 ns (slack −1.033)
```

逻辑深度仅 3 级。根源是 scan_cnt 扇出 + spec_bank ADB 口布线。
**若 Option B 仍不收敛**：scan_cnt 拆分——db_rd_addr 用 scan_cnt，feat_wr_addr + bank_ra 用 scan_cnt 同步延迟一拍。
