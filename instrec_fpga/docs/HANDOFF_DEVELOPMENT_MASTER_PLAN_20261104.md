# 正式开发交接总规划

日期：2026-11-04。交接目的：接手者据此推进真实推理系统，而非继续完善预设曲线演示。本文件统一后续目标与优先级；实时执行状态仍以 STATUS.md 为准。

## 1. 接手结论：做什么，不重新争论什么

目标是在PG2L100H上实现同位流双模式：八类单标签乐器识别、五组独立活跃度；五组为弦乐/木管/铜管/打击/键盘拨弦，保留此前要求的独立主导结果能力。CPU应用通过串口加载启动，软件可改变UI文字和布局，不因普通业务修改重构位流。优先节省资源而非追求峰值算力，允许牺牲不必要并行度，但必须满足实际音频节奏。

已确定原则：

- 不强制缩小模型。先优化存储/端口/数据流和算子复用；模型规模由精度、实测吞吐与完整资源预算决定。
- 首选评估24kHz/1024FFT，与48kHz/2048FFT公平对照，16kHz作为进一步压缩候选；抽取必须抗混叠，不能直接给旧模型换不兼容频谱。
- 一套前端和NPU，模式切换权重/描述符，不复制两套完整加速器。两套模型独立训练优先，共享骨干仅在数据实验胜出后采用。
- CPU控制业务、模式、完整结果快照、后处理和UI场景；硬件做重算子与像素扫描。应用放可写RAM/DDR，保留最小恢复boot ROM。
- 先仿真再综合，最后必须板上数值对拍和真实音频验收。done/WOK/分类变化/屏幕正常都不能代替识别正确。

## 3. 资源优先，不盲目追求小模型

旧完整top片上DRM150.5/155：Mel32、两组store32、conv行缓存19.5、显示谱16、文字12、pool8、wbuf8、wdma8、CPU6、重采样4.5、波形3、其余1.5。此为映射实际值，不是板外DDR占用。

优化顺序及通过条件：

| 优先级 | 改动 | 期望收益 | 必须验证 |
|---|---|---|---|
| R1 | 显示ASCII预格式化/glyph ID，减少多端口小ROM复制 | DRM/LUT；不改模型 | 五状态全帧、动态内容、CDC/时序 |
| R1 | 显示16512B页拆尾/较小谱图；必要时DDR谱图+预取 | DRM | 图像语义/缩放正确，无underflow/撕裂 |
| R1 | store lane打包、互斥生命周期共享 | DRM，当前两份32块是重点 | 每周期吞吐/端口冲突、A/B无reset逐层golden |
| R2 | 卷积跨层共享三行工作集，pool/wdma压紧 | DRM与路由 | 逐层首次/末行/padding、恢复、完整吞吐 |
| R2 | 共用FC/requant等互斥计算器 | APM/LUT | 控制归属、双头快照、scale/rounding不变 |
| R3 | 16→8 lane对照；4 lane仅在8 lane仍有大量余量时 | APM/LUT、部分端口/缓存 | 同模型数值与完整资源/延迟，不能把lane减半当DRM必减半 |
| R3 | 降FFT规模/前端多遍缓存DDR化 | DRM/APM/处理时间 | 音频前端精度和契约，DDR争用 |
| R4 | 缩模型/降数值位宽 | DDR流量/算量，重配后可省片上 | 重训/量化精度，旧权重不能直接删通道 |

降低时钟主要改善时序和功耗，通常不直接减少资源；降低并行度/复用计算器才是面积换时间。多周期时序例外只能在真实有效使能协议支持时使用，不能用放宽约束掩盖错误。

16/8 lane实验保持模型、输入和契约相同，分别报告LUT/FF/DRM/APM、NPU周期、前端周期、DDR等待、总窗口延迟、音频丢窗与时序。默认软件可配置结果提交周期1秒作为性能评估起点，而非已经确认需求；最终由精度上下文/实测决定。最坏总处理时间≤提交周期的80%；若3秒窗口每秒提交，必须覆盖滑窗/排队，不把3秒窗误当3秒更新。

历史NPU约3236万周期；若实际core125MHz，约259ms，仅作容量估算，不能据此保证8lane约518ms或整系统必满足1秒。先确认实际时钟和各阶段能否重叠。验收资源目标DRM≤124/155、LUT≤70%、APM≤70%，作为留余量目标而非器件硬上限；达不到需评审实测余量，不能伪报通过。

DDR放两模型镜像、PCM窗/测试音频、整层activation、完整中间谱/显示历史、应用代码与大资源；其中前三类已有DDR路径。片上留卷积行/权重tile、FFT必要延迟、小stack/boot、CDC及HDMI行FIFO。直接把热点逐周期随机访问搬DDR通常不划算，采用burst/tile/预取和有界公平仲裁。

## 4. 目标架构、软件边界与待冻结接口

```text
外部PCM1808 I2S / 内部确定性I2S源（互斥、不驱动ADC输出线）
 → 生产I2S接收 → 可选抗混叠抽取 → STFT/Mel/固定输入契约
 → 共用NPU（先16/8lane对照，模式权重可选）
 → 同帧完整logits快照 → RV后处理 → UI场景back bank → 帧边界commit
UART → 最小boot恢复协议 → 应用可执行RAM/DDR → 配置模式/权重/UI
DDR统一服务PCM/NPU/前端/CPU/显示，入口有接收FIFO与地址隔离
```

接手前两天先冻结接口，不先重写大顶层：

- 音频契约：左右/单声道策略、位宽与缩放、48k接收、抽取系数、FFT/hop/Mel/fmax、归一与量化、布局/帧数。
- 模型描述符：mode/model/contract ID、shape、合法算子、权重分段、dtype/scale/zp、CRC、DDR区间。
- 结果快照：epoch/frame_id、输入/权重标识、全8/5/双头logits、cycles/error、valid/ACK；禁止只暴露末概率lane。
- 模式切换：停止新请求→等当前完成或受控abort→选择完整已校验镜像→更新epoch→清旧结果→完整新窗→运行。忙时不得改当前权重。
- UART APP：header/type/version/load/entry/length/CRC、chunk序号/重发/ACK/超时/范围校验；应用/权重/UI/PCM调试帧明确分流。
- CPU存储：最小boot与局部RAM保底；第一步UART可写指令RAM验证启动，最终DDR桥/小Icache/非缓存数据通路；审核实际RV指令/栅栏支持及cache invalidate。
- UI ABI：文本/glyph、位置/颜色/裁剪、矩形/条形、波形/谱图region、mode/显隐、资源长度和commit/ACK。常规布局变更仅更新APP/资源；增加新图形算子/PHY才改RTL。
- DDR：地址图/带宽/仲裁/最大突发、音频与显示时限、读数据不可反压的接收credit。不得把CPU新主口绕接到已有主人使用的区间。

全屏CPU绘图不是第一版目标；1080p RGB565@60仅扫描有效像素约249MB/s。软件描述场景，硬件扫描；两份不同APP在同一bit改变文字/布局/模式是软件UI的验收条件。

## 5. 音频/模型实验边界

24k/1024FFT/hop256与48k/2048FFT/hop512保持约42.67ms窗、10.67ms hop作公平对照。16k可比较相近时间窗的合适FFT/hop，但必须记录差异；不能只改采样率而宣称输入矩阵/算量减半。约128帧对应约1.4秒上下文，3秒任务需要不同帧数/策略。

八类输入是log-Mel时频图，训练与部署各步严格一致；五组activity是独立sigmoid、不归一。保留主导头时用独立dominance logits及mask，不用activity argmax替代。分类表不混用紧急演示的八类顺序。

训练/验证/测试按录音来源隔离，校准只用训练split。报告八类macro-F1/逐类recall、五组逐类/macro/micro-F1/PR-AUC及样本支持数，单列打击稀少类别、静音/未知/混音。建议INT8相对同结构float macro-F1损失≤2个百分点，改前端/模型相对可靠参考损失≤3个百分点；单类recall下降>5个百分点须解释并决策。阈值在验证集调，test不参与。基线没有可靠分数时先重测，不编造目标准确率。

## 6. 并行任务包与合入责任

实施必须并行，但本规划提交不启动子任务、训练或构建。推荐同一轮最多四个执行者，按可用名额调度；一名总负责人统一顶层和接口，不允许多人同时改同一生产文件。

| 工作包 | 独占范围 | 首批任务与交付 | 依赖 |
|---|---|---|---|
| A 音频/模型 | 新模型/实验/导出目录 | 复测原模型精度，48/24/16k对照；冻结输入契约和整数golden | 立即开始，不等B |
| B 数值定位/NPU存储 | NPU/注入快照子模块与独立仿真 | 旧feature板测路径、store打包/跨层共享、16/8lane对照 | 先锁定调试ABI；精度不变优化可立即做 |
| C CPU启动/总线 | instrec本地CPU封装/固件/host协议 | UART应用RAM启动、CRC/恢复，DDR桥/取指cache接口 | 与D先定MMIO，新增总线由负责人合入 |
| D 软件UI | UI子模块/资源生成/仿真 | 去并行ASCII复制，scene可写、双bank帧提交、仿真帧预览 | 可用模拟MMIO先行，不等CPU整机 |
| 集成负责人 | 顶层/约束/构建清单/地址图/STATUS | 评审契约、串行合入、全链仿真、唯一PDS/JTAG与证据 | 接收各包PASS提交后合入 |

只有四个名额时，总负责人兼C或D，其他三个包并行；不要为形式上的五路并发超额调度。任务输出用独立run label，标明文件归属与可合入commit；未冻结接口的分支不直接改主线顶层。GPU训练按显存独占/配额，避免互相OOM。

首次交接后执行顺序：

1. 读STATUS/本计划，核对git status与保护文件；校验基线hash和本机仿真工具实际可用性。旧文档“无Verilator”已过时，现有Windows实际RTL仿真记录可用。
2. 集成负责人输出DDR图/MMIO/场景/UART头的v0接口文档与最小测试；A同时准备输入/精度数据。
3. B建立已知feature→NPU的数值抓取与首次差异定位，D去UI表复制，C跑UART小APP收包/跳转/恢复仿真。
4. 每包先产出一个可测最小增量，再推进优化；不等待所有功能完成后一次性大合入。

| 里程碑 | 实际交付 | 退出门槛 |

| M1 软件闭环 | boot+UART小APP、软件UI描述符 | 实际RV仿真运行两个APP改变UI；断包/CRC错/坏入口不执行 |
| M2 存储与吞吐 | 缓存共享/打包、新资源审计、16/8lane测量 | 同模型逐层bit-exact；连续A/B、异常恢复PASS；选择lane有完整数据 |
| M3 模型双模式 | 前端选择/两模式镜像/CPU后处理 | float/INT8精度合格、契约/hash冻结，switch/epoch/快照仿真通过 |
| M4 全top仿真 | I2S→前端→DDR事务模型→NPU→CPU→UI | 各模式≥3个完整不同输入，静音/多活跃/无活跃、切换与错误注入PASS |
| M5 新源资源/时序 | 唯一compile/synth/map→受控PNR | 资源预算审核、完整十表PASS、约束/CDC边界明确，源hash未变 |

| M7 真实音乐/交付 | PCM1808多类别/混音双模式、UART更新UI/APP | 已标注样本可重复、有错误分析、至少1h耐久/恢复/切换无未解释死锁或丢窗 |

PDS前必须有对应源的仿真；FPGA容量/时序不许仅用孤立模块推断完整top。映射通过不等于时序通过，整板完成不等于精度通过。单个诊断不一定包含最终全部模块，但必须明确旁路范围。

## 8. 板上确定性I2S推理调试

必须按以下三层分别验收，板内模拟I2S不是在软件里直接塞feature冒充：

1. 已知feature写入DDR/专用入口→生产NPU→完整logits。若此层错，查权重/DDR/NPU/时序。
2. 已知PCM→生产前端→NPU。若1对2错，查音频预处理与帧布局。
3. 已知PCM经板内串行I2S发生器→生产I2S接收→前端→物理DDR→NPU→RV。若2对3错，查格式/符号/边沿/CDC。

若全链整数一致但真实音乐分类差，再查训练域、模型能力与实际输入增益，不能靠修改显示掩盖。

板内源从ROM短向量或UART装入DDR的真实录音读取；DDR播放器要有预取FIFO和underrun计数，按48k实时节奏输出Philips I2S。核定24有效位/32bit slot/64BCK立体声帧、LRCK后一bit延迟、采样沿和左右顺序。用L/R不同PRBS先查符号/位移；再脉冲、单/双频、静音、阶跃、已知音乐。覆盖断钟/半帧重启/LRCK卡死/恢复。

内部源mux不驱动外部PCM1808的BCK/LRCK输出线。片内测试只验证功能路径，电气/外部异步边沿需实际PCM1808或经审核跳线环回再验证。27MHz分数tick产生的48k若有抖动须单列，精确时钟方案先审PLL余量，不默认免费可用。

观测PCM、抽取PCM、关键FFT/Mel、量化feature、各层activation/GAP/logits、CPU结果、UI快照。CRC用于快速定位，失败后导出数组找首错。可多次确定性重放复用小debug缓存，禁止为了观测永久占满RAM。必须记录输入长度/幅值/采样率/source/model/contract/bit哈希、mode epoch/frame_id、reset、cycle与错误计数。

## 9. 构建/硬件纪律与风险回退

- 全机一次一个PDS流程，初始compile/synth/map30分钟、PNR120分钟上限，启动前写明预算，日志/CPU/RSS/阶段有进展监控；超时留hash与失败证据，不能无限等待。只能受控处理本轮PDS，不碰下载服务。
- 禁止终止/重启/新建cdt_js，不操作既有cdt_cfg；烧录复用可用服务，硬件在线先读查。下载器最后记录掉线，后续需恢复时只按实际缺失请求USB重插，不无故要求用户接线。
- 不并发使用COM口/JTAG，不在ADC连着时烧旧输出BCK/LRCK位流。新源必须新map，不能拿旧数据库冒充优化结果。
- 所有产物在instrec内独立归档，保护cpu/fpga/rv32_ddr3_ip_wrapper.sv和cpu/rtl/rv32_burst_ddr3.sv用户diff，以及PCB/obj_dir/未跟踪五组资产。不要git add整个目录。
- 每次完成更新STATUS→CHANGELOG→记忆→精确stage/commit；push依据当前用户授权，不把旧“已push”记录当本次自动授权。
- 保留冻结正式版与可用演示回退；生产数值/时序FAIL时不覆盖已验收基线。应用/模型/注入源类型在报告中显式标明，预设曲线绝不能计入准确率。

## 10. 排期与交付定义

新范围含CPU DDR执行与软件UI，按2–4周工程量级规划，而非旧1–2周估计；训练数据补充、硬件掉线或时序返工另加。按里程碑交付，不给“某天必须完成”替代DoD。M0/M1与音频实验可以并行，M2/M3按冻结子契约交错推进，M4→M5→M6验证顺序不倒置。

首批最小交付：旧模型固定feature板上数值报告；UART小APP启动与两种UI仿真帧；实际DRM节省和16/8lane数据表；48/24/16k精度对照。随后才冻结最终模型/并行度，完成双模式真实音乐验收。

Flash不是取消：排在UART启动、镜像格式和真实推理稳定之后，复用已冻结APP/模型格式实现上电自动加载，另作冷启动/CRC坏镜像/UART恢复验收。

最终必须有：可重建源码/APP/模型镜像与hash、统一数值契约、独立精度报告、完整top资源与十表时序、实际RV联合仿真、三层板上注入比对、真实音乐双模式/软件UI/UART更新/恢复/耐久报告。任何NOT_RUN单列，不能用文档定版表示功能已验证。
